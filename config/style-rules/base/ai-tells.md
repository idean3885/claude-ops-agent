# AI 티 분류 SSOT (base)

한국어 글(블로그·위키·이슈·PoC·데일리로그·동료리뷰 등 모든 문서)에서
AI 가 쓴 글의 흔적("AI 티")을 식별·차단·교정하기 위한 분류 체계.

> **출처**: AI 티 분류는 A~K 카테고리(심각도 S1/S2/S3)로 구성된다.
> 골격인 A~J 10대 카테고리는 [`epoko77-ai/im-not-ai`](https://github.com/epoko77-ai/im-not-ai) (MIT) 의 한국어 humanize 스킬에서 차용했고, K(감정체·의인화)는 본 SSOT 자체 확장이다.
> 본 SSOT 는 그 골격 위에 한국어 기술 블로그·사내 위키·PoC 문서 맥락의 처방·예시·forbidden-words hook 패턴 매핑을 자체 작성한 파생물이다.
> 번역투 계열 신규 분류의 학술·코퍼스 근거는 `../references/scholarship.md`, 정량 지표 정의는 `../metrics/metrics-spec.md` 를 참조한다.
> 라이선스: im-not-ai 의 MIT 조항을 준수하며, 본 SSOT 도 동일 MIT 로 배포된다.

## 적용 범위

이 SSOT 는 **모든 한국어 문서**에 적용되는 기초 룰이다.
문서 유형별 추가 규약은 `../extensions/{blog,wiki,poc,info,knowledge,issue,dailylog,peer-review,work-review}.md` 에서 base 를 import 한 뒤 얹는다.

소비자:
- `ops-agent/hooks/forbidden-words-{prompt,stop}.sh`: `forbidden-words.json` 의 S1 패턴을 사전 가이드로 주입하고 직전 응답 위반을 사후 통지 (출력 차단은 하지 않음)
- `ops-agent:write` / `ops-agent:lint` / `ops-agent:publish`: 작성·검증·발행 시 base + extension 로드
- 사내 어댑터의 `content-write` · `wiki-publish`: 위키 어댑터. `~/.claude/ops-agent/style-rules/` 미러 경로를 참조

`../metrics/` 와 `../references/` 는 상시 미러 대상이 아니다. 정밀 검증 시에만 참조한다.

## 4대 철칙

검증·윤문이 의미를 훼손하지 않도록 모든 처방에 우선한다.

1. **의미 불변**: 사실·주장·수치·고유명사·직접 인용은 100% 원문 보존
2. **근거 기반**: 탐지된 span 에만 수술적 수정. 탐지 없는 구간은 건드리지 않음
3. **장르 유지**: 칼럼을 문학으로, 리포트를 에세이로 옮기지 않음
4. **과윤문 금지**: 변경률 30% 초과 시 경고, 50% 초과 시 강제 중단. 변경률은 `../metrics/tells_count.py` 의 `change_rate` 로 실측한다

- 큰따옴표 내부 직접 인용
- 코드 블록(``` ``` ```), 인라인 코드(`` ` ``)

## 분류 체계 (A~K)

### A. 번역투 (영어 직역체)

가장 흔하고 결정적인 AI 티. 영어 원문 어순·관용 표현을 한국어로 직역한 결과.

| ID | 패턴 | 심각도 | 처방 | hook 매핑 |
|----|------|-------|------|----------|
| A-1 | `~을 통해`, `~를 통해` | S2 | `~로`, `~으로` (직접 수단). 문단 3회+ 반복만 교정 (비번역 한국어도 흔히 씀: `scholarship.md` 근거) | - (hook 미등록, ADR 0001) |
| A-2 | `~에 있어서`, `~에 있어` | **S1** | `~에서`, `~의 경우`, 또는 삭제 | - |
| A-3 | `~에 대해`, `~에 관해` | **S1** | 직접 목적격 (`~를`, `~에 관한`) | - |
| A-4 | 이중 피동 (`~되어지다`, `~지어지다`) | **S1** | 단순 피동 (`~되다`) 또는 능동. `만들어지다`·`이루어지다` 무주어 자동 피동도 능동(`합의했다`)으로 | - |
| A-5 | `~에 의해 ~된` | S2 | 능동 (`~가 ~한`) | - |
| A-6 | `그/그녀/그것/그들` 강박적 매핑 | **S1**(번역·요약·외부 AI 글 가공 맥락) / S2(자생 작성문) | 한국어는 주어 생략 가능. 반복 호명 제거. 단 자생 산문은 인간이 대명사를 더 씀 (`scholarship.md` caveat) | - |
| A-7 | Light verb 분리 구문 (`have/make/take/give + 명사`) → `~을 가지다`, `~을 만들다` | **S1** | 단일 동사 (`있다`, `만들다`, `결정하다`) | - |
| A-8 | 관계절 좌향 수식 (관형구 3중 중첩) | S2 | 문장 분할 또는 우향 수식 | - |
| A-9 | 이중 조사 (`~에서의`, `~에로의`, `~으로의`, `~에의`) | S2 | 단순 조사 (`~의`, `~에서`, `~로`). 단순 `~의` 는 제외 | - |
| A-10 | 사역·인지·발화 동사 분리 (`~하도록 하다`, `~게 하다`) / 무생물 주어 + 만능 동사 (`X가 Y를 보여준다/제공한다/가져온다`) | S2 | 직접 사역 (`~시키다`) 또는 능동. 무생물 주어는 행위자로 환원, 인지 동사는 `~에 따르면 ~이다` | - |
| A-11 | `활용하여`, `활용한`, `활용함으로써` | **S1** | `사용하여` | `활용하여·활용함으로써·활용한` |
| A-12 | `본 (문서·시스템·기능·보고서·작업)은` | **S1** | 주어 직접 명시 (`이 문서는`, `이 시스템은`) | `본 (문서·시스템·기능·보고서·작업)은` |
| A-13 | `~라는 점에서` 남발 | S2 | `~서`, `~라는 이유로`. 3회+ 만 | - |
| A-14 | `~와 관련하여`, `~와 관련된` | S2 | `~에`, `~의` | - |
| A-15 | `~에 기반하여`, `~을 바탕으로` 남발 | S2 | `~로`, `~을 보고` | - |
| A-16 | `~할 수 있다` 가능형 남발 | S2 | 근거가 확실한 문장만 그 근거를 들어 확정 서술로 바꾼다. 근거가 불확실한 문장은 그대로 둔다. 양태를 다양화해도 된다 (`~을 수도 있다`·`~을 가능성도 있다`) | - |
| A-17 | `~을 위해` 목적절 남발 | S2 | `~려고`, `~도록`, `~위한` | - |
| A-18 | 명사 나열 (조사 생략) | S2 | 조사 (`~의`, `~가`, `~를`) 복원 | - |

**Bad** (A-1, A-8):
```
AI 기술을 통해 효율을 높일 수 있는 다양한 기능을 제공하는 시스템에 대해 설명합니다.
```

**Good**:
```
이 시스템은 AI 로 효율을 높이는 기능을 제공합니다.
```

### B. 영어 인용·용어 과다

번역 가능한 영어를 한국어 옆에 병기하거나 영어 그대로 두는 패턴.

| ID | 패턴 | 심각도 | 처방 |
|----|------|-------|------|
| B-1 | 한국어 옆 영어 괄호 병기 남발 (`효율(efficiency)`, `사용자(user)`) | S2 | 첫 등장 1회만 병기. 이후 한국어만 |
| B-2 | 번역 가능한 영어 그대로 (`provide`, `deliver`, `implement`) | S2 | 한국어 동사 (`제공하다`, `구현하다`) |
| B-3 | 약어 풀이 없음 (`PR`, `CI/CD`, `WAS` 등) | S3 | 첫 등장 시 풀이. 단 업계 표준 약어는 예외 |
| B-4 | 과도한 영어 인용구 (원문 + 번역 병기 반복) | S2 | 한국어로 풀고 출처만 병기 |
| B-5 | `~라고 알려진`, `~로 일컬어지는` | S3 | 괄호 병기로 축약 (`범용 인공지능(AGI)`) |

`readability.md CJ3` (외래어 표기) 와 연계. 기술 용어 첫 등장 시 `한국어(English)` 형식.

### C. 구조적 AI 패턴

문장이 아니라 문서 구조에서 드러나는 AI 티.

| ID | 패턴 | 심각도 | 처방 |
|----|------|-------|------|
| C-1 | 기계적 `첫째/둘째/셋째` 병렬 | S2 | 문맥에 맞는 접속(`먼저`, `그다음`, `마지막으로`) 또는 목록 |

| C-7 | 문단 첫 문장 요약 공식 (topic sentence 강박) | S2 | 일부 문단은 사례·인용으로 시작 |
| C-8 | 헤딩 아래 한 줄 요약 박스 | S2 | 삭제, 본문 직진 |
| C-9 | `먼저·반면·결국` 3단 문두 공식 | S2 | 3개 중 2개 삭제 |
| C-10 | 대칭 대구 공식 (`A인가, B인가` / `A가 아니라 B`) **2회+** | **S1** | 한 번만 살리고 나머지는 비대칭 평서문·직접 단언. 전멸 금지. 실측 최강 신호 (AI 대비 9.2배: `scholarship.md`) |
| C-11 | 숫자 괄호 인덱싱 `1) 2) 3)` | S2 | 본문에 녹이거나 `우선~ / 다음으로~` |

**Bad** (C-4, C-2):
```
## ✅ 장점
- 🚀 빠른 속도
- ⚡ 낮은 메모리
- 🎯 명확한 API
```

**Good**:
```
## 장점

속도가 빠르고 메모리 사용량이 적으며 API 가 명확합니다.
```

**Bad** (C-10 대칭 대구):
```
이것은 선택의 문제가 아니라 생존의 문제다. 우리가 기술을 지배하는가, 기술이 우리를 지배하는가.
```

**Good**:
```
이것은 생존이 걸린 문제다. 기술을 어떻게 다룰지가 결과를 가른다.
```

### D. AI 특유 관용구

| ID | 패턴 | 심각도 | 처방 |

| D-1 | `결론적으로`, `요컨대`, `종합하자면` | **S1** | 결론은 직접 진술. 도입어 삭제 |
| D-2 | `시사하는 바가 크다`, `의미가 깊다` | **S1** | 무엇을 시사하는지 직접 기술 |

| D-9 | `심층(적·적인·있는)`, `심도(있는·깊은)` | **S1** | 범위 구체 명시 | `심층(적·적인·있는)·심도(있는·깊은)` |

| D-13 | 추상 개념 의인화 (`충돌이 질문을 던진다`) | S2 | 실제 행위자로 교체, 의인화 동사 약화. 시스템 의인화는 K 카테고리 참조 |
| D-14 | 완결 공식형 결말 (`~할 때입니다`, `~시점입니다`) | S2 | 구체 동사 단언. 문서당 1회 |
| D-15 | 변환 공식 (`X에서 Y로`, `X을 넘어 Y로`) | S2 | 직접 단언. 문서당 1회 |
| D-16 | 추상 차원 명사 `축` (`크기 축`, `세 축`, `측정 축`) | **S1** | 가리키는 실물로 교체 (`조건`, `구성`, `지표`, `측정 대상`, `구간`) |

D-6~D-11 과 D-16 은 `forbidden-words.json` 에 hook 패턴으로 등록되어 사전 가이드로 주입되고 위반 시 사후 통지된다.

D-17 은 G 계열의 반대 방향이다. 근거가 불확실한데 단언하면 과장이다. 확실한데 완곡하면 회피다. 둘을 함께 두지 않으면 한쪽 처방이 다른 쪽 위반을 만든다. 절대 양화가 늘 위반인 것은 아니다. 전수를 확인했으면 `모든` 이 정확하다. 판정은 그 범위를 실제로 확인했는지다.

D-16 은 좌표 은유가 실물 명사 자리를 차지하는 패턴이다. 한 문서에서 `축` 이 조건·구성·측정 대상·지표를 번갈아 가리키면 독자가 매번 문맥에서 역산해야 한다. **단독 단어로 쓰인 경우만 대상이다.** `압축`·`구축`·`축소`·`축적` 처럼 다른 음절이 앞에 붙은 것은 `축` 이라는 단어가 아니므로 제외한다. 그래프 좌표축(`x축`, `Y축`)은 붙여 쓰므로 패턴에 걸리지 않고 예외로 둔다.

### E. 리듬 균일성

문장 호흡이 평탄해서 사람이 쓴 글의 자연스러운 변주가 사라진 상태.

| ID | 패턴 | 심각도 | 처방 |
|----|------|-------|------|
| E-1 | 문장 길이 표준편차 < 5 **어절** (전체 문장이 비슷한 길이) | S2 | 짧은 문장·긴 문장 의도적 혼용. 목적이 산문 리듬 적용 대상일 때만 (`../extensions/profiles.md` 목적별 적용) |
| E-2 | 동일 종결어미 5문장 연속 (`~합니다.` x 5+) | S2 | 종결어미 변주 (서술 / 의문 / 명령): 단 합쇼체 유지 |
| E-3 | 진행형 `~하고 있다` 자동 매핑 | S3 | 현재형 (`~하다`) 단순화. 진행 의미가 중요할 때만 유지 |
| E-4 | 청자 경어법 손실 (반말↔합쇼체 혼용) | S2 | `readability.md CJ2` (합쇼체 통일) 적용 |
| E-5 | 모든 문단 3~4문장 공식 | S2 | 1문장·6문장 문단 의도적 혼용 |
| E-6 | 단문 일변도 (복문·중문 부재) | S2 | 인접 단문을 연결어미·관형절로 복문화 |
| E-7 | 쉼표 분절 평균 길이 과다 (긴 절) | S2 | 8어절+ 절은 마침표로 분할. estimated 지표 (`scholarship.md` caveat) |

`E-1`·`E-2`·`E-5`·`E-6` 은 산문 리듬 규칙이고 문서 목적에 종속된다. `E-3`·`E-4`·`E-7` 은 언어 규칙이라 목적과 무관하게 적용한다. 목적별 적용은 `../extensions/profiles.md` 가 갖는다.

측정 단위를 규칙에 적는 이유는 재현이다. `E-1` 을 어절로 재면 개조식 문서가 전부 위반이고 글자로 재면 전부 통과한다. 단위 없는 역치는 측정하는 사람마다 다른 값을 낸다.

`E-2`·`E-5`·`E-6` 은 표본 아홉 편에서 위반 0건이었다. 게이트를 걸지 않은 이유가 그것이다. 위반이 나오면 그때 목적별로 켠다.

**관찰 전용 지표 (서브패턴 번호 미부여)**: 쉼표 전후 POS 다양성, 무정물·추상명사 `-들` 복수 표지는 `../metrics/metrics-spec.md` 의 관찰 지표로만 추적한다. 코퍼스 검증 전까지 교정 규칙으로 승격하지 않는다.

### F. 수식·중복

형용사·부사·접미사를 반복적으로 덧붙이는 패턴.

| ID | 패턴 | 심각도 | 처방 |
|----|------|-------|------|
| F-1 | `매우`, `정말`, `상당히`, `굉장히` 빈출 | S2 | 정량 (`3배`, `0.5초`) 또는 삭제 |
| F-2 | 동의어 이중 수식 (`빠르고 신속한`, `중요하고 핵심적인`) | S2 | 둘 중 하나만 |
| F-3 | 한자어 명사화 접미사 `~적`, `~성`, `~화` 남발 | S2 | 구체 동사·명사. `~적 N` 구체명사 앞 체인 3회+ 는 `~로서의 N`·동사구로 해체 |
| F-4 | 명사화 접미사 누적. 영어 `-tion`·`-ment`·`-ness`·`-ity` 직역 + 한자어 `-성`·`-적`·`-화` | S2 | 동사·형용사 어근으로 환원. 통합 12회 초과 시 강화 |
| F-5 | 기능+역할 복합구 (`~의 역할과 기능`) | S2 | 하나만 |

F-4 의 한자어 접미사 3종(`-성`·`-적`·`-화`)은 영어 접미사 4종과 합산한다. 처방은 같다. 명사를 동사·형용사 어근으로 되돌린다. `F-5`(`~적 N` 복합 추상어 체인)는 `-적` 의 특수 사례이므로 분리해 둔다.

| F-6 | 한 문장 안에서 같은 명사 반복 (`값이 무엇의 값인지`) | S2 | 아래 판정으로 지우거나 묶는다 |
| F-7 | 비유로 만든 계수 명사 (`4겹`, `방어 세 겹`) | S2 | 통용 단위 (`건`·`개`·`줄`·`곳`·`단`) |
| F-8 | 한자 접두 조어. `未`·`非`·`無`·`不` 를 명사에 붙여 만든 사전 밖 낱말 (`미인지`, `미보관`, `비기재`) | S2 | 사전에 있는 말로 풀어 쓴다 (`알 수 없음`, `보관하지 않는다`, `적지 않는다`) |

#### F-6 판정

두 번째 등장이 가리키는 대상이 첫 번째와 같은지로 나뉜다.

| 두 번째 등장 | 처리 | 근거 |
|-------------|------|------|
| 같은 대상 | 지운다 | 새 정보가 없다. 지시어·접속어·생략이 자리를 대신한다 |
| 다른 대상이고 나란히 놓임 | 가운뎃점으로 묶는다 | 반복은 묶지 않은 결과다 |
| 다른 대상이고 대조가 목적 | 남긴다 | 그 단어가 대조하는 말이라 바꾸면 비교가 깨진다 |

같은 대상일 때 무엇으로 바꾸는지는 자리가 정한다.

| 자리 | 대체 | 예 |
|------|------|-----|
| 주어·목적어 | 지시어 또는 생략 | `파드 하나에` → `하나에` |
| 서술어 | 접속어 | `종료해야` → `그래야` |
| 앞에서 이미 한정 | 뒤를 벗긴다 | `차수별 … 차수 로그` → `차수별 … 로그` |

대조가 목적이어도 뒤쪽만 남기고 앞쪽을 줄일 수 있는지 함께 본다.

`계정 수를 … 같은 계정이` 에서 뒤는 대체어가 없지만 앞은 `계정을` 로 줄어든다.

고유명사와 식별자는 세지 않는다. 링크 제목·코드스팬·제품명은 4대 철칙의 의미 불변에 따라 보존하므로, 반복이 걸리면 그쪽이 아니라 산문 쪽을 줄인다.

`요약 원천은 [주간 요약](...) 이다` 에서 뒤의 「요약」은 페이지 이름이라 손댈 수 없다. 앞을 `원천은` 으로 줄인다.

대상 동일성 판정이라 `forbidden-words.json` 정규식으로 가지 않는다. 검증 단계에서 문맥으로 판독한다.

#### F-7 판정

세는 대상이 실제로 층이나 겹으로 쌓여 있지 않은데 그 단위를 붙이면 대상이 흐려진다. 원인이 4개면 `4건` 이고, 추상화가 2단이면 `2단` 이다. 물리적으로 겹쳐 있을 때만 그 단위를 사용한다.

| Bad | Good | 근거 |
|-----|------|------|
| `원인 4겹` | `원인 4건` | 원인은 쌓이지 않는다 |
| `추상화가 두 겹` | `추상화가 2단` | 계층은 단으로 센다 |
| `방어가 세 겹` | `방어 3단` | 같음 |

동사형은 대상이 아니다. `겹치다`·`겹쳐`·`겹침` 은 대상이 실제로 포개진 상태를 말하므로 그대로 사용한다.

비유 계수는 만들어 사용하는 말이라 목록으로 닫히지 않는다. `forbidden-words.json` 정규식으로 가지 않고 검증 단계에서 단위가 대상에 맞는지 판독한다.

세는 자리의 표기는 [tone.md T19](tone.md#t19-수량과-순서는-숫자로-적는다) 를 따른다.

#### F-8 판정

접두가 붙은 낱말이 사전이나 독자 코퍼스에 있는지로 나뉜다. `미결`·`미정`·`비활성`·`무중단`·`불가` 는 통용되는 낱말이라 대상이 아니다. `미인지`·`미보관`·`비기재` 는 서술을 압축하려고 그 자리에서 만든 말이라 독자가 원문을 복원하지 못한다.

| Bad | Good | 근거 |
|-----|------|------|
| `백엔드 상태 미인지` | `백엔드 상태를 알 수 없음` | 未認知 는 사전에 없다 |
| `식별자 미보관` | `식별자를 보관하지 않는다` | 같음 |
| `사유 비기재` | `사유를 적지 않는다` | 非記載 는 행정 문서 어법이다 |

유발 조건은 개조식 변환이다. 서술문을 항목으로 압축할 때 부정문이 접두 조어로 바뀐다. 개조식에서도 부정은 `없음`·`~하지 않는다` 로 적는다.

판정 기준이 사전 등재 여부라 정규식으로 가지 않는다. `forbidden-words.json` 에 등록하지 않고 검증 단계에서 낱말 단위로 판독한다. 접미 조어(`~적`·`~성`·`~화`)는 F-3·F-4 가, 약어와 구어 동사의 합성은 `tone.md` T9 가 맡는다.

### G. 근거를 대지 못하는 완곡

**완곡 자체는 대상이 아니다.** 근거가 불확실할 때 완곡은 그 불확실성을 정확히 표시하는 장치다. 표본이 제한적이고 조건이 특정적인데 단언하면 신뢰를 잃는다.

대상은 **근거를 대지 못하면서 사실처럼 보이는 완곡**이다. 판정 기준은 표현의 양이 아니라 근거와의 관계다.

| 완곡한 상황 | 판정 |
|-------------|------|
| 근거가 확실한데 완곡했다 | 회피. G-1·G-3 |
| 근거가 불확실해서 완곡했다 | 정당. 대상이 아니다 |
| 뒤에서 근거를 대는 도입부·주제문의 완곡 | 정당. 대상이 아니다 |
| 근거가 불확실한데 단언했다 | 과장. D-17 |

| ID | 패턴 | 심각도 | 처방 |
|----|------|-------|------|
| G-1 | 근거 없이 겹친 완곡 (`~할 수 있을 것으로 보인다`, `~할 가능성이 있다고 판단된다`) | S2 | 근거를 함께 적는다. 근거가 없으면 주장의 범위를 좁힌다. **단언으로 바꾸지 않는다**. 근거가 없는 문장을 단언으로 만들면 회피가 과장으로 바뀐다 |
| G-2 | 안전 균형 lexicon (`물론`, `그러나`, `하지만`, `다만`, `한편` 빈출) | S2 | 회수 조절 |
| G-3 | 추측·관측형 종결 **분포** 편중 (`~로 보인다`, `~로 판단된다`, `~인 듯하다` 가 문장 대부분) | S2 | 근거가 있는 문장만 그 근거를 들어 단언한다. 근거가 없는 문장은 그대로 둔다. G-1(문장 내 밀도)과 달리 문서 전체 분포 문제 |

지시·절차 문서는 예외다. 수행할 동작에 완곡이 들어갈 이유가 없다. 이 예외를 문서 목적별로 어디에 거는지는 `../extensions/profiles.md` 가 갖는다.

처방이 서법을 바꾸지 않는 이유는 `base/purpose.md` 의 보존 원칙과 같다. 필자가 유보한 것을 확정으로 만드는 것은 교정이 아니다. 의미를 바꾸는 것이다.

### I. 형식명사 과다

문장 끝에 의미가 가벼운 형식명사를 덧붙여 문장이 부풀게 만드는 패턴.

| ID | 패턴 | 심각도 | 처방 |
|----|------|-------|------|
| I-1 | `~것이다`, `~한 것이다` | S2 | 동사 단언 (`~이다`, `~다`). 3회+ 반복만 교정 (실측상 인간이 더 씀: `scholarship.md`) |
| I-2 | `~한 점`, `~한 수`, `~한 바` | S2 | 구체 명사 또는 동사 |
| I-3 | 당위 결말. `~할 필요가 있다`·`~해야 한다`·`요구된다` 로 끝나는 문단이 **2개+** | **S1** | 첫 번째를 제외한 나머지에서 **당위 문장을 문단 끝에서 앞·중간으로 옮겨 결말 자리를 비운다. 이동만 허용한다.** 옮길 비당위 문장이 없으면 원문을 그대로 둔다 |
| I-4 | `~다는 것`, `~라는 것` | S2 | 명사절 단순화 |

| I-7 | 지시 대상 없는 평가 명사로 문장을 닫는다 (`~지점입니다`·`~값입니다`·`~자리입니다`·`~범위입니다`) | **S1** (되받기가 성립할 때) | 명사를 지우고 앞 문장에 붙이거나, 그 명사가 무엇의 것인지 서술한다 |

### I-3 의 금지 처방 (서법 보존)

당위 결말을 고칠 때 아래 다섯 가지를 하지 않는다. 전부 필자가 요구한 것을 이미 일어난 일이나 다른 것으로 바꾼다.

| 금지 | 왜 |
|------|-----|
| 병합 (`A해야 한다. B해야 한다` → `A하고 B해야 한다`) | 표지만 줄고 결말은 그대로다 |
| 당위 표지 삭제 (`~해야 한다` → `~한다`) | 요구가 사실 서술로 바뀐다 |
| 다른 서법으로 치환 (단정·조건·추측) | 필자가 요구한 것을 이미 일어난 일로 만든다 |
| 명사화 (`~하는 것이 과제다`) | 주체와 의무가 사라진다 |
| 종속절로 옮기기 | 표지가 사라지고 주장이 배경으로 밀린다 |

**처리 전후로 의무 표지 총수가 같아야 한다.** 줄었으면 되돌린다. 법조문과 직접 인용 안의 당위는 대상이 아니다.

이 조항은 `G` 계열의 완곡 처방과 같은 뿌리다. 필자가 표시한 서법은 교정이 바꾸지 않는다.


### I-7 의 판정 (되받기와 규정의 구분)

앞 문장이 이미 말한 것을 뒤 문장이 명사로 되받기만 하면 그 명사에는 지시 대상이 없다. 반대로 그 명사가 서술 대상을 새로 규정하면 정상이다.

| 문장 | 판정 | 이유 |
|------|------|------|
| 매번 최신본을 선별해 조인하는 구조였습니다 | 정상 | 어떤 구조인지 문장이 서술한다 |
| 그 측정이 판단의 출발점이었습니다 | 정상 | 시간 관계를 새로 규정한다 |
| 평문 대조에서 필드 질의로 바뀐 지점입니다 | 어색 | 앞 문장이 이미 「필드로 조회하게 했다」를 말했다 |
| 전환한 것이 이 건의 값입니다 | 어색 | 무엇의 값인지 문장이 말하지 않는다 |

판정은 하나다. **그 명사를 지우고 문장을 앞 문장에 붙였을 때 잃는 정보가 없으면 되받기다.**

정규식으로 잡히지 않는다. 같은 명사가 규정하는 자리에도 쓰이므로 어휘 목록으로는 정상 문장까지 걸린다. hook 에 등록하지 않고 `lint` 의 원칙 판독 목록에 둔다.

F-6(한 문장 안 같은 명사 반복)과 인접하지만 다르다. F-6 은 반복을 보고 이 항목은 지시 대상 부재를 본다. 위 예시의 「값」은 문서에 한 번만 나온다.

### K. 감정체·의인화 표현

사람 상태 형용사로 시스템을 묘사하거나 시스템에 생명·감정을 부여하는 패턴. 기술 문서 톤을 흐리고 도메인 용어 일관성을 깨뜨린다.

| ID | 패턴 | 심각도 | 처방 | hook 매핑 |
|----|------|-------|------|----------|
| K-1 | `멀쩡(한·하다·히·함)` (사람 상태 형용사로 시스템·서비스 묘사) | **S1** | 도메인 동사 (`중단되지 않는다`, `유지된다`, `동작한다`) | `멀쩡(한·하다·히·함)` |
| K-2 | 시스템·프로세스·서비스 의인화 동사 (`죽다`, `살아남다`, `뻗다`, `쓰러지다`) | S2 | 도메인 동사 (`다운된다`, `동작 중이다`, `정지한다`). TCP `연결이 끊기다` 같은 IT 표준 한국어는 예외 | - |
| K-3 | 구어 감정체 (`박살`, `쌩쌩`, `먹통` 등: 시스템 묘사 맥락) | S2 | 도메인 동사 | - |
| K-4 | 추상 대상에 붙는 물리 조작 동사 (`쪼개다`, `빼다`, `내리다`, `때려박다` 등: 도구·로직·규칙 대상) | S2 | 추상 중립 동사 (`분할한다`, `제외한다`, `낮춘다`, `삽입한다`). 판정 기준은 `tone.md` T8 | `쪼개(다·서·고·는·면·진)`, `때려박`, `쑤셔넣` |

K 는 **시스템·서비스** 의인화(IT 도메인)를 다룬다. **추상 개념** 의인화(산문 수사, `충돌이 질문을 던진다`)는 D-13 이 다룬다. 경계가 다르므로 상호 참조한다.

K-4 는 `tone.md` T8(구어체·감정체 동사 금지) 물리 조작 계열의 AI 티 관점 대응이다. **어조가 튀지 않는 물리 동사**(`잇다`·`붙이다`·`가르다`·`벗기다`·`뽑다`·`빠지다`·`넘기다`·`덮다`·`가리키다`)도 같은 대상이다. 어조로 걸리지 않아 눈에 남지 않으므로 `metrics/tells_count.py` 의 `physical_verb_count` 로 밀도를 본다.  등록 패턴은 오탐이 낮은 것만 hook 에 올리고, 목록에 없는 동사는 T8 의 판정 기준 세 조건(추상 대상 · 물리 조작 어근 · 어휘 쌍 파괴)으로 판단한다.

**Bad** (K-1, K-2):
```
컨트롤 플레인이 죽어도 사용자 파드는 멀쩡합니다.
```

**Good**:
```
컨트롤 플레인이 다운되어도 사용자 파드는 중단되지 않습니다.
```

**도메인 용어 일관성**: 본문에서 `무중단` / `중단` 같은 어휘 쌍을 일관되게 사용한다. `끊김`·`멀쩡`·`죽음`을 섞으면 어휘 쌍 정합이 깨져 톤이 흐려진다.

### 용례 근거를 들 때

「이 말을 사용해도 되는가」를 판정할 때, 근거 코퍼스는 **판정할 자리와 같아야** 한다.

| 코퍼스 | 그 근거가 성립하는 자리 |
|--------|---------------------|
| UI 문자열·메뉴 라벨·버튼 이름·기능 이름 | 기능 이름 자리 |
| 기술 문서 산문 | 산문 서술 자리 |
| 리뷰 있는 번역 문서 | 번역 자리. 원문 한국어 근거를 대신하지 못한다 |

자리가 다른 코퍼스에서 검출 건수를 집계해 「표준이다」로 결론하지 않는다. 자리를 맞춘 코퍼스에서 0건이면 0건이다.

**번역 코퍼스 단독으로 어휘를 정하지 않는다.** 영어 원문의 낱말을 옮긴 자리가 한자어 쪽 빈도를 부풀린다. 원문 한국어 코퍼스에서 같은 방향이 나오는 것만 규칙으로 등재한다.

이 구분은 T22 와 AR1 의 근거 문단이 「이름 자리」와 「산문 자리」를 나눈 것과 같은 기준이다. 그쪽은 결론에 적용했고 이 항목은 근거를 모으는 단계에 적용한다.

## 검증 절차 (요약)

상세는 `ops-agent:lint` SKILL.md 와 `readability.md` 의 체크리스트 표를 참조한다. base 단계에서는 다음 순서를 따른다.

1. **카테고리 매칭**: 본문에서 A~K 패턴 탐지 (span 단위)
2. **심각도 분류**: 탐지된 span 을 S1/S2/S3 로 분류
3. **카운트 집계**: S1 건수, S2 빈도. 정밀 검증 시 `tells_count.py` 로 객관 수치 확보
4. **품질 등급 판정**: A/B/C/D
5. **수술적 윤문**: 탐지된 span 만 처방대로 교정 (`change_rate` 로 변경률 모니터링)

## 확장 (extensions/) 가이드

extension 은 base 를 대체하지 않고 **추가**만 한다.

익스텐션 파일에는 그 유형의 고유 규칙과 `필수 구조` 만 사용한다. 적용 대상·base 대비 적용 강도·합격선은 [`extensions/profiles.md`](../extensions/profiles.md) 의 행으로 넣는다. 유형이 늘 때 파일이 아니라 행이 하나 늘게 하기 위해서다.
