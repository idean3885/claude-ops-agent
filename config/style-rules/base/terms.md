# 표준 용어

대화와 문서에서 한 개념을 한 말로 부르기 위한 목록이다. 용어 교정(전역 지침 「용어 교정」)으로 바로잡은 말이 세션 마무리 때 여기 올라온다. 이 목록이 원천이다. 같은 말이 로컬 메모리 · 프로젝트 문서에 따로 있으면 여기로 옮긴다.

## 등재 조건

- 항목마다 문장 시험(tone T5)의 글 예문과 말 예문을 하나씩 둔다. 제목의 표준 용어가 두 예문에 모두 들어간다.
- 말 예문이 필수인 이유: 글로 이해한 것을 남에게 설명할 때 사람은 말로 한다. 말로 해서 어색한 용어는 전달하는 자리에서 다른 말로 바뀌고, 다시 섞인다.
- 말로 했을 때 어색하면 등재하지 않고 다른 말을 고른다.
- 공개할 수 없는 사내 용어는 올리지 않는다.
- 형식 검사: `python3 scripts/terms.py check`. 등재 절차는 `skills/learn` 「용어 교정 등재」

### 해상도 1초
- 섞어 쓴 말: 같은 초(1초 안의 두 변경을 구분하지 못하는 성질을 가리킬 때)

- 글: 「mtime 의 해상도가 1초라, 1초 안의 두 번째 쓰기는 변경으로 감지되지 않는다.」

## 익힌 항목」 절로 옮기고 `- 익힘: YYYY-MM-DD` 를 붙인다. 지우지 않고 보관하며 세션 시작 때 주입하지 않는다. 다시 헷갈리면 「## 항목」으로 되돌린다. 되돌릴 때 `익힘` 줄을 지우고 `등재` 를 되돌린 날로 바꿔 집계를 새로 시작한다. 그러지 않으면 되돌린 원인이 된 교정이 오답으로 남아 다시는 제거 후보가 되지 못한다. 되돌아오는 과정도 학습이다.
- 제거 후보는 정답률 100% 이고 등재 다음 날부터 서로 다른 세션 3개 이상에서 다룬 항목이다. 정답률은 그 항목을 다룬 세션(용어가 모두 나왔거나 그 항목으로 교정받은 세션) 중 교정받지 않은 비율이다. 한 세션의 교정은 여러 번이어도 하나다.
- 쌍 항목은 두 용어가 모두 나온 세션만 사용으로 집계한다. 한쪽이 일반어면 한쪽만 집계할 때 정답률이 부풀려진다.
- 항목 수에는 상한을 두지 않는다. 세션 시작 때 주입하는 것은 항목당 한 줄(표준 용어 · 섞어 쓴 말)의 인덱스이고, 구분 · 예문은 교정할 때 원천에서 읽는다. 비용과 효과는 항목마다 생기므로 개수가 아니라 항목별 정답률로 판정한다.
- 집계: `python3 scripts/terms.py stats`. 「## 항목」 절만 집계한다. 옮기는 것은 사람 확인 뒤에 한다.

## 항목 형식

```markdown
### 표준 용어 (둘로 나눈 개념이면 「A · B」)
- 섞어 쓴 말: 사용자가 섞어 쓴 말과 그때 가리킨 개념
- 구분: 각 용어가 무엇을 가리키는지 한두 문장
- 글: 「문서에 쓰는 문장」
- 말: 「입으로 설명하는 문장」
- 등재: YYYY-MM-DD
- 익힘: YYYY-MM-DD (「## 익힌 항목」으로 옮길 때만)
```

### envelope

- 글: 「오류 응답도 같은 envelope 의 error 필드에 담는다.」

### 도메인 · 애그리거트 루트
- 섞어 쓴 말: 도메인(컨트롤러 URL 의 `resource-quotas` 를 가리킬 때) · 애그리거트 · 루트
- 구분: 도메인은 업무 영역 전체이고 모듈 하나에 대응한다. 애그리거트는 한 트랜잭션에서 함께 바뀌는 묶음이고, 애그리거트 루트는 그 묶음에 들어가는 유일한 입구 엔티티다. REST URL 의 컬렉션 리소스는 보통 애그리거트 루트에 대응하고, 그 아래 하위 경로는 루트를 좁히는 범위다.
- 글: 「상품 활성화 도메인에서 리소스 쿼터는 애그리거트 루트이고, `resource-quotas` 경로가 이 루트에 대응한다.」
- 말: 「상품 활성화가 도메인이고, URL 의 resource-quotas 는 그 안의 애그리거트 루트예요.」

### 플러시 · 커밋
- 섞어 쓴 말: 「커밋하고 플러시」(순서를 바꿔 부름)
- 구분: 플러시는 JPA 영속성 컨텍스트에 쌓인 변경을 SQL 로 DB 에 보내는 것이고, 커밋은 트랜잭션을 확정하는 것으로 DB 트랜잭션 커밋과 같다. 트랜잭션이 끝날 때 플러시가 먼저, 커밋이 뒤다. DB 의 유니크 방어는 플러시 여부와 무관하게 일어나고, 플러시가 정하는 것은 위반이 어느 시점에 드러나느냐다.
- 글: 「트랜잭션이 끝날 때 플러시가 INSERT 를 먼저 보내고, 커밋이 그 결과를 확정한다.」
- 말: 「끝날 때 플러시로 쿼리를 먼저 보내고, 그다음에 커밋해요.」
- 등재: 2026-10-21

### 포트 계약 · HTTP 상태
- 섞어 쓴 말: 「포트 계약에서 409 를 주기로 약속했다」

- 글: 「포트 계약은 중복 예외를 약속하고, 409 같은 HTTP 상태는 웹 경계가 그 예외에 매핑한다.」
- 말: 「포트 계약은 예외까지만 약속해요. HTTP 상태 409 는 웹 쪽에서 정해요.」

### expand-contract
- 섞어 쓴 말: 확장 · 수축(번역)
- 구분: 스키마를 바꿀 때 새 구조를 먼저 더하고(expand) 애플리케이션이 옮겨 간 뒤 옛 구조를 지우는(contract) 패턴이다. Martin Fowler 는 Parallel Change 로 정리했다. 번역하지 않고 글로는 expand-contract, 말로는 「익스팬드 컨트랙트」라고 한다.
- 글: 「컬럼 변경은 expand-contract 로 나누고, expand 단계에서는 옛 컬럼을 지우지 않는다.」

### Authorization: Bearer
- 섞어 쓴 말: 어센티케이션 베어러 · 어소라이제이션 베어러(헤더 이름을 말로 바꿔 부를 때)
- 구분: HTTP Authorization 헤더에 「Bearer <토큰>」 형식으로 토큰을 싣는 방식이다(RFC 6750). 하는 일이 인증이라 Authentication 헤더로 잘못 부르기 쉽지만 그런 헤더는 없다. Basic 인증도 같은 헤더에 Basic 스킴으로 싣는다.
- 글: 「외부 연동은 Authorization: Bearer 대신 Basic 인증으로 받는다.」
- 말: 「Authorization: Bearer 로 보내면 인증 필터가 먼저 막아요.」
- 등재: 2026-11-10

### 인증 없는 접근
- 섞어 쓴 말: 무인증(억지 한글화. 인증을 거치지 않고 자원에 닿는 요청이나 그런 경로를 가리킬 때)
- 구분: 요청이 인증(authentication)을 거치지 않고 자원에 닿는 것이다. 부사로는 「인증 없이」라고 한다. 「인증되지 않은 접근」도 같은 뜻이지만 제목에 넣기엔 길다. 비인가 접근은 권한(authorization) 문제라 다른 개념이고, 비인증은 제품 인증(certification)으로도 읽혀 쓰지 않는다.
- 글: 「모니터링 호스트에 인증 없는 접근이 가능해 Ingress 앞단에서 로그인을 확인하게 했다.」
- 말: 「그 주소 인증 없이 들어가져요. 인증 없는 접근이라 앞단에서 막아야 해요.」

### RACI
- 섞어 쓴 말: RaCI(표기 흔들림) · 알파벳 하나씩 읽기
- 구분: 일마다 역할을 넷으로 나누는 책임 배정표다. R 은 실행(Responsible), A 는 최종 책임(Accountable, 한 명), C 는 사전 협의(Consulted), I 는 결과 통보(Informed)다. 글로는 RACI, 말로는 한 단어로 「레이시」라고 읽는다.
- 글: 「에이전트 역할은 RACI 로 나누고, A 는 언제나 사람 한 명이다.」
- 말: 「에이전트 역할은 RACI, 레이시로 나눴고 최종 책임은 항상 제가 져요.」
