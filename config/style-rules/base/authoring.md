# 에이전트가 읽는 문서

> **적용 범위**: 사람이 아니라 에이전트가 소비하는 문서. `SKILL.md`, `CLAUDE.md`·`AGENTS.md`, 단계 가이드, provider 정의, 포인터로 도달하는 참조 문서.
> **다른 base 파일과의 관계**: `readability`·`tone`·`punctuation`·`ai-tells` 는 사람이 읽는 한국어 산문을 다룬다. 이 파일은 읽는 쪽이 모델일 때 달라지는 것만 다룬다. 겹치는 항목은 없다.
> **출처**: 골격은 [`mattpocock/skills`](https://github.com/mattpocock/skills) 의 `writing-for-agents` (MIT, Copyright (c) 2026 Matt Pocock) 를 차용했다. 한국어·이 레포 맥락의 판정과 예시는 자체 작성.

문서가 노리는 것은 같은 결과물이 아니라 **같은 절차**다. 매번 같은 문장이 나오게 만드는 게 아니라, 매번 같은 순서로 같은 것을 확인하게 만든다.

## AU1. 컨텍스트 포인터

**컨텍스트 포인터**는 컨텍스트에 상주하면서 밖에 있는 자료를 가리키고, 언제 그 자료에 도달할지를 함께 담은 참조다. 스킬의 `description` 이 그렇고, `CLAUDE.md` 에서 문서를 가리키는 한 줄이 그렇다.

도달 여부를 정하는 것은 가리키는 **대상**이 아니라 포인터의 **문구**다. 꼭 읽혀야 하는 자료가 안 읽힌다면 자료를 본문으로 옮기기 전에 문구부터 고친다.

포인터는 두 가지를 한다. 무엇에 관한 자료인지 말하고, 어떤 갈래에서 도달해야 하는지 열거한다. 상주 비용을 매 턴 내므로 본문보다 더 깎는다.

| 트리거 요건 | 처방 |
|------|------|
| 첫 단어 | 도달 판정이 걸리는 말을 앞에 둔다 |
| 갈래당 하나 | 같은 갈래를 다른 말로 두 번 사용하지 않는다. 실제로 다른 갈래만 남긴다 |
| 중복 제거 | 본문이 이미 말하는 정체는 포인터에서 뺀다 |

Bad:
```
description: 문서를 검증합니다. 검증, verify, 확인, 체크, 점검, 검사, 리뷰가 필요할 때 사용합니다.
```

Good:
```
description: 마크다운 콘텐츠 검증. 품질 3요소 + 가독성·톤·구두점·AI 티 체크리스트. 트리거 "검증", "가독성 검사", "AI 티 검사", "윤문".
```

## AU2. 두 가지 부하

문서와 포인터를 늘릴 때 둘 중 하나를 사용한다.

| 부하 | 무엇에 쌓이는가 | 성격 |
|------|-----------------|------|
| 컨텍스트 부하 | 모델의 컨텍스트 창 | 상주 자료가 발화 여부와 무관하게 매 턴 토큰과 주의를 쓴다 |
| 인지 부하 | 사람 | 어떤 문서가 있고 언제 꺼내는지를 사람이 색인으로 들고 있어야 한다 |

인지 부하는 없애야 할 비용이 아니다. 사람이 판단하는 자리의 값이다. 사람 판단이 필요한 곳에는 사용하고, 필요 없는 곳에서는 걷는다.

포인터 뒤로 밀어 둔 자료는 포인터 한 줄 값만 내고 컨텍스트 부하를 피한다. 포인터조차 없는 자료는 전부 인지 부하로 간다.

## AU3. 정보 계층

문서는 **단계**(에이전트가 순서대로 하는 것)와 **참조**(필요할 때 들춰 보는 정의·규칙)로 이뤄지고, 둘은 한 문서에 섞여도 된다. 정할 것은 각 조각이 계층 어디에 앉는가다.

| 계층 | 자리 | 언제 |
|------|------|------|
| 1 | 파일 안 단계 | 무엇을 어떤 순서로 하는가 |
| 2 | 파일 안 참조 | 필요할 때 본다. 평평한 규칙 묶음도 여기 |
| 3 | 분리 참조 | 별도 파일로 빼고 포인터로 도달. 포인터가 걸릴 때만 로딩 |

**점진적 공개**는 이 사다리를 내려보내는 동작이다. 토큰 절약이 목적이 아니라 위층을 읽을 수 있게 지키는 장치다. 판정 기준은 갈래다. 모든 갈래가 사용하는 것은 본문에 두고, 일부 갈래만 도달하는 것은 포인터 뒤로 보낸다.

단계가 있는 문서에서 내려보내야 할 참조를 본문에 두면 단계가 파묻힌다. 읽기 편함의 문제가 아니라 그 단계를 수행할지가 실행마다 달라지는 문제다.

이 레포의 적용례: `skills/flow/guides/` 는 단계 진입 시에만 읽고, `config/style-rules/references/`·`metrics/` 는 세션 시작 미러에서 뺀다.

## AU4. 완료 조건

단계는 **완료 조건**으로 끝난다. 두 성질이 결과를 좌우한다.

- **명확성**: 끝났는지 아닌지를 에이전트가 판별할 수 있는가. "이해에 도달했다" 같은 흐린 조건은 **조기 완료**를 부른다. 아직 안 끝났는데 끝났다고 넘어가는 것이고, 뒤에 남은 단계가 보일수록 앞 단계를 서두른다. 먼저 조건 문구를 조이고, 그래도 흐릿한데 서두르는 게 관찰되면 그때 순서를 갈라 뒤 단계를 시야에서 뺀다. 숨기기는 실제 컨텍스트 경계(하위 에이전트 위임·인계)에서만 듣는다.
- **요구량**: 얼마나 요구하는가. "변경 목록을 낸다"와 "바뀐 항목을 하나도 빠짐없이 대조한다"는 같은 단계에서 다른 양의 조사를 끌어낸다. 요구량은 단계에만 걸리지 않는다. "모든 규칙을 적용한다"는 평평한 참조 묶음에도 같은 방식으로 걸린다.

| 조건 | 판정 |
|------|------|
| "표를 만든다" | 낮음. 표가 있으면 끝나므로 그 표가 무엇을 말하는지는 안 나온다 |
| "비교마다 결론을 맺고, 결론 없는 비교 0건을 확인한다" | 높음. 세어서 판별되고 빠뜨림이 드러난다 |

셀 수 있으면서 빠뜨림을 잡는 조건이 가장 세다.

## AU5. 선행어와 부정 지시

**선행어**(leading word)는 모델이 사전학습에서 이미 들고 있는 압축 개념어다. 문장으로 풀지 않고 토큰으로 반복하면 그 말이 나올 때마다 같은 동작을 꺼내고, 정의에 드는 토큰을 사전학습이 대신 낸다.

자체 조어도 정의를 붙이면 동작하지만 사전학습이 받쳐 주지 않으므로 정의 비용을 직접 낸다. 있는 말을 먼저 찾는다. 이 판단은 `tone.md T5`(교과서 용어 우선)·`T9`(임의 신조어 합성 금지)와 같은 뿌리다.

세 군데 흩어져 설명된 성질 묶음, 한 문장을 들여 개념 하나를 가리키는 포인터는 선행어 하나로 접힐 자리다.

**부정 지시**는 이 옆의 실패 모드다. 금지형은 금지 대상을 컨텍스트로 끌어와 오히려 더 잘 떠오르게 만든다. 목표 동작을 긍정형으로 적어서 금지 대상이 아예 나오지 않게 한다.

Bad:
```
장황하게 쓰지 마세요. 수식어를 남발하지 마세요.
```

Good:
```
한 문단은 2-4문장으로 쓴다. 형용사는 측정값이 있을 때만 붙인다.
```

긍정형으로 못 쓰는 하드 가드에만 금지형을 남기고, 그때도 목표 동작을 함께 적는다.

> 이 레포의 `config/style-rules/forbidden-words.json` 은 금지형 목록이지만 성격이 다르다. 컨텍스트에 주입하지 않고 교정 단계 대조 + 사후 통지로만 쓰여 출력을 막지 않고, 룰마다 `대체` 필드로 긍정형 처방을 함께 싣는다. 판단 배경은 [`docs/design-philosophy.md`](../../../docs/design-philosophy.md) 결정 3 참조.

## AU6. 가지치기

| 가지치기 대상 | 처방 |
|------|------|
| 단일 출처 | 한 의미는 한 곳에만 둔다. 두 곳에 있으면 유지 비용을 두 배로 내고, 계층에서 실제보다 높은 자리를 차지한다 |
| 환경이 곧 출처 | `package.json` 스크립트, 설정 파일, 디렉토리 구조, `--help` 도 출처다. 그것을 옮겨 적은 문서는 캐시이고, 찾기 비싼 것만 캐시할 값이 있다 |
| 관련성 | 각 줄이 이 문서가 하는 일에 아직 걸리는지 본다. 처음부터 안 걸렸거나(설명을 위한 설명), 세상이 바뀌어 낡았거나 |
| no-op | 모델이 기본값으로 이미 하는 지시는 비용만 내고 아무것도 바꾸지 않는다. 판정은 문서를 실행해서 한다. 걸리면 문장 전체를 지운다 |
| 침전 | 더하는 건 안전해 보이고 빼는 건 위험해 보여서 낡은 층이 쌓인다. 살아 있는 게 뭔지 찾으려면 층을 파고 내려가야 하는 상태가 침전이다 |

캐시할 값이 있는 것은 찾아서 안 나오는 것이다. 적히지 않은 관행, 그렇게 정한 이유, 어떤 설정도 알려 주지 않는 함정.

## AU7. 소비자에게 주는 경로

문서·안내 문구·오류 메시지가 사람이나 다른 도구에 건네는 경로에는 **버전과 설치 위치를 넣지 않는다.** 둘 다 갱신 때 바뀌고, 바뀐 뒤에도 문구는 남는다.

| 경로 요소 | 처방 |
|------|------|
| 버전 디렉토리 | 고정 진입점을 참조한다. 버전이 들어간 경로를 문구에 넣으면 그 문구를 복사해 둔 사람이 나중에 옛 것을 실행한다 |
| 글롭과 정렬 | `*` 로 찾게 하지 않는다. 자릿수가 다른 버전이 섞이면 사전순 정렬이 최신을 집지 못한다. 소비자마다 정렬 규칙을 다시 쓰게 되고, 레이아웃이 바뀌면 전부 깨진다 |
| 셸 확장 | 큰따옴표 안의 `~` 는 확장되지 않는다. 그대로 제시하는 명령은 실행해 보고 싣는다 |
| 없을 때 | 고정 진입점이 없으면 조용히 기본값으로 떨어지지 않고 그 사실을 알린다 |

경로를 주는 쪽이 해석 책임을 갖는다. 소비자가 찾게 하면 그 해석이 소비자 수만큼 복제된다.

## AU8. 긴 규칙 문서는 앞에 항목 색인을 둔다

항목이 스무 개를 넘는 문서는 앞에 항목 번호와 한 줄 이름을 나열한다. 색인이 없으면 어떤 항목이 있는지 알기 위해 전문을 읽어야 한다.

읽는 쪽이 모델일 때 비용이 그대로 드러난다. 30KB 문서를 열어 실제로 사용한 항목이 다섯 개였던 사례가 있다. 색인이 있으면 본문을 열지 않고 해당 항목만 찾아 읽는다.

색인은 목차가 아니다. **판정 항목의 목록**이다. 헤딩은 계열 이름만 담아 어떤 판정이 있는지 알려 주지 못한다.
