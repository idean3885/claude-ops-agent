# 문서 유형 프로필

각 익스텐션이 반복하던 세 절(`적용 대상` · `base 대비 적용 강도` · `합격선`)을 한곳에 모은 표다. 이 세 절은 규칙이 아니라 유형마다 값만 달라지는 자리이므로, 유형이 늘면 파일이 아니라 행이 하나 는다.

익스텐션 파일에는 그 유형의 고유 규칙과 `필수 구조` 만 남는다. 유형별 파라미터는 여기가 정본이다.

| 문서 유형 | 익스텐션 | 접두 |
|-----------|----------|------|
| 블로그 | [blog.md](blog.md) | `B` |
| 위키 | [wiki.md](wiki.md) | `W` |
| 정보성 | [info.md](info.md) | `I` |
| 지식 | [knowledge.md](knowledge.md) | `K` |
| PoC | [poc.md](poc.md) | `PC` |
| 이슈 | [issue.md](issue.md) | `ISS` |
| 장표 | [deck.md](deck.md) | `D` |
| 아키텍처 | [architecture.md](architecture.md) | `AR` |
| 데일리로그 | [dailylog.md](dailylog.md) | `DL` |
| 동료리뷰 | [peer-review.md](peer-review.md) | `PR` |
| 성과평가 | [work-review.md](work-review.md) | `WR` |

## 1. 문서의 목적

**매체는 목적을 정하지 않는다.** 같은 위키에 학습 안내도, 조회용 참조도, 시험 보고도 쓴다. 그래서 매체로 규칙을 정하면 목적이 다른 두 글이 같은 판정을 받는다.

목적은 글마다 판정한다. 아래 분류는 외부 표준을 원천으로 삼고 여기서 발명하지 않는다. 판본과 확인일은 [`references/upstream.md`](../references/upstream.md) 가 갖는다.

**Diátaxis** (Daniele Procida) 는 두 기준으로 네 가지를 나눈다. 실천 지식(knowing how)과 이론 지식(knowing that), 습득과 적용이다.

| | 습득 | 적용 |
|---|---|---|
| 실천 지식 | 학습 | 과제 안내 |
| 이론 지식 | 설명 | 참조 |

**IMRaD** 는 측정·시험 보고의 구조 표준이다. 서론·방법·결과·논의 순서다. 발견 순서를 그대로 따른다.

설득은 두 원천이 담지 않는다. 원천 미확정 상태로 둔다. 확정되기 전에는 base 값을 그대로 사용한다.

### 목적별 적용

| 목적 | 산문 리듬 | 서술 순서 | 완곡 |
|------|----------|----------|------|
| 학습 | 적용 | 순차 | 불허. 수행할 동작에 유보를 넣지 않는다 |
| 과제 안내 | 면제 | 절차 순 | 불허. 같음 |
| 참조 | 면제 | 조회 순 | 불허. 같음 |
| 설명 | 적용 | 두괄식 | 근거 강도에 맞춰 허용 |
| 보고 | 면제 | IMRaD | 근거 강도에 맞춰 허용 |
| 설득 | (원천 미확정) | 두괄식 | 근거 강도에 맞춰 허용 |

- **산문 리듬**은 `ai-tells.md` `E-1`(문장 길이 편차) 을 뜻한다. `E-2`·`E-5`·`E-6` 는 표본 아홉 편에서 위반 0건이라 게이트를 걸지 않았다. `E-3`·`E-4`·`E-7` 은 언어 규칙이므로 목적과 무관하게 적용한다
- **서술 순서**의 기본값은 두괄식이다. 보고만 다르다. 결과를 먼저 놓으면 읽는 사람이 발견 과정의 타당성을 확인할 자리가 없다
- **완곡**의 판정 기준은 `ai-tells.md` `G` 계열이 갖는다. 이 표는 그 기준을 목적별로 켜고 끄는 자리다

### 리듬을 목적으로 나누는 이유

`E` 계열은 기계 산출물 탐지 지표다. 문장 길이가 균일하면 기계가 쓴 흔적이라는 관측이다. 근거는 번역학·post-editese 문헌이다. **좋은 문서를 정의하려고 만든 규칙이 아니다.**

그런데 개조식·표 중심 문서에서 균일한 문장 길이는 성질이다. 같은 관측값이 목적에 따라 뜻이 반대다. 표본 측정에서 이슈 3건과 스킬 문서 2건이 전부 `E-1` 위반이고 산문은 4편 중 1편이었다.

## 2. 적용 대상

어떤 매체에 어떤 익스텐션이 걸리는지를 정한다. 두 익스텐션이 함께 걸리는 조합은 `적용` 열에 명시한다.

| 정보성 | 설정 가이드·트러블슈팅 | `info` |
| 정보성 | API 사용 가이드 | `info` |
| 정보성 | 절차 안내 (배포·릴리스·온보딩) | `info` |

| PoC | PoC 문서 (위키·레포 `.docs/`) | `poc` |
| PoC | 블로그 PoC 회고 | `blog` + `poc` 의 결론 선행·재현 가능성 항목 |

| 장표 | 비교·판단을 전달하는 페이지·슬라이드 | `deck` |

| 동료리뷰 | 조직장 참고용 동료 평가 | `peer-review` |
| 동료리뷰 | 360도 리뷰 | `peer-review` + 익명 처리 |
| 성과평가 | 연말 성과평가 자기 기술서 | `work-review` |

## 4. 유형별 분량 기준값

착수 전 계획 게이트(`../base/purpose.md` PU2 의 분량 항목)에 적을 값이다. 추측한 상한은 낮으면 필요한 내용을 깎게 하고 높으면 아무것도 제약하지 않는다. 그래서 같은 유형의 기존 산출물에서 뽑는다.

단위는 행이고 코드 블록은 세지 않는다. 측정 도구와 각 값의 정의는 `../base/length.md` 「총량 측정」이 갖는다.

측정일 2026-08-27, 이 저장소와 블로그 저장소의 463편 기준이다.

|-----------|------|------|--------|------|-------------|
| 이슈 본문 | 200 | 12 | 26 | 40 | 73% |
| PR 본문 | 177 | 12 | 26 | 49 | 65% |
| `SKILL.md` | 10 | 5 | 40 | 146 | 40% |
| ADR | 12 | 45 | 64 | 70 | 100% |
| 규칙 문서 (extensions) | 12 | 47 | 80 | 158 | 67% |

| 스킬 가이드 | 5 | 42 | 177 | 205 | 60% |
| 규칙 문서 (base) | 7 | 104 | 158 | 450 | 57% |

**포함률이 낮은 유형에는 상한을 강하게 걸지 않는다.** ADR 은 100% 라 상한 70행이 실제로 판정에 쓰인다. `SKILL.md` 는 40% 로, 5행부터 293행까지 흩어져 있어 이 유형의 상한은 계획 시 참고값이다. 그 편차의 원인은 스킬마다 담는 절차의 수가 다른 것이고, 분량 규칙으로 좁힐 대상이 아니다.

표에 없는 유형은 직접 측정한다. 3편 미만이면 상한을 적지 않는다.

이 값은 저장소의 산출물이 쌓이면 달라진다. 낡은 값으로 문서를 깎지 않도록, 상한 초과가 반복되면 다시 측정해 표를 교체한다.

## 5. 합격선

유형마다 통과 조건이 다르다. `없으면 합격 불가` 로 표시된 항목은 다른 항목이 모두 통과해도 불합격이다.
