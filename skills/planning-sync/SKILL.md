# 기획 최신화

기획을 다시 읽어 직전에 읽은 기획과 비교하고, 바뀐 항목마다 설계의 어디를 보완해야 하는지 보고한다.

기획이 정답이다. 설계가 기획과 다르면 기본값은 기획대로 고치는 것이고, 회의로 가져갈 질문은 기획이 아직 정하지 않은 것뿐이다. 이 스킬은 그 대조를 한 번 하고 끝내지 않고, 바뀐 것만 다시 대조하도록 기준(스냅샷)을 남긴다.

## 역할

절차만 정한다. 판정과 반영은 이 스킬의 몫이 아니다 ([ADR 0019](../../docs/adr/0019-roles-follow-raci-a-c-r.md)).

| 무엇 | 누가 |
|------|------|
| 조회 · 디프 · 보완점 보고 | 이 스킬 (메인 세션이 직접. 조회는 도구 호출 몇 번이라 위임하지 않는다) |
| 보완점을 받을지 판정 | 결정자 |
| 새 기획 항목 자체가 타당한가 | 기획 전문가 ([`/expert`](../expert/SKILL.md), [`experts/planner.md`](../../experts/planner.md)) |
| 설계 원본 수정 | 소비 환경의 설계 문서 작성 절차 |

## 오버레이

기획 출처는 환경마다 다르다. 이 레포는 형태를 고정하지 않고, 소비 환경이 `~/.claude/ops-agent/planning/<프로젝트>.md` 에 선언한다. 파일 하나가 프로젝트 하나다.

| 항목 | 필수 | 담는 것 |
|------|------|---------|
| 출처 | 예 | 기획이 있는 곳(URL)과 읽을 범위. 화면 기획이면 페이지 · 프레임 단위로 적는다. |
| 정본 | 예 | 출처 안에서 무엇이 정답인가 (예: 화면보다 프레임 주석) |
| 스냅샷 자리 | 예 | 직전 기획을 저장하는 디렉토리 |
| 설계 | 예 | 대조할 설계 원본의 위치 |
| 도구 | 아니오 | 조회 도구 오버라이드. 없으면 아래 기본값 |

| 상황 | 동작 |
|------|------|
| 파일이 하나 | 그 프로젝트로 진행한다. |
| 파일이 여럿이고 지시에 프로젝트가 없다. | 어느 프로젝트인지 묻고 멈춘다. |
| 파일이 없다. | 출처를 묻고 멈춘다. 출처를 추측해 찾아 나서지 않는다. |

## 1. 조회

기본 도구는 Chrome DevTools MCP 다. 기획서 형태(화면 기획 · 문서 · 위키)를 가리지 않고 브라우저로 열 수 있으면 같은 경로로 읽는다. 오버레이에 `도구` 가 있으면 그것을 쓴다.

| 한다. | 하지 않는다. |
|------|-------------|
| 오버레이가 적은 범위(프레임 · 절)만 연다. | 페이지 전체를 한 번에 읽는다. |
| 텍스트는 `take_snapshot`, 화면은 필요한 범위만 `take_screenshot` | 편집 · 코멘트 · 상태 변경 |
| 처음 허용받은 세션에서 필요한 권한만 쓴다. | 로그인 · 권한 요청을 대신 진행한다. |

로그인이 필요하면 사용자에게 열어 달라고 하고 멈춘다. 읽은 원문은 정본 기준으로 항목(프레임 · 절)마다 나눠 둔다.

## 2. 디프

스냅샷 자리의 가장 최근 파일과 이번 조회를 항목 단위로 비교한다.

| 분류 | 판정 |
|------|------|
| 추가 | 직전에 없던 항목 |
| 삭제 | 이번에 없는 항목 |
| 변경 | 같은 항목의 정본 문구가 다르다. |
| 표현 변경 | 문구는 다르지만 뜻이 같다. 한 줄로 묶어 알리고 대조하지 않는다. |

스냅샷이 없으면 첫 실행이다. 디프 없이 이번 조회를 기준선으로 저장하고 「기준선 생성 · 항목 N개」만 보고한다. 기준선 전체를 설계와 대조하는 일은 범위가 다르므로 결정자가 따로 지시할 때 한다.

## 3. 보완점 보고

변경 항목을 한 번에 다 펼치지 않는다. 하나씩 세 줄로 내고 판정을 받은 뒤 다음으로 간다.

```text
기획: <바뀐 정본 문구. 변경이면 직전 → 이번>
설계: <설계 원본의 해당 자리와 지금 내용. 없으면 "설계 없음">
기획대로면: <설계에서 바뀌는 것>
```

| 판정 | 다음 |
|------|------|
| 반영 | 반영 목록에 모은다. |
| 기획 확인 | 기획이 정하지 않은 것이다. 질문 한 줄로 미결 목록에 모은다. |
| 무관 | 버린다. |

판정을 지어내지 않는다. 설계 쪽 대응 자리를 못 찾았으면 「설계 없음」으로 두고, 있을 것 같은 자리를 추측해 채우지 않는다.

## 4. 마무리

1. 이번 조회를 스냅샷 자리에 새 파일(`YYYY-MM-DD.md`)로 저장한다. 직전 파일은 지우지 않는다. 항목마다 정본 원문을 요약 없이 남긴다. 요약하면 다음 디프의 기준이 흐려진다.
2. 반영 목록과 미결 목록을 한 번에 보고한다.
3. 설계 원본 수정은 반영 목록을 들고 소비 환경의 설계 문서 절차로 넘긴다. 이 스킬 안에서 고치지 않는다.

스냅샷 자리가 레포 안이면 그 레포의 반영 절차(커밋 · 릴리스)를 따른다.

## 하지 않는 것

| 무엇 | 이유 |
|------|------|
| 기획 수정 · 코멘트 | 기획은 정답의 자리다. 읽기만 한다. |
| 일정 · 진척 추적 | 기획 내용의 변화만 본다. |
| 기획 문서 품질 판정 | 기획 전문가가 맡는다. |
