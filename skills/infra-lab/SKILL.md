# 인프라 실험 랩

클라우드 구성 하나를 만들고 부하를 올려 한계를 관측한 뒤 철거하는 한 바퀴를 정의한다. 역할과 도구는 외부가 갖고, 이 스킬은 **순서와 기록**만 갖는다.

진입하기 전에 `requires:` 를 확인한다. 미충족이면 [`bootstrap`](../bootstrap/SKILL.md) 의 미충족 보고를 내고 멈춘다. 절반만 도는 것은 없는 것보다 나쁘다.

## 이 스킬이 갖는 것과 갖지 않는 것

| 갖는다 | 외부에 위임한다 |
|--------|-----------------|
| 회전 순서 | 클라우드 설계 지식 |
| 어느 단계에서 누구를 부르는가 | IaC 문법과 검사 |
| 무엇을 기록으로 남기는가 | 부하 도구 사용법 |
| 언제 멈추는가 | 지표 수집과 대시보드 |

외부 의존은 [외부 의존](#외부-의존) 에 있다. 그 목록에 없는 지식이 필요하면 회전을 멈추고 어느 출처가 그것을 갖는지 먼저 정한다.

## 쓰기는 한 갈래

파일과 클라우드 자원을 고치는 것은 `infra-lab-operator` 하나다. 나머지 전문가는 읽고 의견만 낸다.

여럿이 동시에 고치면 서로의 결정을 덮어쓰고, 무엇이 왜 그렇게 됐는지 회전이 끝난 뒤 되짚을 수 없다. 판단만 하는 역할은 파일을 고치지 않으므로 여럿이어도 비용이 리포트 한 번으로 끝난다.

## 회전

한 회전은 여섯 단계다. 각 단계는 산출물 하나를 남기고 다음으로 넘긴다.

| 단계 | 실행 | 부르는 전문가 | 남기는 것 |
|------|------|---------------|-----------|
| 1. 구성 | operator | [인프라](../../experts/infra.md) · 구성 보안 | IaC 코드, 비용 견적 |
| 2. 배포 | operator | 없음 | 엔드포인트, 헬스 확인 결과 |
| 3. 부하 | operator | 없음 | 단계별 요청률과 응답 지표 |
| 4. 관측 | operator | [인프라](../../experts/infra.md) | 한계 지점과 병목 후보 |
| 5. 기록 | operator | 없음 | 실험 기록 (아래 양식) |
| 6. 철거 | operator | 없음 | 자원 0 확인 |

부하는 요청률을 단계로 올린다. 한 번에 최대치를 넣으면 어느 지점에서 무엇이 먼저 무너지는지 나오지 않는다.

1단계에서 구성 보안을 부르는 이유는 그 뒤로는 되돌리는 비용이 커지기 때문이다. 배포 후에 열린 접근 범위를 발견하면 이미 열려 있던 시간이 생긴다.

## 실험 기록

회전마다 한 건을 남긴다. 다섯 칸 중 넷은 operator 가 채우고 **결론은 사람이 쓴다.**

| 칸 | 채우는 주체 | 내용 |
|----|-------------|------|
| 가설 | 사람 | 이 구성에서 무엇이 먼저 한계에 닿을 것인가 |
| 부하 프로필 | operator | 요청률 단계, 지속 시간, 통과 기준 |
| 관측 | operator | 측정값과 한계 지점 |
| 결론 | **사람** | 가설이 맞았는가, 다음 구성을 어떻게 바꾸는가 |
| 다음 실험 | 사람 | 한 가지만 바꾼다 |

결론 칸을 사람이 쓰는 이유는 그 칸이 학습이 일어나는 자리이기 때문이다. operator 가 채우면 측정은 남고 판단은 남지 않는다.

기록 위치는 소비 프로젝트가 정한다. 이 레포는 양식만 갖는다.

## 멈추는 조건

회전 중에는 확인을 구하지 않고 끝까지 간다. 판단이 필요한 자리는 원장에 `결정: 무엇을 정했나 · 왜 · 틀리면 무엇을 잃나` 로 기록하고 진행한다.

멈추는 것은 넷이다.

| 조건 | 예 |
|------|-----|
| 되돌릴 수 없는 행위 | 데이터 삭제, 계정 조작 |
| 보안에 영향을 주는 행위 | 접근 범위 확대, 권한 정책 변경 |
| 랩 밖으로 미치는 부수 효과 | 랩 계정 밖 자원 접근, 외부 엔드포인트로 부하 |
| 계획 자체가 성립하지 않음 | 어느 길로 가도 추측이 되는 상태 |

넷 중 하나를 만나면 무엇을 왜 하려는지 제시하고 사람의 판정을 기다린다.

## 비용 상한

랩에서는 자원을 만들고 지우는 일이 회전마다 반복되므로 상한을 먼저 정하고 시작한다.

| 층 | 무엇을 막는가 |
|----|---------------|
| 조직 정책 | 되돌릴 수 없는 것 (조직 구조, 청구, 감사 로그 삭제) |
| 예산 임계 | 알림 → 자원 정지 → 신규 생성 거부 |
| 배포 전 검사 | 열린 접근 범위, 자격 증명 노출 |
| 회전 종료 철거 | 남은 자원 |

상한 값은 소비 프로젝트가 정한다.

## 외부 의존

| 무엇 | 어디서 | 맡는 것 |
|------|--------|---------|
| 클라우드 설계·비용·제어 | 클라우드 벤더 공식 플러그인 | 1단계 구성, 자원 조작 |
| IaC 규칙과 검사 | IaC 벤더 공식 스킬 | 코드 규약, 테스트 |
| 구성 검토 · 부하 판독 · 지표 검토 · 구성 보안 | 에이전트 마켓플레이스 | 읽고 의견만 |
| 실행 규율과 원장 | 외부 오케스트레이션 스킬 | 작업마다 새 서브에이전트, 각 작업 뒤 검토 |

구성 도구와 부하 도구는 `requires:` 에 있어 진입 게이트가 본다. 나머지는 없어도 회전이 돌고 판정의 근거가 얕아진다. 이름과 설치 경로는 소비 프로젝트가 자기 환경에 맞춰 채운다.
