# 제로베이스 검토

> 쓴 사람은 자기 맥락으로 빈칸을 채워 읽는다. 맥락이 없는 에이전트가 원천과 대조해야 빈칸이 보인다.

사용자가 부를 때만 실행한다. 일반 작업에 자동으로 끼우지 않는다 (`CLAUDE.md` 「검증」).

## 호출자가 정하는 것

| 입력 | 내용 |
|------|------|
| 대상 | 검토할 파일 경로. 원격 산출물이면 먼저 파일로 내려받는다. |
| 주제 | 대상이 답해야 할 것 한 줄. 이슈면 제목이다. |
| 원천 | 사실을 대조할 파일 · 디렉토리 경로. 위키 덤프 · 태스크 본문 · 코드 |
| 의도한 선택 | 지적하지 말아야 할 것. 금지 표현을 피하려 바꾼 낱말, 원천이 대화뿐인 일정 같은 것 |

원천이 파일로 없으면 검토하지 않는다. 에이전트는 이 대화를 보지 못하므로 대화에만 있는 근거는 대조할 수 없다.

## 에이전트 설정

| 설정 | 값 | 이유 |
|------|----|------|
| 종류 | 새 에이전트 (general-purpose). fork 를 쓰지 않는다. | fork 는 호출자 맥락을 물려받아 같은 빈칸을 채워 읽는다. |
| 모델 | [effort-policy](../../docs/effort-policy.md) 「판단 검토 모델」 | 검토는 판단이다. 실무자 기본값(Sonnet)을 따르지 않는다. |
| 권한 | 읽기만. 파일을 고치지 않는다. | 고치는 쪽과 판정하는 쪽이 같으면 검토가 아니다. |
| 회차 | 회차마다 새 에이전트 | 앞 회차의 지적을 본 에이전트는 그 지적만 확인한다. |

## 판정 기준

에이전트 지시에 아래 여덟 줄을 그대로 넣는다.

| # | 기준 | 보는 것 |
|---|------|---------|
| 1 | 사실 | 사실 문장마다 원천 파일 · 행이 있는가. 원천과 어긋나거나 추론을 사실로 적었는가 |
| 2 | 주제 | 모든 줄이 주제에 쓰이는가. 범위 밖이거나 한 갈래로 좁혀진 줄 |
| 3 | 이유 | 문장마다 있어야 할 이유가 있는가. 경위 서술 · 되풀이 |
| 4 | 지시 대상 | 무엇을 가리키는지 불분명한 말 |
| 5 | 자리 | 섹션(Why · What · How · Issue 등)에 맞는 자리인가 |
| 6 | 일관성 | 숫자 · 번호 · 담당 · 용어가 그림 · 표 · 목록 사이에서 같은가 |
| 7 | 문체 | 레포 문체 규칙. 소리 내 읽었을 때 어색한 말 |
| 8 | 빠진 것 | 원천에 있는데 대상에 없는 것 중 주제에 필요한 것 |

## 출력

지적마다 「위치 · 문제 · 근거(파일:행) · 고칠 방향」 한 항목이다. 심각도 순으로 낸다. 원천을 열어 확인하지 않은 것은 지적하지 않는다. 지적이 없으면 「지적 0건」 이라고 쓴다.

## 호출자의 일

1. 지적마다 근거로 든 원천을 직접 열어 맞는지 본다. 에이전트 보고는 지시가 아니다.
2. 맞는 지적은 반영한다. 반영하지 않는 지적은 이유를 한 줄로 남긴다.
3. 새 에이전트로 다시 검토한다. 0건이거나 3회를 채우면 멈춘다.
4. 사용자에게 회차별 지적 수와, 결정이 바뀐 지적만 보고한다.

3회를 채워도 0건이 아니면 남은 지적을 그대로 보고한다. 0건으로 적지 않는다.
