# 대외비 가드

텍스트가 기록되기 직전 통과해야 하는 검증 게이트. 방향은 둘이다.

## 표면 분류

표면은 셋이고, 표면마다 적용되는 규칙이 다르다. 호스트만 보면 둘로만 나뉘어 **비공개 저장소가 공개 표면으로 오판된다.**

| 표면 | 판정 | 추가 규칙 | 막는 방향 |
|------|------|-----------|-----------|
| `public` | 사내 호스트 아님 + 공개 확인 | `externalOnly` | 사내 → 공개 (대외비 위반) |
| `private` | 사내 호스트 아님 + 비공개 확인 | 없음 |—|
| `internal` | 사내 호스트 | `personalDevOnly` | 개인 → 사내 (개인 환경 노출) |

`keywords`·`patterns`(최상위)는 표면과 무관하게 항상 적용된다. 존재 자체가 노출되면 안 되는 항목을 여기 둔다.

`private` 는 본인 비공개 공간이므로 추가 규칙을 걸지 않는다. 여기서 막으면 비공개 저장소를 원천으로 쓰는 작업이 멈춘다.

### 공개 여부 판정

사내 호스트는 호스트만으로 확정한다. 그 외 호스트는 `gh repo view <slug> --json visibility` 로 확인하고 결과를 캐시한다.

| 캐시 속성 | 값 |
|-----------|---|
| 캐시 경로 | `~/.claude/ops-agent/cache/repo-visibility.json` |
| 키 | `host/owner/repo` |
| 유효 기간 | 7일 |
| 조회 시점 | `git commit` · `gh issue/pr/release` · 이슈 어댑터(`gh-issue.sh create/start`) 만. 레포당 최초 1회 |
| 조회 실패·불명 | `public` 으로 닫는다 |

측정값: 최초 조회 약 590ms, 캐시 적중 약 83ms.

조회 실패를 `public` 으로 닫는 이유는 두 오판의 비용이 다르기 때문이다. 비공개를 공개로 잘못 보면 불필요하게 막히고, 공개를 비공개로 잘못 보면 대외비가 노출된다. 후자가 되돌릴 수 없다.

캐시 파일은 **저장소 단위 예외를 표현하는 수단**이기도 하다. 조회가 안 되는 환경에서는 항목을 직접 적어 고정한다. 경로 예외(`allowPaths`)와 달리 다른 저장소로 새지 않는다.

## 적용 대상

다음 명령/API는 **공개 표면**에 텍스트를 기록한다. 실행 전 가드 필수.

- `gh issue create`, `gh issue edit`, `gh issue comment`
- `gh-issue.sh create`, `gh-issue.sh start` (이슈 어댑터. `--title` · `--body-file` 이 대상)
- `gh pr create`, `gh pr edit`, `gh pr comment`, `gh pr review`
- `gh release create`, `gh release edit`
- `git commit -m`, `git commit --amend` (퍼블릭 리모트 대상 브랜치)
- `git push` (커밋 메시지가 공개됨)

검증 대상 텍스트:
- `--body`, `--body-file`, `--title`, `-m` 옵션 값

## 검사 시점

훅(`scripts/pre-tool-use.mjs`)은 Bash 도구 호출만 본다. 파일 편집(Edit·Write) 자체는 검사하지 않는다. 대신 **커밋 시점에 커밋 대상 diff** 를 검사한다.

| 검사 대상 | 검사 시점 |
|-----------|-----------|
| 이슈·PR·릴리즈 본문·제목 | 해당 명령 실행 직전 |
| 커밋 메시지 | `git commit` 직전 |
| 커밋 대상 파일 내용 | `git commit` 직전, diff 의 **추가된 줄만** |

편집 시점이 아니라 커밋 시점인 이유:

- 편집 시점에는 그 파일이 어디로 갈지 모른다. gitignore 대상일 수도, 사내 레포일 수도 있다. 커밋 시점에는 레포 리모트로 표면(`public`·`private`·`internal`)을 판정할 수 있다
- 추적 대상만 diff 에 오르므로 로컬 전용 파일이 자연히 제외된다
- 커밋당 1회만 돌아 비용이 낮다

**삭제된 줄은 검사하지 않는다.** 대외비를 제거하는 커밋이 자기 가드에 막히면 안 된다.

### 대상 디렉토리

표면 판정과 diff 검사는 **같은 경로**를 본다. 명령의 `cd` · `git -C` 인자를 해석하고, 없으면 훅이 받은 `cwd` 를 쓴다.

경로를 해소할 수 없으면 커밋을 **차단한다**.

| 상황 | 처리 |
|------|------|
| `cd "$VAR" && git commit` | 차단: 훅은 셸 변수를 확장할 수 없다 |
| `cd /없는/경로 && git commit` | 차단 |
| `cd /실제/경로 && git commit` | 그 경로로 검사 |
| `git -C /실제/경로 commit` | 그 경로로 검사 |

검사하지 못한 상태를 통과로 두면 "미검사" 와 "검사해서 깨끗함" 이 같아진다.

`git` 과 `commit` 사이에는 전역 옵션이 올 수 있다(`-C`, `-c`, `--no-pager`, `--git-dir=` 등). 커밋 판정 정규식은 이 형태를 받아야 한다. 인접만 보면 `git -C <path> commit` 이 커밋으로 인식되지 않아 파일 내용 검사가 통째로 건너뛰어진다.

**한계**: 이미 커밋된 내용을 `--amend` 로 다시 커밋할 때 기존 커밋의 내용은 다시 검사하지 않는다. diff 가 검사 한도(256KB)를 넘으면 앞부분만 검사하고, 그 사실을 알린다.

키워드를 정당하게 다루는 문서·설정은 설정의 `allowPaths` 정규식으로 제외한다.

특히 **예시 문자열**이 유입 경로다. 실제 프로젝트명·제품명·경로·트래커 번호를 예시로 쓰면 그대로 공개 표면에 남는다.

| 위치 | 중립 표기 |
|------|-----------|
| 프로젝트·서비스명 | `project-a`, `service-b` |
| 로컬 경로 | `-Users-me-git-project-example-repo` |
| 트래커 번호 | `#NNNN` |
| 외부 어댑터 스킬 | 역할 서술 (예: "사내 트래커 어댑터의 태스크 스킬") |

예시는 동작을 보이는 게 목적이므로 실제 값일 필요가 없다. 작성 단계에서 중립 표기를 쓴다.

이미 커밋된 내용은 히스토리에 남는다. 현재 HEAD 정리만으로는 되돌릴 수 없다.

## 전수 스캔

가드는 커밋 diff 의 **추가된 줄**만 본다. 가드 도입 이전이나 무동작 기간에 들어간 내용은 다시 검사되지 않는다. 레포 전체를 같은 규칙으로 훑는 수단을 따로 둔다.

```bash
node scripts/confidential-scan.mjs [레포경로...] [옵션]
node scripts/confidential-scan.mjs --owner <소유자> --branches      # 전수
```

규칙 로딩과 표면 판정은 `scripts/confidential-rules.mjs` 를 가드와 공유한다. 복제하면 스캐너가 "깨끗함" 을 보고하는데 가드는 막는 상태가 생긴다.

### 검사 범위를 사람이 정하지 않는다

점검 대상을 손으로 열거하면 빠진다. 두 층에서 각각 빠진다.

| 층 | 무엇이 빠지는가 | 실측 |
|----|----------------|------|
| 레포 | 기억하는 목록과 실제 목록이 어긋난다 | 공개 레포 17개 중 12개만 열거해 "전부 깨끗함" 으로 결론냈고, 누락 5개 중 한 곳에 448건 |
| 브랜치 | 정리 커밋을 받지 못한 브랜치가 정리 이전 트리를 보존한다 | 기본 브랜치가 깨끗한 레포에서 잔재 브랜치 3개가 각각 74·75·74건 |

| 옵션 | 효과 |
|------|------|
| `--owner <name>` | `gh repo list` 로 레포 목록을 받아 전체 순회. 레포마다 임시 클론 후 검사, 끝나면 제거 |
| `--visibility <v>` | `public`(기본)·`private`·`internal`·`all` |
| `--branches` | 기본 브랜치 외 원격 브랜치를 워크트리로 검사 |
| `--progress` | 진행 상황을 stderr 로 |

브랜치 검사는 **워크트리**를 쓴다. 체크아웃으로 사용자의 작업 트리를 바꾸지 않는다.

### 잔재 브랜치 판정

브랜치마다 고유 커밋 수와 머지 여부를 함께 찍는다.

| 조건 | 표시 | 의미 |
|------|------|------|
| 고유 커밋 0건 + 기본 브랜치 조상 | `삭제 안전` | 정리 이전 커밋을 가리키는 ref 일 뿐. 지워도 잃는 게 없다 |
| 그 외 | `고유 커밋 N건 · 미머지` | 내용 판단이 필요하다 |

`삭제 안전` 이고 히트가 있는 브랜치는 리포트 끝에 따로 모아 출력한다. 조치 단위가 파일이 아니라 ref 이기 때문이다.

**ref 를 지워도 커밋 객체는 남는다.** GitHub 은 SHA 로 접근되는 캐시 뷰를 유지하고, 포크가 있으면 그쪽에서 계속 접근된다. ref 삭제는 열람 경로를 없애는 것이고 데이터 제거가 아니다.

### 아카이빙은 공개를 닫지 않는다

아카이빙은 읽기 전용으로 만드는 것이다. `archived + PUBLIC` 이면 누구나 그대로 읽는다. 리포트가 이 조합에 경고를 붙이는 이유다. "정리된 레포" 로 오인하면 노출이 남는다.

공개를 닫으려면 PRIVATE 전환이나 삭제가 필요하다.

### 값을 출력하지 않는다

출력은 규칙 식별자·길이·건수·파일 경로뿐이다. 키워드 값도 매칭 문맥도 내지 않는다. 스캔 결과를 붙여 공유하는 순간 그것이 유출이 된다.

- 파일 경로에 키워드가 들어간 경우는 그 부분만 `«redacted:lenN»` 으로 치환한다. 리포트 전체를 막으면 정작 조치할 파일을 못 찾는다
- 출력 직전 자기 검사가 값 잔존을 확인하고, 남아 있으면 리포트를 내지 않는다. 원칙을 주석으로 두지 않고 기계로 강제한다
- 무엇이 걸렸는지는 `ruleId` 로 로컬 설정에서 조회한다

### 오탐 억제

| 수단 | 이유 |
|------|------|
| 확장자 목록 + 선두 8KB NUL 검사 | 확장자만 보면 놓친다. 바이너리의 우연 일치를 실제 노출로 세면 우선순위가 뒤집힌다 |
| 단어 경계 분류 (`standalone` / `substring`) | 짧은 키워드는 다른 단어 안에 우연히 들어간다. 합계만 보면 부분 일치가 노출로 보인다 |
| 비 ASCII 키워드는 경계 분류 안 함 | 한글 키워드는 앞뒤가 한글이라 경계 검사를 늘 통과해 전부 standalone 으로 보인다. 판정하지 않는다고 표시한다 |
| 크기 상한 (`--max-bytes`, 기본 1MB) | 대용량 생성물에서 시간을 쓰지 않는다 |
| `allowPaths` 적용 | 가드와 같은 예외 경로를 쓴다 |

### 조치 대상과 「참고」 구획

조치할 수 없거나 조치하지 않기로 정한 대상을 조치 대상에 남기면 리포트가 영구히 빨간 상태가 된다. 그러면 **새로 생긴 노출과 이미 판단이 끝난 노출을 구분할 수 없다.** 그래서 네 종류를 「참고」 구획으로 빼고 종료 코드에서 제외한다.

| 레포 상태 | 왜 조치 대상이 아닌가 |
|-----------|----------------------|
| 외부 소유 | 권한이 없다. 히트가 그 도구의 동작에 필요한 경우도 있다 |
| 포크 | upstream 내용이 섞인다 |
| 아카이빙 | 읽기 전용이라 해제 없이는 커밋할 수 없다. 포크와 같은 성질이다 |
| `--exclude <name>` | 확인 후 유지하기로 정한 대상. 아카이빙이 아닌데 유지하기로 한 것은 도구가 알 방법이 없다 |

빼더라도 **존재는 보고에 남긴다.** 조치 대상에서 빼는 것과 노출이 사라지는 것은 다르다. 특히 `archived + PUBLIC` 에는 경고를 붙인다.

`--include-archived` 로 아카이빙 레포를 조치 대상에 되돌릴 수 있다. 기본에서 빼는 것이 판단을 대신하는 것이 되지 않게 한다.

소유자를 판별하지 못하면 **조치 대상으로 둔다.** 판별 불가를 외부 소유로 처리하면 조치 대상이 조용히 빠진다.

레포마다 공개 여부를 함께 찍는다. private 레포의 히트를 공개 노출로 오인하면 우선순위를 잘못 매긴다.

### 종료 코드

| 코드 | 의미 |
|------|------|
| 0 | 조치 대상 히트 없음 |
| 1 | 조치 대상 히트 있음 (기본 브랜치 + 검사한 브랜치 합산) |
| 2 | 검사 실패: 경로가 저장소 아님·클론 실패·규칙 비어 있음·사용법 오류 |

검사하지 못한 대상을 0 으로 돌리지 않는다. 경로 오타나 클론 실패가 "이상 없음" 으로 보고되면 미검사와 무해가 같아진다.

같은 이유로 조회 명령의 인자를 셸에 인용 없이 넘기지 않는다. `--format=%(refname:short)` 의 괄호를 셸이 문법으로 해석해 명령이 실패하면 브랜치 목록이 빈 배열이 되고, **검사하지 않은 상태가 "0건" 으로 보고된다.** 실제로 그 형태로 한 번 조용히 통과했다.

출력에 상한이 있는 곳(규칙당 파일 목록)은 잘린 사실을 알린다. 조용히 자르면 전체를 본 것으로 오인된다.

### 히스토리 (`--history`)

키워드별로 그 값이 등장·소멸한 커밋 수만 센다. 기본은 HEAD 만이다.

**한계**: `git log -S` 는 값을 argv 로 받아야 해서 실행 중 `ps` 에 값이 잠깐 보인다. 그래서 기본이 아니라 명시 옵션이다.

## 키워드 소스

### 1. 기본 패턴 (플러그인 내장)

플러그인 공개 레포에는 **조직 특화 용어를 하드코딩하지 않는다**. 내장 패턴은 일반 원칙만 다룬다.

- 내부 식별자 변수명: `pageId`, `wikiId`, `driveId` 등 숫자형 ID 필드
- 민감 토큰 패턴: API 키, OAuth 토큰 (GitGuardian 등 기존 도구가 담당)
- 내부 도메인: provider 정의(`hostPattern` 외) 기준

### 2. 로컬 오버라이드 (조직/레포 특화)

조직/레포별 대외비 용어는 사용자 로컬 설정에서 주입:

- 경로: `~/.claude/ops-agent/confidential-keywords.local.json`
- 형식:
  ```json
  {
    "keywords": ["항상 막을 키워드"],
    "patterns": ["^항상막을식별자\\d+$"],
    "externalOnly": {
      "keywords": ["공개 표면에서만 막을 사내 용어"],
      "patterns": []
    },
    "personalDevOnly": {
      "keywords": ["사내 표면에서만 막을 개인 환경 용어"],
      "patterns": []
    },
    "internalHosts": ["사내.호스트"],
    "allowPaths": ["^docs/guard-rules\\."]
  }
  ```
- `externalOnly` 와 `personalDevOnly` 는 방향만 반대이고 강도는 같다

#### 키워드 항목 옵션

키워드는 문자열 또는 객체로 쓴다. 객체 형태에서 매칭 방식을 지정한다.

```json
"keywords": [
  "긴키워드는그대로",
  { "value": "abc", "wordBoundary": true },
  { "value": "AppFoo", "ignoreCase": true }
]
```

| 옵션 | 기본값 | 효과 |
|------|--------|------|
| `wordBoundary` | ASCII 3글자 이하면 on, 그 외 off | 다른 식별자 안에 묻힌 등장을 히트로 세지 않는다 |
| `ignoreCase` | off | 표기형을 무시하고 매칭한다 |

`wordBoundary` 를 짧은 키워드에 기본 적용하는 이유는 오탐이 무동작으로 이어지기 때문이다. 실측에서 3글자 키워드 하나가 19건 중 12건이 다른 식별자 안에 묻힌 형태였다. 무관한 파일이 걸려 정상 작업이 막히는 경험이 쌓이면 가드를 끄게 된다.

`ignoreCase` 는 표기형 중복 등록을 없앤다. 표기형마다 항목을 넣는 방식은 세 번째 표기형이 생기면 검출되지 않는다.

#### 경계 문자에 한글을 넣지 않는다

경계 문자 집합은 `[0-9A-Za-z_]` 다. 한글은 **넣지 않는다.**

한글을 경계 문자로 넣으면 조사가 붙은 정상 등장이 "묻힌 것" 으로 분류된다. 한국어는 조사가 명사에 직접 붙으므로 `Foo를`, `Foo에서` 같은 형태가 전부 통과하게 된다. 그건 오탐이 아니라 **미탐**이다.

오탐은 작업을 막고, 미탐은 대외비를 내보낸다. 두 오류의 비용이 다르므로 경계 판정은 차단 쪽으로 닫는다.

**그래서 한글만으로 된 키워드에는 경계 옵션이 무력하다.** 앞뒤가 늘 비경계 문자라 항상 독립 등장으로 잡힌다. 한글 일반명사가 목록에 있으면 옵션으로 줄일 수 없고, 목록에서 빼야 한다. 전수 스캔이 그런 항목을 `경계 분류 불가 (비 ASCII 키워드)` 로 표시한다.
- Git 무시 대상: 로컬 전용, 공개 레포에 올라가지 않음
- 예시 템플릿은 `templates/confidential-keywords.example.json` 참고

**설정만 있고 집행이 없으면 무의미하다.** `personalDevOnly` 는 규칙이 정의된 뒤에도 이 훅이 읽지 않아 사내 호스트의 커밋·이슈·PR 에서 검사되지 않던 기간이 있었다. 규칙 묶음을 추가할 때는 그것을 읽는 코드 경로가 있는지 확인한다.

### 3. 레포별 CLAUDE.md

레포별 고유 용어는 해당 레포의 `CLAUDE.md`에 "대외비 키워드" 섹션으로 명시. AI가 작업 시 반드시 참조.

## 검증 절차

1. **수집**: 공개 표면 대상 텍스트 전체 (제목/본문/코멘트 모두)
2. **스캔**: 로컬 키워드 리스트 + 기본 패턴으로 매칭
3. **히트 처리**:
   - 히트 없음 → 통과
   - 히트 있음 → **하드 차단**: 히트 위치·원문 사용자에게 표시, 정정 요청
4. **재검증**: 정정 후 1~3 반복

## 드라이런 모드

환경변수 `OPS_AGENT_CONFIDENTIAL_DRYRUN=1` 설정 시 차단 대신 경고만 출력. 키워드 리스트 배포 전 검증, 오탐 확인용.

## 우선순위

이 가드는 `/flow`의 모든 GATE보다 앞선다 (GATE 0). 플랜 승인·커밋 승인 전에 대외비 검증이 선행된다.

## 훅 통합

`scripts/pre-tool-use.mjs`가 Bash 도구 호출을 인터셉트하여 위 적용 대상 명령의 본문과 커밋 대상 diff 를 스캔한다. 히트 시 `permissionDecision: deny`로 차단.

훅 내부 오류로 판정하지 못하면 통과시키되 그 사실을 알린다. 조용히 통과하면 검사된 것으로 오인된다.

가이드 단계(이슈/커밋/PR)에서의 "검증" 항목은 훅이 실패했을 때의 백업이자, 텍스트 생성 단계에서부터 키워드를 피하도록 유도하는 역할이다.

## 실패 사례 (참고)

초기 버전에서는 `issue.md`에 검증 단계가 누락되어, 사용자 입력의 내부 용어가 공개 이슈 본문으로 유입되는 장애가 발생. 4층 방어선(가이드 + 참조 문서 + 훅 + 로컬 키워드)으로 재발 방지 구조 확립.
