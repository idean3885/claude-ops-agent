# CLAUDE.md

AI 기반 프로젝트 협업 가이드 (범용 템플릿)

> 이 파일은 ops-agent 를 도입하는 레포에 복사해 쓰는 골격입니다.
> 레포 고유 규칙은 하단 「이 프로젝트」 섹션에 채웁니다.

## 작업 방식

**AI-Native Development (Spec-Driven Workflow)**

```
spec(Markdown) → implement(AI) → review → commit → PR → merge
```

마크다운 명세를 기반으로 AI 에이전트가 구현하며, 커밋·푸시는 사용자 검토 후에 수행합니다.

## Git Flow

브랜치 전략과 작업 플로우 상세는 스킬 진입 시 안내됩니다.

> 브랜치명은 provider 정의에 따른 패턴을 사용합니다. 기본값 `{타입}/{이슈번호}`.
> 이슈 내용은 바뀔 수 있으므로 브랜치명에 설명을 붙이지 않습니다.

### 커밋 전 확인

- [ ] 변경 파일 목록 확인
- [ ] 커밋 메시지 사용자 승인
- [ ] 브랜치 확인

## 이슈 플로우

```
Issue → Spec → Implement → Commit → PR
```

이슈 하나의 생애주기를 관리하는 플로우입니다. 자연어로 수정 요청을 받으면 `/flow` 가 전체 플로우를 안내합니다.

### 스킬 목록

| 스킬 | 역할 | 트리거 |
|------|------|--------|
| `/flow` | 이슈 플로우 단일 진입점 (issue → spec → 구현 → commit → pr) | "flow", "플로우", 자연어 수정 요청 |
| `/org-flow` | 멀티레포 오케스트레이션 | "org-flow", "멀티레포" |
| `/setup` | provider 등록, 상태 확인, overlay 설정 | "setup", "설정" |
| `/write` | 글 작성·수정 (계획 → 초고 → 퇴고) | "글 작성", "계획", "초고", "퇴고" |
| `/lint` | 교정 (AI 티·가독성·톤·구두점) | "교정", "검증", "가독성 검사" |
| `/publish` | 블로그 발행 (Jekyll 변환) | "블로그 발행", "publish" |
| `/expert` | 분야 전문가와 토론 (의견 → 반박 → 합의) | "전문가", "기획 검토", "설계 검토" |

issue · spec · commit · pr 은 별도 스킬이 아니라 `/flow` 내부의 단계 가이드입니다. 단계 진입 시에만 로딩됩니다.

## 핵심 규칙

1. **명세 우선**: 코드 작성 전 명세 문서 먼저
2. **사용자 승인**: 커밋·푸시는 사용자 요청 시에만
3. **동기화 유지**: 문서와 코드는 항상 일치

## 검증

새로운 기준이나 규칙을 정할 때, 아키텍처를 결정할 때는 해당 분야 전문가를 불러 토론합니다. 전문가가 의견을 내고 개발자가 반박하며, 결론은 개발자가 냅니다.

일반 구현·문서 작업에는 별도 검증 단계를 두지 않습니다.
