# ADR-0009: 표 열 규칙은 외부 근거가 말하는 범위까지만 둔다

- 상태: accepted
- 일시: 2026-08-27
- 관련: 이슈 #347, ADR-0001(AI 티 제거 우선순위와 저자 취향 경계)

## 배경

`readability.md` 의 L3~L5 는 표의 용도·열 수·비교 결론을 다루고 열 자체의 설계는 다루지 않았다. 그래서 두 형태가 반복됐다.

| 형태 | 결과 |
|------|------|
| 행마다 적용 범위가 다른데 그것을 밝히는 열이 없다 | 일부 행에만 해당하는 규칙이 전역 규칙으로 읽힌다 |
| 무엇이든 들어갈 수 있는 열 이름을 쓴다 | 열이 담는 값을 읽는 쪽이 추측한다 |

이슈 #347 이 함께 지적한 것이 근거의 부재다. `ai-tells.md` 가 가리키는 정량·학술 자료는 문장 레벨만 다루고 표 레벨 자료가 없어, 판정이 작성자 감각에 남았다.

## 조사

넷을 열어 확인했다. 확인한 내용과 확인일은 `references/upstream.md` 「표준·문헌 근거」에 행으로 적었다.

| 출처 | 표 열에 대해 말하는 것 |
|------|----------------------|
| Microsoft Writing Style Guide, Tables | 행 식별 정보는 맨 왼쪽 열. 열 이름을 정확하게(「Name」 금지, 「Group」·「Employee」). 한 열 안의 항목을 평행하게. 열 이름과 셀을 이어 문장이 되게 하지 않는다. 빈 칸·대시 대신 「Not applicable」 |
| Google 기술 문서 가이드, Lists and tables | 각 열에 뜻이 있는 이름. 평행은 열 **안에서**. 셀이 두 문장을 넘으면 다른 형식을 본다 |
| Chicago Manual of Style 17th ed. 3장 | 맨 왼쪽 열(stub)이 행을 식별한다. stub 항목이 같은 종류면 stub 열에 이름을 붙인다 |
| The Open Group Technical Publications Style Guide | 표 본문에 평행 구성 |

## 결정

### 1. L8 을 신설하고 판정을 여섯으로 둔다

열 이름의 구체성 · 행 식별 열의 위치 · 적용 범위 · 열 안의 형태 통일 · 열 이름과 셀의 관계 · 셀 분량. 각 판정 옆에 근거 출처를 함께 적는다.

### 2. 「열 이름 명사형 고정」은 채택하지 않는다

이슈가 제안한 형태다. **조사한 넷 어디에도 명사형 요구가 없다.** Microsoft·Google 이 요구하는 것은 「정확·구체」이고, 평행 요구는 열 이름이 아니라 열 **안의 셀**에 걸린다.

구어형 열 이름(`무엇을 보나`)을 걷는 판정 자체는 유지한다. 다만 근거를 헤딩 규칙 H4 의 확장에 두고 L8 에는 싣지 않는다. 없는 근거를 만들어 붙이면 다음에 이 규칙을 다시 볼 때 무엇이 확인된 것인지 판별할 수 없다.

### 3. 「적용 범위를 열로 올린다」는 자체 판단임을 밝힌다

외부 근거가 말하는 것은 해당 없는 칸을 비우지 말라는 것까지다. 범위가 다른 행이 섞였을 때 열을 올릴지 표를 나눌지는 우리가 정했다. 표를 나누면 같은 대상을 두 자리에서 고치게 되므로 열을 택했다.

### 4. 「설명」은 제네릭 열 이름으로 보지 않는다

Microsoft 자신의 예시 표가 `Function | Description` 이다. 제네릭으로 판정하는 것은 항목·이름·내용·값·기타·정보·구분이다.

## 기각한 대안

| 대안 | 기각 이유 |
|------|-----------|
| 이슈 제안대로 명사형을 고정한다 | 근거가 없다. 자체 판단을 외부 근거인 것처럼 두면 재검토가 불가능해진다 |
| 근거가 부족하니 규칙을 두지 않는다 | 넷 중 다섯 판정은 근거가 확인됐다. 하나가 확인되지 않았다고 나머지를 버릴 이유가 없다 |
| 표 레벨 근거를 별도 파일로 만든다 | `upstream.md` 의 「표준·문헌 근거」가 이미 그 자리다. 파일이 늘면 대조 절차도 늘어난다 |
