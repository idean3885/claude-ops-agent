# ADR-0037: 레슨런은 작업 시간 밖에서 판정하고 정답률로 효과를 잰다

- 상태: accepted
- 일시: 2026-11-13
- 관련: #986, #991(실행 경로 실측), #992(구현, #986 으로 합침), #775(닫음, 이 결정이 이어받음), ADR-0022(무엇을 남기는가), ADR-0023(관찰), #516(정규식 교정 판별 제거)

## 배경

| 사실 | 출처 |
|------|------|
| 레슨런 판정은 사람이 세션을 마칠 때 불러야 실행된다. 부르지 않은 세션은 통째로 빠진다. | skills/learn |
| 레슨런의 효과(실수 감소)를 잰 기록이 없다. 지표 다섯 칸이 모두 미측정이다. | lessons.md 「지표」 |
| 확인되는 효과는 운영 비용(쌓인 후보 675건 정리, 매 세션 로드량 감소)뿐이다. | lessons.md 「정규식으로 교정을 판별하지 않는다」, ADR-0022 |
| ADR-0022 의 근거 「재발 62회」는 남은 기록에서 재현되지 않고(50건), 분모와 기준선이 없다. | ADR-0022 근거 재정립, #986 조사 기록 |
| 사용자 발화를 정규식으로 보고 교정을 잡는 방식은 실패했다 (가장 좁힌 패턴이 6건 중 1건). | #516, lessons.md |
| 규칙 · 스킬 · ADR 을 쌓아도 세션이 그것을 건너뛰고 답하는 일이 잦은데, 그 횟수를 세지 않는다. | 사용자 교정 (2026-11-13). |

목적은 일을 잘하는 것이다. 히스토리를 자산화해 같은 상황에서 흔들리지 않는다. 측정과 레슨런은 수단이고, 수단이 목적의 시간(본 작업 시간 · 사람의 주의)을 쓰면 기각한다 (작업 원칙 「위계」).

## 결정

1. **교정 추리기는 작업 시간 밖에서 한다.** 세션이 시작될 때 기계가 마지막 판정 뒤에 생긴 트랜스크립트를 분리 프로세스로 넘기고 바로 비킨다. 작업을 막지 않고 화면에 띄우지 않는다. 재귀를 막는 가드를 두고, 판정용 자식 세션의 기록은 판정하지 않는다. 설치 시점 이전 세션은 판정하지 않고 하루 판정 건수와 입력 길이에 상한을 둔다. 자산 대조와 등재는 사람이 승인 묶음을 열 때 한다.
2. **사람은 챙기지 않고 승인만 한다.** 주 1회 기한이 지나 판정안이 쌓였을 때만 한 줄로 알린다. 기한은 마지막 승인부터, 첫 승인 전에는 설치 시점부터 센다. 한 번에 올리는 건수에 상한을 둔다. 자동 등재는 없다.
3. **효과는 정답률로 잰다.** 정답률은 사용자가 바로잡지 않은 답의 비율이다. 분모는 기계가 세고 분자는 에이전트가 트랜스크립트로 판정한다. 틀린 답의 원인은 내용 · 수준 둘이다. 새 용어는 두지 않는다.
4. **사람 표본으로 지표를 보정한다.** 바로잡힘이 판정되지 않은 답 중심으로 주 5건 안팎, 50건이 쌓일 때까지 값은 대리 지표다. 기계 집계값과 표본 추정값은 섞지 않는다. 일치도 기준은 80% 다.
5. **대책은 원인 하나에 하나, 기준선과 비교한다.** 기준선은 지난 2주 세션 기록에서 표본(20세션 안팎)을 한 번 판정해 만든다. 기준선 행이 쌓이면 다시 만들지 않고, 판정이 모두 실패했으면 다시 만들 수 있다. 기준선을 쌓으려고 변경 머지를 미루면 이슈가 레거시가 된다. 시범 적용의 손 기록은 이 비교로 옮긴다.
6. **무시를 센다.** 막을 수 있던 자산이 있었는데 틀린 답은 따로 센다. 같은 자산에서 2회 쌓이면 그 자산에 도구 경계 로드를 주는 구조 수정안이 승인 묶음에 올라온다.

## 기각한 대안

| 대안 | 기각 이유 |
|------|-----------|
| 세션을 마칠 때 사람이 부른다 (지금). | 부르지 않으면 그 세션이 빠진다. 사람이 기억해야 한다. |
| 다음 세션 시작 때 판정 결과를 띄운다. | 작업하려고 연 세션의 시작을 판정 · 보고가 잡아먹는다. 수단이 목적의 시간을 쓰는 주객전도다. |
| 사용자 입력을 훅이 정규식으로 보고 교정을 센다. | #516 에서 실패했다. 교정은 직전 답과의 관계로 정의되는데 훅은 발화만 본다. 검출률이 말투를 따라 흔들린다. |
| 세션 종료 훅을 기둥으로 쓴다. | 예산이 1.5 \~ 60초이고, 비정상 종료에서 실행되는지 문서에 없다. 세션 시작 훅이 지난 트랜스크립트를 훑으면 비정상 종료 세션도 잡힌다. |
| 운영체제 스케줄러로 주기 판정한다. | 설치 단계가 하나 늘어 「설치만 하면 알아서」가 약해진다. |
| 판단 계열 실수를 규칙 문장으로 올린다. | 문장으로 남긴 판단 자산은 가진 채로 재발했다. 그 순간 바로잡는 장치로 막는다. |

## 관찰 (ADR-0023)

#991 에서 실측했다 (macOS, 헤드리스).

- 세션 시작 훅이 띄운 분리 프로세스는 세션이 끝난 뒤에도 살아남아 끝까지 실행됐다.
- 재귀 가드가 작동했다.
- 답 210개 세션 하나를 판정하는 데 10초, 입력 약 11만 토큰이 들었다(API 환산 0.41 달러).
- 대화형 세션의 생존과 판정 정확도는 설치 뒤 관찰한다.

## 결과

- 레슨런 · 규칙 · 시범 적용의 효과를 같은 자(정답률)로 말한다. 운영 비용 효과와 실수 감소 효과는 나눠 보고한다.
- 포기하는 것: 완전 무인 자가발전, 판정 결과의 즉시성(최대 1주 늦음), 표본 50건 전까지의 수치 신뢰.

## 다시 판정할 조건

- 사람 표본 50건에서 일치도가 80% 밑이면 기계 판정 지표를 버리고 사람 표본 판정 주기 점검으로 바꾼다.
- 판정 비용이 사용자 사용 한도에서 무시할 수 없는 몫이 되면 판정 입력을 줄이거나 주기를 늘린다.
- 정답률 기준선이 나온 뒤 판단 실수가 줄지 않으면 ADR-0022 의 「판단은 남기지 않는다」를 다시 판정한다.
