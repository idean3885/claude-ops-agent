# ADR-0019: 역할은 RACI 의 A · C · R 세 칸을 따르고, 위탁 작성은 실무자가 한다

- 상태: accepted
- 일시: 2026-10-01
- 관련: 이슈 #587

## 배경

레포에는 사용자 · 전문가(`experts/*.md`) · 실행 에이전트(`agents/infra-lab-operator.md`) 가 이미 있었지만 역할 정의가 레포 수준에 없었다. 그래서 「전문가」가 두 뜻으로 쓰였다.

| 쓰임 | 하는 일 | 최종 주체 |
|------|---------|-----------|
| 의견을 내는 전문가 | 판정 기준으로 입장을 내고 반박받는다 | 사용자 |
| 작성을 위탁받는 「글쓰기 전문가」 | 초고 · 퇴고를 대신 쓴다 | 위탁받은 쪽 |

둘째는 판단이 아니라 위탁이다. 같은 이름으로 두면 전문가가 자기 의견대로 산출물까지 만들고, 그 산출물을 다시 자기 기준으로 승인하는 고리가 생긴다.

README 의 전문가 표도 명부(`skills/expert/SKILL.md`)와 따로 관리돼 DBA 가 빠져 있었다.

## 결정

### 1. 역할은 책임 할당 매트릭스(RACI)의 세 칸에 대응시킨다

| RACI | 원 정의 | 이 레포 | 이름 |
|------|---------|---------|------|
| Accountable | 최종 책임. 작업마다 한 명 | 사용자 | 결정자 |
| Consulted | 양방향으로 의견을 주고받는 상대 | `experts/*.md` | 전문가 |
| Responsible | 실제로 일을 하는 주체 | `agents/*-operator.md` | 실무자 |

이름을 새로 짓지 않고 원 정의에 기댄다. 경계를 다툴 때 바깥 기준으로 돌아갈 수 있다.

### 2. 위탁 작성은 실무자가 한다

`agents/writing-operator.md` 를 둔다. 형식은 `infra-lab-operator` 를 따른다. 계획 게이트와 최종 확인은 결정자, 초고 · 퇴고는 실무자, 교정은 `lint` 다.

### 3. README 는 명부를 복제하지 않는다

전문가 표를 지우고 명부로 링크한다. 명부가 두 곳이면 한쪽이 낡는다.

## 기각한 대안

| 대안 | 기각 이유 |
|------|-----------|
| 글쓰기 전문가 신설 | 전문가는 의견을 내는 역할이다. 작성까지 맡기면 의견과 위탁이 다시 섞인다 |
| RACI 밖의 새 개념 신설 | 이미 쓰는 구조(전문가 · 실행 에이전트)를 이름만 바꿔 늘린다. 바깥 기준이 없어 경계를 다툴 근거가 없다 |
| `write` 스킬 개편만 | 스킬은 절차다. 누가 그 절차를 맡는지(위탁의 주체)는 스킬로 표현되지 않는다 |

## 검토: 알림(Informed) 칸

후보는 훅의 위반 위치 통지와 `lint` 였다. 검토 결과 지금은 대응시키지 않는다.

| 관점 | 판단 |
|------|------|
| 방향 | RACI 의 I 는 진행을 단방향으로 알려 받는 사람이다. 훅 통지는 실무자(어시스턴트)에게 가는 신호라 받는 쪽이 다르다 |
| 성질 | `lint` 는 교정 단계의 규칙 대조다. 알림이 아니라 검사다 |

알려 받는 사람이 실제로 생길 때(팀 공유 등) 다시 본다. 그 전에는 README 에 넣지 않는다.

## 결과

- README 에 역할 표(A · C · R)를 두고 전문가 표를 명부 링크로 대체한다
- README 「글」 절에 단계별 주체를 적는다
- 새 실무자는 `agents/<분야>-operator.md` 로 두고 「한다 · 하지 않는다」 표를 갖는다
