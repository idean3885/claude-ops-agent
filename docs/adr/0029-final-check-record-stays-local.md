# ADR-0029: 최종 점검 기록의 원천은 로컬 통과 기록이다

- 상태: proposed
- 일시: 2026-10-15
- 관련: ADR-0028(병합 주체), ADR-0019(역할), ADR-0027(기록 대조), #612 · #655(최종 점검), #634(댓글 노출), #690(통과 기록의 자리)

## 배경

머지 전 최종 점검(#612)의 설계는 결정적 점검 결과와 판단 노트를 **머지할 커밋에 묶인 로컬 통과 기록**에 적는 것이었다. 구현은 설계에 없는 동작을 하나 더 넣었다. 통과하면 판단 노트를 PR 댓글로 올린다.

| 자리 | PR 댓글에 대해 적힌 것 |
|------|------------------------|
| #612 설계 표 | 없음. 판단 결과는 「HEAD SHA 에 묶인 영수증」에 적는다. |
| 구현 PR 본문 | What 에 「통과하면 노트를 PR 댓글로 남긴다」. Why 에 이유 없음. |
| `docs/action-gate.md` | 끄는 옵션(`--no-comment`)의 용도만. 올리는 이유 없음. |
| #634 | 「팀 레포 PR 에 개인 도구의 점검 기록이 노출된다」. 끄는 설정을 요구. |
| #690 · 아키텍트 검토 | 댓글을 전제로 유형별 기본값(「업무만 끌지 사상까지 끌지」)을 쟁점으로 냄. |

결정 없는 동작이 결정처럼 굳어 그 범위를 논하는 데까지 갔다. 「애초에 왜 PR 에 올리는가」를 물은 것은 결정자였고, 답은 「기록된 이유가 없다」였다.

ADR-0028 은 업무 · 사상 유형 레포에서 통과 기록을 「상황 보고의 첨부로 쓴다」고 정했고, 웹 병합 경로에서 점검을 강제할 수단은 숙제로 남겼다.

## 결정

### 1. 최종 점검 기록의 원천은 로컬 통과 기록이다

점검 주체는 결정자의 로컬에서 실행되는 AI 다. 결정적 점검 결과 · 판단 노트 · 머지할 커밋의 해시는 로컬 통과 기록 한 곳에 적는다. 레포 유형과 무관하게 PR 댓글 · 커밋 상태 · 이슈 댓글 같은 공유 표면에는 올리지 않는다.

공유 표면에 올리는 것은 기록이 아니라 게시다. 게시는 읽는 사람이 있어야 이유가 선다. 동료 리뷰어는 개인 도구의 점검 기록을 읽을 이유가 없고(#634), 본인 레포에서는 로컬 기록을 읽는 사람이 본인이라 같은 내용을 두 곳에 둘 이유가 없다.

### 2. 사람에게는 상황 보고로 전달한다

AI 는 상황 보고(ADR-0028 결정 4)에 통과 기록의 경로와 머지할 커밋의 해시를 첨부한다. 업무 · 사상 유형 레포에서는 결정 칸 앞에, 저장소 유형 레포에서는 반영 결과와 함께 둔다. 사람이 기록을 열어 볼지는 사람이 정한다.

### 3. 웹 병합 경로에 추가 강제 장치를 두지 않는다

로컬 경로(`gh pr merge`)는 훅이 통과 기록을 요구한다(#655). 웹 병합은 사람이 보고를 읽고 판단한 뒤 누르는 행위이고, 그 판단 자리가 ADR-0028 결정 2 가 둔 사람의 자리다. 점검 실행 여부는 보고의 첨부로 확인한다.

강제 장치로 검토한 커밋 상태 + 브랜치 보호와 GitHub Action 은 모두 PR 표면에 기록을 올리거나 레포마다 CI 를 요구한다. 결정 1 과 어긋나고, 업무 유형에서는 ops-agent 를 쓰지 않는 동료의 PR 까지 막는다.

## 결과

| 대상 | 바뀌는 것 |
|------|-----------|
| `final-check.sh` | PR 댓글 게시와 `--no-comment` 옵션을 없앤다. 통과 시 기록 경로 · 머지할 커밋 해시를 출력하고, 끝 안내를 레포 유형별로 낸다(업무 · 사상: 웹 병합과 보고 첨부, 저장소: `gh pr merge`). |
| flow · org-flow 가이드 | ADR-0028 결정 3 의 단계(드래프트 · 리뷰 · 머지 전 최종 점검 · 상황 보고 · 판단)를 PR 가이드의 단계 표에 한 벌만 두고, 머지 절은 유형별로 분기한다. |
| 아키텍트 판정 기준 AR7 | 「출처」 기준을 새로 쓰는 문장만이 아니라 검토 대상의 기존 동작에도 댄다. 결정 기록 없는 동작은 매개변수를 논하지 않고 제거가 기본이다. |
| #634 | 댓글 게시가 없어지므로 끄는 설정 요구는 소멸한다. |

대가는 하나다. 점검 기록을 보려면 로컬 파일을 열어야 한다. PR 화면에서는 보이지 않는다.

## 다시 열어야 하는 조건

| 조건 | 다시 볼 것 |
|------|------------|
| 점검 없이 웹 병합된 사례가 발견된다. | 결정 3. 그때도 강제 장치는 기록을 공유 표면에 올리지 않는 형태여야 한다. |
| 로컬 기록을 읽는 사람이 결정자 말고 생긴다. | 결정 1 의 「읽는 사람」 전제 |

## 기각한 대안

| 대안 | 기각 이유 |
|------|-----------|
| PR 댓글 게시 유지 + 유형별 기본값 | 결정 없이 들어온 동작의 범위를 정하는 것이다. 이유가 없는 동작은 범위를 조절하지 않고 없앤다. |
| 커밋 상태 `ops-agent/final-check` + 브랜치 보호 필수 상태 | 업무 유형에서 동료 PR 이 막힌다. 머지 박스에 개인 도구 기록이 뜬다. 사상 유형에만 켜면 유형별 분기가 하나 더 생기고, 강제가 필요하다는 사례가 아직 없다. |
| GitHub Action 으로 통과 기록 검사 | 레포마다 CI 설정이 필요하다. 로컬 통과 기록을 CI 가 읽을 수 없어 기록을 PR 로 올려야 한다. |
