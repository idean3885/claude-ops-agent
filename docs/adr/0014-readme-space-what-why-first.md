# ADR-0014: README 는 무엇과 왜를 담고 어떻게는 접는다

- 상태: accepted
- 일시: 2026-09-05
- 관련: 이슈 #447, [0004](0004-fix-altitude.md)

## 배경

README 에 무엇을 넣고 무엇을 제외할지 판정하는 기준이 없었다. 그래서 사상이 바뀔 때마다 지면 구성을 처음부터 다시 논의했다.

측정한 값이다.

| 대상 | 값 |
|------|-----|
| README 분량 | 119줄 |
| README 변경 | 2026-08-26 ~ 09-03 아흐레 동안 5회 |
| 메이저 | 8개 / 2026-02-11 ~ 08-27 |
| CHANGELOG | 215개 릴리스 항목 |
| ADR | 13건 |

변경 빈도는 문제가 아니다. 아흐레에 다섯 번 고쳤다는 것은 이미 따라가고 있다는 뜻이다. 문제는 매번 무엇을 기준으로 고쳤는지가 남지 않는다는 점이다.

지면 판단을 어렵게 만드는 조건도 확인했다. `8.0.0` 의 사유는 스킬 이름에서 `content-` 접두를 걷은 것이다. 사상이 바뀐 것이 아니라 이름이 바뀌었다. 버전 번호는 사상 변화를 가리키지 못하고, 그래서 README 가 그 역할을 대신 떠맡는다.

## 결정

| 조 | 내용 |
|----|------|
| 1 | README 는 무엇인가와 왜 그렇게 하는가를 담는다 |
| 2 | 어떻게 쓰는가는 본문에 두지 않는다. 접기(`<details>`) 또는 `docs/` 로 보낸다 |
| 3 | 판정 질문은 하나다. 처음 보는 사람이 1분 안에 「내가 원하는 것이 여기 있는가」에 답할 수 있는가 |
| 4 | 기준이 바뀌면 README 를 먼저 고치지 않고 이 ADR 을 근거로 재논의한다 |

### 1조. 무엇과 왜만 지면을 쓴다

읽는 쪽의 시간이 가장 희소한 자원이다. 플러그인은 계속 늘어나고, 읽는 사람은 자기가 찾는 것이 여기 있는지만 판정한다. 그 판정에 필요한 것은 무엇을 하는 도구인지와 왜 그렇게 만들었는지 둘이다.

「왜」를 지면에 두는 이유는 이 레포가 규칙을 배포하기 때문이다. 규칙은 근거 없이는 채택되지 않는다.

### 2조. 어떻게는 같은 페이지에 접어 둔다

스킬 이름 목록, 명령, 절차는 어떻게 쓰는가에 해당한다. 이것을 본문에 두면 지면을 쓰면서 판정에는 기여하지 않는다.

접기와 `docs/` 를 나누는 기준은 그 자리에서 필요한가다. 설치처럼 바로 이어지는 것은 접기, 근거 표처럼 시험받는 자리에서만 필요한 것도 접기, 항목이 늘어나 계속 갱신되는 목록은 `docs/` 로 보낸다.

### 3조. 1분이 판정 단위다

「빠짐없이 적었는가」로 판정하면 지면이 계속 늘어난다. 「1분 안에 답이 나오는가」로 판정하면 늘릴 때마다 무엇을 제외할지 함께 정하게 된다.

### 4조. 기준이 먼저다

README 문장을 먼저 고치면 그 판단이 어디에도 남지 않는다. ADR 0004 의 층 판정과 같은 방향이다. 지면 구성은 사상·규약 층에서 정하고 README 는 그 결과를 반영한다.

## 적용

| 자리 | 처리 |
|------|------|
| `## 규칙의 근거` 의 차용 원천 표와 문헌 목록 | 접기. 시험받는 자리에서만 필요하다 |
| 스킬·스크립트 목록 | `docs/usage.md` 유지. README 로 올리지 않는다 |
| 사상 절 | 지면에 유지 |

## 남는 것

깊이를 보는 독자에게는 이 기준이 손해다. 그 독자는 `docs/adr/` 과 `docs/` 로 간다. 두 독자를 한 지면에서 동시에 만족시키려다 둘 다 놓치는 쪽을 피한다.
