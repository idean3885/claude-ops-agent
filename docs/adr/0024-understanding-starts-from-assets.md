# ADR-0024: 외부 시스템 파악은 자산에서 시작하고 파악한 결과는 그 세션에서 자산이 된다

- 상태: accepted
- 일시: 2026-10-13
- 관련: 이슈 #661, ADR-0004(고칠 층), ADR-0014(README 지면), ADR-0022(레슨런 등재 조건)

## 배경

외부 시스템을 파악해 얻은 것이 다음 파악에 쓰이지 않았다. 같은 모양의 실패가 두 번 났다.

| 사례 | 무엇이 빠졌나 | 어떻게 드러났나 |
|------|---------------|-----------------|
| 외부 저장소 조회에 자격부터 찾았다. 같은 계정 · 같은 오류로 막힌 기록이 참조 버킷에 있었다. | 접근하기 전에 참조 자산을 찾는 단계가 없었다. | 같은 401 을 처음 보는 것처럼 진단했다. 쓰이지 않는 키 이름을 안내해 원격 기록까지 오염됐다. |
| 외부 시스템 연동 구조를 파악하기 전에 「전에 정리해 둔 것이 있다」고 봤다. 찾아보니 없었다. | 파악을 마친 세션이 결과를 등재하는 단계가 없었다. 지난 파악은 대화에만 남았다. | 31페이지 문서 트리를 처음부터 다시 받아 읽었다. |

레슨런 자산화([`docs/lessons.md`](../lessons.md))는 교정에서 사실 · 절차 · 취향을 골라 `areas` 에 등재한다. 작업 시작에 인덱스를 올리고 판단 지점에서 대조한다. 이슈 완료 단계는 「조사로 확정한 참조 사실」도 함께 모은다.

그런데 PARA 스켈레톤의 `resources` 는 「찾아봐야 아는 참고」라고만 적혀 있었다. 무엇을 두고 언제 찾는지가 없었다. 접근하기 전에 찾는 규칙은 소비 레포의 작업 규칙에만 있었다. 조직 식별자가 없는 절차가 공통 계층에 없었으니, 규칙이 안 읽힌 것이 아니라 규칙이 없었다.

## 결정

### 1. 자산은 둘이고 읽히는 방식이 다르다

| 자산 | 버킷 | 무엇인가 | 어떻게 읽히나 |
|------|------|---------|---------------|
| 레슨런 | `areas` | 없으면 같은 실수를 다시 하는 것. 사실 · 절차 · 취향 (ADR-0022) | 작업 시작에 인덱스가 올라가고 판단 지점에서 걸린다. |
| 참조 자산 | `resources` | 없으면 같은 문서를 다시 찾아 읽어야 하는 것. 외부 시스템의 구조와 역할, 문서 트리의 위치, 받아야 하는 것과 창구, 실측한 함정 | 주제(환경 · 상품 · 시스템 이름)로 찾아서 읽는다. 상주하지 않는다. |

나누는 질문은 하나다. **없으면 실수가 되풀이되는가, 같은 문서를 다시 찾아 읽게 되는가.** 참조 자산은 재발하지 않고 낡으므로 확인 날짜와 확인 방법을 갖는다.

### 2. 파악은 자산에서 시작한다

외부 시스템에 접근하거나 문서를 읽기 전에 `resources` 를 대상 이름으로 먼저 찾는다. 환경 이름과 시스템 이름을 각각 검색어로 쓴다. 「자산이 없다」는 시도한 검색어를 적은 뒤에만 말한다.

검출 가능한 형태는 보고의 한 줄이다. `참조 자산: N건 (검색어 …)`. 이 줄이 없는 외부 접근은 자산을 보지 않은 것이다.

### 3. 파악한 결과는 그 세션에서 자산이 된다

파악을 마친 세션이 등재한다. 이슈 완료까지 미루지 않는다. 완료에 도달하지 못한 작업은 통째로 빠진다. 다음 세션은 요약을 넘겨받지 않고 다시 분석하므로, 대화에만 남은 파악은 없는 것과 같다.

등재 단위는 「다시 파악하면 같은 답이 나오고 파악에 비용이 든 것」이다. 결론 한 줄, 구조, 받아야 하는 것과 창구, 원천 문서의 위치를 담는다. 원천 본문은 옮겨 적지 않는다. 옮겨 적은 값은 상대가 고치면 그날부터 거짓이다.

### 4. 보완은 갱신이다

같은 대상의 파일이 있으면 그 파일을 고치고 확인 날짜를 올린다. 새 파일을 만들지 않는다. 파일이 늘면 검색이 둘로 나뉘고 어느 쪽이 최신인지를 사람이 들고 있어야 한다.

### 5. 호출은 자연어다

쌓기와 꺼내기는 되돌릴 수 있는 행위라 자연어 트리거로 들어간다. 공식 문서도 같은 경로를 기본으로 둔다 ([Skills](https://code.claude.com/docs/en/skills)). 「Claude uses skills when relevant, or you can invoke one directly with `/skill-name`」, 「Custom commands have been merged into skills」 두 문장이 그것이다. `/name` 전용(`disable-model-invocation`)은 커밋 · 배포처럼 시점을 사람이 정해야 하는 부수효과에 둔다. 어떤 말로 들어가는지는 `docs/usage.md` 가 예시로 적는다.

## 자리

| 층 | 자리 | 담는 것 |
|----|------|---------|
| 사상 | 이 ADR, README | 두 자산의 경계, 시작과 등재 시점 |
| 방법 | [`templates/para/README.md`](../../templates/para/README.md) | `resources` 등재 기준 · 시점 · 회수 · 보완 |
| 집행 | [`skills/flow/guides/issue.md`](../../skills/flow/guides/issue.md) | 시작 시 참조 자산 검색 한 줄, 완료 시 등재 확인 한 줄 |
| 호출 | [`docs/usage.md`](../usage.md) | 프롬프트 예시 |

실제 자산 · 버킷 경로 · 트리거 문장은 소비 레포가 갖는다.

## 기각한 대안

| 안 | 기각 이유 |
|----|-----------|
| 참조 사실을 전부 레슨런으로 등재한다. | 인덱스는 매 세션 상주한다. 문서 트리 맵 같은 자산이 들어오면 상주 비용이 된다. 판단 지점에서 걸리지도 않는다. |
| 이슈 완료 단계에서만 등재한다. | 완료 전에 세션이 끝난 파악이 빠진다. 두 번째 사례가 그것이다. |
| 참조 자산 전용 스킬을 만든다. | 스킬이 하나 늘고 트리거가 flow 와 겹친다. flow 가이드 한 줄과 PARA 절로 된다. 더 작은 층이 먼저다. |
| 소비 레포 작업 규칙으로 둔다. | 식별자가 없는 절차다. 다른 소비 환경이 같은 절차를 다시 만든다 (ADR-0004). |

## 롤백 조건

시작 전 검색이 매번 0건으로 끝나는 사례가 쌓이면 2항의 검색 단계를 빼고 3항의 등재만 남긴다.
