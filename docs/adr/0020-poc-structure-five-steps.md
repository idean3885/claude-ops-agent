# ADR-0020: PoC 문서 구조는 다섯 단계이고 정본은 poc.md 하나다

- 상태: accepted
- 일시: 2026-10-01
- 관련: 이슈 #585, ADR-0019(역할)

## 배경

PoC 문서 구조를 세 곳이 서로 다르게 정의했다.

| 위치 | 구조 |
|------|------|
| `extensions/poc.md` | TL;DR → 배경 → 환경 → 대안 → 검증 → 결론 |
| `skills/write` 유형 표 | TL;DR → 배경 → 환경 → 검증 → 결론 |
| `skills/infra-lab` 실험 기록 | 가설 → 부하 프로필 → 관측 → 결론 → 다음 실험 |

실제 비교 실험 보고서를 쓰면서 두 빈자리가 드러났다. 무엇과 무엇을 비교하는지(조건), 어떤 시나리오로 어떤 지표를 보는지(절차)가 독립 절로 없어 조건 설명이 결과 아래 줄글로 밀려났다.

## 결정

1. 구조는 목적 → 조건 → 절차 → 결과 → 결론 다섯 단계다. 기존 PC 규칙은 단계에 배치한다
2. 요약(TL;DR)은 독자가 하는 일로 정한다. 검증하는 독자(리뷰)에게는 두지 않고, 가져가는 독자(공유)에게는 목적 앞에 둔다
3. 정본은 `poc.md` 다. `write` 는 링크하고, `infra-lab` 은 칸마다 대응 단계를 적는다

## 기각한 대안

| 대안 | 기각 이유 |
|------|-----------|
| 문서 구조 전문가에게 맡긴다 | 전문가는 입장을 내는 역할이다(ADR-0019). 구조는 반복해 적용할 규칙이고, 작성은 이미 `write` 가 유형 규칙으로 맡는다 |
| 요약을 PoC 에 항상 필수로 둔다 | 리뷰 문서에서 결론을 먼저 주면 근거를 읽지 않고 결론만 다루게 된다 |
| 요약을 PoC 에서 없앤다 | 결정 뒤 공유 · 상위 보고 독자는 결론을 가져가러 온다 |
