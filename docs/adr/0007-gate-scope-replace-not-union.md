# ADR-0007: 게이트 개방은 대체로 두고 합치는 일은 차단 메시지가 한다

- 상태: accepted
- 일시: 2026-08-27
- 관련: 이슈 #353, `docs/action-gate.md` 액션 게이트 절

## 배경

액션 게이트는 시간뿐 아니라 행위 갈래로도 열린다. `action-gate-allow.sh on <scopes>` 가 마커를 새로 쓰고, 마커에 담긴 갈래만 통과한다.

한 작업에서 두 갈래가 순차로 필요하면 이 순서가 나온다.

| 단계 | 마커 | 결과 |
|------|------|------|
| 갈래 A 개방 | `[A]` | |
| 갈래 B 개방 | `[B]` | A 가 사라짐 |
| A 가 필요한 명령 | | 차단. A 를 다시 요청 |
| A 개방 | `[A]` | B 가 사라짐 |
| B 가 필요한 명령 | | 차단 |

스크립트는 `on a,b` 로 여러 갈래를 한 번에 받는다. 그런데 **차단 메시지가 그 사실을 말하지 않고 항상 걸린 갈래 하나만 제시했다.** 실제 세션에서 같은 종류의 요청이 사람에게 네 번 갔고 그중 둘은 앞서 연 것이 지워져서 생긴 것이었다.

## 결정

### 1. `on` 은 대체로 유지한다

합집합으로 열지 않는다. **합치면 TTL 도 함께 연장된다.** 갈래 A 를 30분으로 연 뒤 25분째에 B 를 열면, 합집합 방식에서는 A 의 개방 시간이 55분이 된다. 사람이 승인한 것은 30분이었다.

마커는 사람이 마지막으로 승인한 것을 그대로 담는다. 이 성질을 잃으면 마커를 읽어도 무엇이 왜 열려 있는지 말할 수 없다.

### 2. 합치는 일은 차단 메시지가 한다

차단 메시지가 감지된 갈래에 **이미 열려 있는 갈래**를 더해 한 줄로 제시한다. 사용자는 그 한 줄을 실행하고, 두 갈래가 같이 열린다. 왕복이 사라지면서 마커의 성질은 그대로 남는다.

이미 열린 갈래가 없으면 그 안내를 싣지 않는다. 매번 추가되면 메시지가 길어지고 읽히지 않는다.

### 3. 스크립트도 대체 사실을 알린다

살아 있는 마커를 다른 갈래로 덮어쓸 때 이전 갈래를 stderr 로 알린다. 사람이 차단 메시지를 거치지 않고 직접 실행하는 경로가 있어서다. 조용히 대체하면 앞서 연 갈래가 사라진 것을 아무도 모른다.

## 기각한 대안

| 대안 | 기각 이유 |
|------|-----------|
| `on` 을 합집합으로 바꾼다 | TTL 이 함께 연장되어 먼저 연 갈래의 개방 시간이 승인 범위를 넘는다 |
| 합집합 + 갈래별 만료 시각 | 마커가 갈래마다 만료를 갖게 되어 「지금 무엇이 열려 있나」를 한눈에 읽을 수 없다. 왕복을 없애는 값에 비해 구조가 무겁다 |
| 메시지에 `on a,b` 형식만 설명한다 | 형식을 알려도 사람이 갈래 이름을 손으로 모아야 한다. 갈래를 사람이 고르지 않는다는 기존 결정과 어긋난다 |
| TTL 을 늘려 왕복을 줄인다 | 개방 시간으로 범위 문제를 덮는다. 갈래를 도입한 이유를 되돌린다 |

## 다시 열어야 하는 조건

| 조건 | 다시 볼 것 |
|------|-----------|
| 세 갈래 이상이 한 작업에 필요한 사례가 반복된다 | 작업 단위로 갈래 묶음을 미리 정의할지 |
| 차단 메시지를 거치지 않는 직접 개방이 흔해진다 | 스크립트가 합집합 여부를 물을지 |
