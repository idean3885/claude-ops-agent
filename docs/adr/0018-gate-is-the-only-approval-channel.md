# ADR-0018: 게이트 대상 행위의 승인 채널은 게이트 하나다

- 상태: accepted
- 일시: 2026-10-01
- 관련: 이슈 #581, ADR-0017(대체됨), #141(게이트 개방 프로토콜)

## 배경

ADR-0017 은 하네스의 오토 모드 분류기를 사용자의 대화 승인 문장으로 통과시키는 경로를 정했다. 행위 · 대상 · 범위를 이름으로 댄 상시 승인이면 분류기가 통과시킨다는 공식 문서 문장에 기댔다.

이 경로는 판정 근거가 문장이다. 문장이 승인으로 읽히는지는 분류기가 해석하고, 해석은 보수적으로 막힐 수 있다. 게이트가 「자연어 승인은 권한을 열지 않는다」를 원칙으로 둔 이유와 같은 문제가 다른 판정자 쪽에서 다시 생긴다.

사용자 결정은 이렇다. 승인은 항상 게이트로만 받고 나머지는 자율 진행한다. 자율 진행에 하네스의 bash 승인이 필요하면 사용자 환경의 허용 규칙으로 연다. 판정은 게이트가 한다.

## 결정

### 1. 승인 채널은 게이트 하나다

어시스턴트는 게이트 대상 행위의 승인을 게이트 개방으로만 받는다. 대화 속 승인 문장을 요청하지 않는다.

### 2. 하네스 허용 규칙은 사용자 환경의 전제 조건이다

게이트 대상 명령이 Claude Code 허용 규칙에 맞으면 분류기를 거치지 않고, PreToolUse 훅인 게이트만 판정한다. 공식 문서 [Permission modes](https://code.claude.com/docs/en/permission-modes) 의 평가 순서다.

> Each action goes through a fixed decision order. The first matching step wins: 1. Actions matching your allow, ask, or deny rules resolve immediately

묶은 명령은 하위 명령마다 맞아야 한다. 공식 문서 [Configure permissions](https://code.claude.com/docs/en/permissions) 「Compound commands」.

> A rule must match each subcommand independently.

그래서 머지 앞에 물리는 `scripts/pre-merge-check.sh` 도 규칙에 둔다.

규칙 목록은 게이트 자신의 갈래 표에서 끌어낸다. 분류기가 무엇을 막는지는 옮겨 적지 않는다. 규칙은 사용자가 넣는다. 어시스턴트는 0단계에서 규칙이 있는지 읽고, 없으면 첫 요청에 게이트 개방과 함께 싣는다.

### 3. 운영에 닿는 갈래는 규칙에 두지 않는다

`cluster-write` · `repo-delete` · `git-default-push` 는 허용 규칙 표에서 뺀다. 운영 · 모니터링에 닿는 민감 작업은 사용자가 `!` 로 직접 실행한다는 사용자 규칙과, 기본 브랜치 직접 push 금지 규칙이 이미 있다.

## 기각한 대안

| 대안 | 기각 이유 |
|------|-----------|
| 대화 승인 문장으로 분류기를 통과 (ADR-0017) | 판정 근거가 문장 해석이다. 보수적으로 막히면 자율 진행이 다시 끊긴다 |
| 게이트 대상 행위를 매번 사용자가 `!` 로 직접 실행 | 자율 위임이 성립하지 않는다 |
| 게이트를 없애고 허용 규칙만 둔다 | 허용 규칙은 상시다. 갈래 · 만료로 범위를 좁히는 판정자가 사라진다 |

## 대가

허용 규칙에 맞는 명령은 분류기의 다른 검사도 거치지 않는다. 다른 레포의 PR 머지처럼 분류기가 잡던 범위 이탈을 게이트는 보지 않는다. 게이트는 갈래와 만료만 판정한다.

게이트를 끄는 플래그(`OPS_AGENT_ACTION_GATE_DISABLE=1`)를 켜면 규칙에 든 명령에는 판정자가 없다.

| 공식 문서의 평가 순서가 바뀌어 허용 규칙이 분류기보다 뒤에 온다 | 결정 2 |
