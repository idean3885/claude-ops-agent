# ADR-0036: 기획 최신화는 필요 시점에 그 도메인만 돈다

- 상태: accepted
- 일시: 2026-11-11
- 관련: #942, #641 · #645(증분 확인), #654(구현 판정 전 오버레이 읽기)

## 배경

기획 최신화는 사용자가 부를 때만 돌았다. 그 사이 두 가지가 일어났다.

| 일 | 원인 |
|----|------|
| 화면을 근거로 답해야 하는 자리에서 스냅샷을 보지 않고 「없다」고 하거나 사용자에게 화면을 물었다. | 작업 흐름 안에 기획을 확인하는 자리가 없었다. |
| 같은 기획 파일의 다른 페이지에 있던 관리 화면을 몇 주 동안 놓쳤다. | 오버레이가 적은 페이지 · 프레임만 읽어, 그 밖에 생긴 화면이 드러나지 않았다. |

어디까지 언제 봤는지 기록하는 자리도 없어, 필요한 범위가 스냅샷에 있는지 바로 판정하지 못했다.

## 결정

1. 사용자가 부르지 않아도 두 자리에서 돈다: 기획 오버레이가 있는 프로젝트의 설계 · 구현 착수, 화면 · 요구사항을 근거로 답하기 직전.
2. 범위는 그 자리가 걸리는 도메인의 항목만이다. 같은 세션에서 확인한 도메인은 다시 돌지 않는다.
3. 스냅샷 머리에 진행 인덱스(출처 · 항목 · 도메인 · 상태 · 마지막 확인 · 사유)를 둔다. 필요 시점은 이 표로 범위를 정한다.
4. 필요 시점마다 출처의 항목 목록(페이지 · 최상위 프레임)을 세션에서 출처당 한 번 인덱스와 대조해, 인덱스에 없거나 「미정」인 것을 후보로 보고한다(범위 발견). 추적 중인 도메인이어도 한다. 놓친 화면은 추적 중인 도메인의 다른 페이지에 있었다. 목록만 읽어 비용이 작다. 범위에 넣을지는 결정자가 정한다. 다른 도메인 후보는 「미정」으로 남기고, 「범위 밖」은 결정자가 정한 것만 적는다.
5. 지문 비교는 추출 쪽에서 하고 대화에는 바뀐 항목만 돌려받는다.
6. 오버레이가 없는 프로젝트에서는 돌지 않는다.

## 기각한 대안

| 대안 | 기각 이유 |
|------|-----------|
| 세션 시작 훅이 마지막 확인일을 보고 주기(예: 7일)마다 실행을 주입 | 기획이 필요 없는 세션에도 실행 비용(변경이 없어도 컨텍스트의 몇 %)이 든다. 놓친 원인은 주기가 아니라 필요한 자리에서 보지 않은 것이다. |
| 사용자가 부를 때만 (지금 상태) | 부르지 않으면 이번처럼 놓친다. 비용은 필요 시점 실행과 같다. |
| 필요 시점마다 오버레이 범위 전체 실행 | 걸리지 않는 도메인까지 읽는다. 전체 실행은 사용자가 부를 때만 한다. |

## 다시 열 조건

- 필요 시점 실행이 있었는데도 기획 변경을 놓친 사례가 나온다.
- 필요 시점 실행 비용이 작업 비용보다 커지는 프로젝트가 생긴다(도메인 하나의 항목이 매우 많다).

## 결과

- 기획이 필요 없는 세션의 비용은 0 이다.
- 인덱스에 없는 화면도 범위 발견으로 후보가 된다. 범위 밖으로 둔 항목은 사유와 함께 남아 다시 후보로 나오지 않는다.
