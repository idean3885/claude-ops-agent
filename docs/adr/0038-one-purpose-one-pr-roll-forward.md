# ADR-0038: 목적 하나를 이슈 하나 · PR 하나로 모으고, 실패는 롤포워드로 고친다

- 상태: accepted
- 일시: 2026-11-13
- 관련: #986, ADR-0032(이슈 하나 · PR 하나, 결정 5 와 나누는 기준을 대체), [태스크 관리 전략](../task-management.md)

## 배경

| 사실 | 출처 |
|------|------|
| 한 세션이 목적 하나(옵스가 정답률을 스스로 재고 쌓게 한다)를 위해 이슈 여섯 · PR 넷을 만들었다. 대상은 레포 하나였다. | #986 |
| PR 을 나눈 결과 머지 순서를 사람이 챙겨야 했고, CHANGELOG 같은 줄을 PR 넷이 고쳐 충돌이 예정됐다. | #986 본문 Why, 닫은 PR #993 · #995 · #996 |
| 이슈 가이드에 「발견 시점에 갭 이슈를 따로 올렸어도 진행 지시를 받으면 하나로 모아 진행한다」가 이미 있었는데 따르지 않았다. 기준이 「서로 의존하지 않는」 · 「리뷰 질문이 둘 이상이면 나눈다」라 판단이 갈렸다. | skills/flow/guides/issue.md |
| PR 을 나누는 근거는 이슈 단위 롤백이었다 (ADR-0032 결정 5). | ADR-0032 |

AI 가 코드를 쓰고 고치는 지금은 문제를 다음 커밋으로 고치는 시간이 되돌리고 다시 쌓는 시간보다 짧다.

## 결정

1. **나누는 기준은 목적이다.** 착수 전에 목적을 80자 안 한 줄로 적는다. 그 목적에 드는 변경은 의존 여부 · 리뷰 질문 수 · 레이어와 관계없이 이슈 하나 · PR 하나로 모은다.
2. **실패는 롤포워드로 고친다.** 머지된 변경에 결함이 있으면 되돌리지 않고 다음 커밋으로 고친다. revert 는 되돌릴 수 없는 피해(데이터 · 보안 · 운영 장애)가 지금 이어질 때만 쓴다.
3. **분할은 레포 성격에 따른다.** 이 레포처럼 사람 하나가 쓰는 도구 레포는 목적 단위로 묶는다. 여러 팀이 쓰는 운영 서비스처럼 배포 단위가 고객에게 닿는 곳은 그 레포의 규칙이 정한다.

## 기각한 대안

| 대안 | 기각 이유 |
|------|-----------|
| 지금 상태 (리뷰 질문 하나 = 이슈 하나) | 같은 목적의 변경이 여러 PR 로 갈라져 머지 순서 · 충돌 · 교차 참조를 사람이 챙긴다. 사람의 주의가 목적이 아니라 PR 관리에 쓰인다. |
| 이슈 단위 롤백을 위해 PR 을 나눈다. | 되돌린 뒤 다시 쌓는 비용이 다음 커밋으로 고치는 비용보다 크다. 이 레포 main 커밋 1,060개 중 revert 커밋은 0개다 (2026-11-13 `git log --grep=^revert`). |

## 결과

- 이슈 가이드 · 태스크 관리 전략 · 레포 CLAUDE.md 가 목적 기준을 쓴다.
- PR 이 커지므로 리뷰는 ADR-0032 결정 2 대로 설계 · 결정 기록 중심이고, 가치는 테스트로 지킨다.
- 포기하는 것: 변경 일부만 되돌리는 선택지.
