# ADR-0036: 실험 판정 자리를 실험 전문가 하나로 둔다

- 상태: proposed
- 일시: 2026-11-11
- 관련: #940, ADR-0016(공식 문서), ADR-0019(역할), ADR-0020(PoC 구조), ADR-0021(전문가 근거와 노하우), ADR-0023(관찰), ADR-0035(글쓰기 자산 통일)

## 배경

실험 설계가 틀려 다시 하는 일이 서로 다른 자리에서 이어졌다.

| 사례 | 실패 |
|------|------|
| 비교 실험 보고서 (#585, ADR-0020) | 무엇과 무엇을 비교하는지, 어떤 시나리오로 어떤 지표를 보는지가 독립 절로 없어 조건 설명이 결과 아래 줄글로 밀려났다. |
| 구현 중 실측 누락 (ADR-0023) | 잠금 대기와 라우팅, 두 건에서 처음 쓰는 동작의 효과를 관찰하지 않고 통과했다. |
| 측정 랩 1차 (#940) | 비교군 선정 근거가 없고, 각 방식이 무엇을 하는지 서술이 없고, 전제와 다른 호스트에서 측정했다. |
| 측정 랩 2차 (#940) | 판정할 전문가가 없어 기획 전문가가 대신 정의했다. 막으려는 손실을 묻지 않고 일반값(요청 실패율)으로 채워, 구간에서 나는 실패에 30회 반복 통계 설계(약 13시간)가 나왔다. |

규칙은 대부분 이미 있었다. 흩어져 있어서 정의 단계에서 한 번에 적용되지 않았다.

| 판정 내용 | 있던 자리 |
|-----------|-----------|
| 사전 성공 기준 · 가설 먼저 · 후보 비교 · 재현 환경 | poc PC2 · PC5 · PC7 · PC8 (형식 규칙) |
| 가설 · 결론은 사람이 쓴다 | infra-lab 실험 기록 (클라우드 회전 전용, 질문은 부하 한계로 고정) |
| 규모 값이 실측인가 | 인프라 IN1 |
| 처음 쓰는 동작은 대상 환경에서 관찰 | ADR-0023, 구현 가이드 |
| 대조군을 두고 차이와 이유를 본다 | learning-flow 「대조군」, 작업 원칙 |
| 하네스부터 의심 · 확인하지 않은 값 · 재현 산출물 | 작업 원칙 |

결정자는 같은 지시(비교군 근거와 출처, 방식 서술, 환경 일치, 목적)를 자리마다 다시 해야 했다. 지시가 자리마다 조금씩 다르게 적혀 결정이 흐려졌다.

## 결정

1. **판정 자리는 실험 전문가 하나다.** 실험(PoC · 측정 랩 · 구현 중 실측)이 정한 질문에 답하도록 설계됐는지와 결과가 결론을 받치는지를 판정한다. 정의와 원천은 [`experts/experiment.md`](../../experts/experiment.md) 다.
2. **원칙은 아홉 개다(EX1 \~ EX9).** 막으려는 손실 · 질문 · 가설과 반증 조건 · 비교군 · 평가 기법 · 지표 · 환경 · 편향 · 결론의 크기다. 근거는 GQM, Jain 의 성능 평가 체계, 실험 타당도 위협 네 갈래다.
3. **막으려는 손실은 결정자가 쓴다(EX1).** 비어 있으면 전문가는 그것 하나만 묻고 멈춘다. 일반값으로 채우지 않는다. 손실이 범위 · 지표 · 기법을 정하므로 여기가 비면 뒤 기준이 전부 일반값으로 채워진다.
4. **자리를 나눈다.** 판정은 실험 전문가, 손실과 결론은 결정자, 회전 절차는 infra-lab, 실행은 실무자, 문서 형식은 poc · issue 규칙, 구성의 성질은 인프라 전문가, 전달은 기술 커뮤니케이션 전문가다.
5. **중복은 원천 한 곳만 남긴다.** 전문가 파일은 원천 자리를 가리키는 색인을 갖는다. 파일 위치와 규칙 ID 는 그대로 둔다. 훅 · 스크립트 · 미러가 경로와 ID 를 직접 읽는 사정은 ADR-0035 6항과 같다.
6. **infra-lab 회전 앞에 정의를 둔다.** 회전에 들어가기 전에 실험 전문가가 정의를 판정한다.

## 기각한 대안

| 대안 | 기각 사유 |
|------|-----------|
| 이름을 「연구 전문가」로 한다. | 연구(research)는 문헌 조사 · 학술 연구까지 넓다. 이 레포는 이미 「실험」(인프라 실험 랩 · 실험 기록)을 쓴다(작업 원칙 「이름은 있는 것부터 찾는다」). 「실험」은 한영 라운드트립(실험 → experiment → 실험)이 같은 개념으로 돌아오고, 구두로 「이 랩 설계는 실험 전문가한테 먼저 보자」가 자연스럽다. |
| 기획 전문가를 넓힌다. | 기획 전문가는 기획 문서가 푸는 문제를 본다. 측정 기준을 넣으면 PL1(문제 정의)이 기획 문제와 실험 손실 두 뜻이 된다. |
| 인프라 전문가를 넓힌다. | 인프라 전문가는 구성의 성질(용량 · 병목 · 비용)을 본다. 실험 설계는 구성이 없는 PoC · 구현 중 실측에도 쓰인다. |
| infra-lab 스킬에 판정 기준을 넣는다. | 스킬은 절차다(ADR-0019). 판정 기준을 넣으면 클라우드 회전을 타지 않는 실험(로컬 랩 · PoC)에는 기준이 닿지 않는다. |
| poc 규칙에 체크리스트만 더한다. | 규칙은 등록된 위반만 잡는다. 「이 손실에 이 기법이 맞는가」는 판정이 필요하다(ADR-0035 같은 사유). |
| 규칙 파일을 전문가 아래로 옮긴다. | 경로를 읽는 훅 · 스크립트가 조용히 깨진다. 같은 효과를 색인으로 얻는다. |

## 검토: 전문가 정의에 맞는가

| 확인 | 판정 |
|------|------|
| 근거 자리(ADR-0021) | 맞다. 실험 설계는 표준 문헌이 있다(GQM · Jain · Wohlin). 원천이 판정 원천 표에 있다. |
| 노하우 자리(ADR-0021) | 맞다. 「측정 비용이 손실 크기보다 크면 기법을 줄인다」처럼 정답이 없는 선택이 있고, 첫 케이스가 측정 랩 2차다. |
| 역할(ADR-0019) | 맞다. 판정만 한다. 실행은 infra-lab-operator, 손실과 결론은 결정자다. |
| 추가 조건(전문가 스킬 「전문가를 추가할 때」) | 맞다. 부를 상대가 없어 막힌 일이 서로 다른 자리(PoC 보고서 · 구현 실측 · 측정 랩)에서 두 번을 넘었다. |
| 동시 호출 금지(전문가 스킬 「누구를 부르나」) | 경계를 둔다. 인프라 전문가와 IN1 이 겹친다. 규모 값의 실측 여부는 IN1, 그 지표가 손실을 재는가는 EX6 이다. |

## 다시 열 조건

- 실험 전문가가 인프라 전문가와 같은 지적을 반복해 내면 경계를 다시 긋는다.
- 클라우드를 쓰지 않는 랩이 infra-lab 회전에 들어가지 못하는 일이 한 번 더 나오면, 회전의 진입 조건(구성 도구 · 부하 도구 의존)을 고친다.

## 결과

- 실험 정의와 결과 해석을 판정하는 자리가 하나가 된다.
- 결정자는 막으려는 손실 한 줄을 쓰고, 나머지 지시는 전문가 기준이 대신한다.
- 기획 · 인프라 전문가와 poc 규칙은 실험 판정을 실험 전문가로 넘기는 포인터를 갖는다.
