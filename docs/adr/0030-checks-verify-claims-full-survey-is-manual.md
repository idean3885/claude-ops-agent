# ADR-0030: 검사는 주장을 대조하고, 전체 조사는 사람이 부른다

- 상태: proposed
- 일시: 2026-10-27
- 관련: ADR-0019(역할), ADR-0028(병합 주체), ADR-0029(최종 점검 기록), #612 · #655(최종 점검), #772(판단 검토 기록), #810

## 배경

머지 전 최종 점검은 판단 점검으로 제로베이스 검토를 호출했다 (#772). 이 결정을 운영해 보니 세 가지가 드러났다.

| 사실 | 원천 |
|------|------|
| 판정 기준 8줄 중 대부분이 글 품질(사실 · 주제 · 이유 · 지시 대상 · 자리 · 일관성 · 문체)이다. 「설계를 지켰는가」는 「빠진 것」 한 줄로만, 「테스트가 충분한가」는 보지 않는다. | 제로베이스 검토 스킬 「판정 기준」 |
| 기준이 열려 있어 지적 0건으로 끝난 회차가 없다. 2026-10 기록 17회 중 0회 | 같은 스킬 「심각도」 |
| HEAD 가 바뀔 때마다 처음부터 다시 실행된다. 한 작업(PR 2건)에서 판단 점검 3회 · 강제 푸시 2회가 나 작업이 멈췄다. | #810 |

검사가 답해야 할 물음은 셋이다.

1. 설계를 지켰는가
2. 테스트가 충분한가
3. 1 · 2 에 대한 주장이 사실인가

1 · 2 는 작성자가 커밋 · 리뷰 요청 준비에서 이미 확인한다. 작성자의 확인은 자기 보고라 증거가 아니다 (ADR-0028 결정 4). 맥락 없는 시선이 필요한 것은 3 이다.

## 결정

### 1. 맥락 없는 검사는 주장을 대조한다

실행자가 자체 검증 끝에 주장 표(설계 항목 → 구현 자리 → 받치는 테스트)를 낸다. 맥락 없는 에이전트는 열린 조사를 하지 않는다. 다음 넷만 원천과 대조한다.

| 기준 | 보는 것 |
|------|---------|
| 구현 | 행마다 구현 자리가 주장한 동작을 하는가 |
| 테스트 | 행마다 테스트가 그 동작을 실제로 검증하는가 |
| 빠진 행 | 설계 원천 · 이슈 완료 조건의 항목 중 표에 행이 없는 것 |
| 행 밖 변경 | 어느 행에도 속하지 않는 변경. 범위 밖 수정과 과잉 구현이 여기서 잡힌다. |

기준이 닫혀 있어 끝이 난다.

### 2. 주장 검증은 드래프트 단계에서 1회 한다

리뷰 요청 준비 단계에서 작업 전체 변경분을 대상으로 1회 한다. 봇 · 사람 리뷰는 주장 검증을 마친 변경분을 받는다. 리뷰가 거짓 주장을 잡는 일까지 떠안지 않아야 리뷰가 의미를 갖는다.

차단이 나오면 고친 뒤 새 에이전트가 고친 행과 고친 변경만 다시 확인한다. 작업 전체를 다시 보지 않는다. 멈춤 조건은 제로베이스 검토와 같다: 차단 0건, 직전 회차와 이번 회차 모두 차단이 있고 이번 차단 수가 줄지 않음, 3회. 차단이 남은 채 멈추면 사람 판단으로 넘긴다.

머지 전 최종 점검은 드래프트 통과 이후 바뀐 부분 중 동작이나 테스트를 바꾼 것만 같은 방식으로 대조하고, 결정적 점검을 실행한다. 동작과 테스트를 바꾸지 않은 변경이면 결정적 점검만 한다.

### 3. 제로베이스 검토는 사람이 부르는 전체 조사로 되돌린다

자동으로 끼우지 않는다는 스킬의 원래 약속으로 돌아간다. 사용자가 모든 작업이 끝난 뒤 작업 전체를 조사할 때 부른다. 지적은 둘로 나눈다.

| 종류 | 뜻 | 처리 |
|------|----|------|
| 결함 | 원천에 기준이 있는데 어긋남 | 고친다 |
| 원천 공백 | 판정할 기준이 원천에 없음 | 결정 기록 후보로 사용자에게 올린다. |

같은 지적이 반복되는 원인은 판단 기준이 원천에 없는 것이다. 호출마다 주는 「의도한 선택」은 그 호출에서만 쓰이고 사라진다. 원천에 한 번 적으면 반복이 끝난다.

### 4. 안전장치는 그대로 둔다

`gh pr merge` 의 통과 기록 요구(#612)와 결정적 점검 항목은 유지한다. 점검 항목 h 가 보는 기록만 제로베이스 회차에서 주장 검증 회차로 바뀐다.

## 결과

| 대상 | 바뀌는 것 |
|------|-----------|
| 구현 가이드 | 자체 검증 끝에 주장 표를 낸다. |
| PR 가이드 | 리뷰 요청 준비에 주장 검증을 둔다. 머지 전 최종 점검은 드래프트 이후 바뀐 부분만 본다. 리뷰 반영은 새 커밋으로 쌓고 합치기는 최종 점검에서 1회 한다. |
| 제로베이스 검토 스킬 | 최종 점검의 자동 호출이 없어진다. 지적을 결함과 원천 공백으로 나눈다. |
| `final-check.sh` 항목 h | 노트의 `## 주장 검증` 회차를 본다. |

대가는 둘이다. 드래프트 이후 동작을 바꾸지 않았다고 판단한 변경은 맥락 없는 대조를 거치지 않는다. 열린 조사가 잡던 글 품질 지적은 자동으로 나오지 않고, 사람이 전체 조사를 부를 때만 나온다.

주장 검증은 판단 검토 모델(effort-policy 「판단 검토 모델」)로 실행한다. 비용은 모델이 아니라 범위로 줄인다. 거짓 주장을 잡는 것이 이 검사의 목적이라 판단 정확도를 낮추지 않는다.

## 다시 열어야 하는 조건

| 조건 | 다시 볼 것 |
|------|------------|
| 주장 검증을 통과한 변경에서 리뷰나 운영이 거짓 주장을 잡는 사례가 반복된다. | 결정 1 의 네 기준 |
| 드래프트 이후 「동작을 바꾸지 않았다」고 본 변경에서 결함이 나온다. | 결정 2 의 생략 조건 |

## 기각한 대안

| 대안 | 지불하는 것 | 얻는 것 | 기각 이유 |
|------|-------------|---------|-----------|
| 지금 상태 (최종 점검마다 제로베이스 검토) | HEAD 마다 열린 조사, 최대 3회 | 글 품질까지 매번 확인 | 목적(설계 · 테스트 · 거짓 주장)을 직접 보지 않으면서 비용이 가장 크다. |
| 작업당 1회로 횟수만 축소 | 머지 훅과 통과 기록 구조를 작업 단위로 다시 설계 | 검토 횟수 감소 | 열린 기준이 그대로라 1회 안에서 끝나지 않는다. 결정적 점검은 이미 싸서 얻는 것이 적다. |
| 최종 점검에서만 맥락 없는 검사 | 리뷰가 검사 전 변경분을 받음 | 검사 1회 | 리뷰 전에 거짓 주장이 걸러지지 않아 리뷰의 의미가 줄어든다. |
| 맥락 없는 검사 폐지 | 거짓 주장을 잡을 장치가 없음 | 비용 0 | 3 번 물음은 작성자 확인으로 반복해서 놓친 자리라 이 검사를 넣었다. |
