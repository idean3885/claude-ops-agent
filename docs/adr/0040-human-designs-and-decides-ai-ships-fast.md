# ADR-0040: 사람은 설계 리뷰와 의사결정만 하고, 구현 · 릴리즈 · 롤백은 AI 가 빠르게 한다

- 상태: accepted (시범 적용, 4주 뒤 「다시 열 조건」으로 판정)
- 일시: 2026-11-16
- 관련: #1040, [ADR-0039](0039-session-bundle-one-commit-per-issue.md)(묶음 · 이슈당 커밋 유지), [ADR-0038](0038-one-purpose-one-pr-roll-forward.md)(결정 2 롤포워드를 보정), [ADR-0032](0032-one-issue-one-pr-review-design-not-code.md)(코드가 아니라 설계를 본다, 유지), [ADR-0028](0028-merge-owner-follows-impact-scope.md)(자율 판단을 레포 유형으로 열지 않는다), #731 · #765 · #766

## 배경

이 레포는 사람 하나가 쓰는 공개 도구다. 머지하면 릴리즈를 거쳐 설치 캐시로 몇 분 안에 모든 세션에 퍼진다. 그래서 지금까지 판단 자리를 촘촘히 뒀다: 이슈마다 진행 지시, PR 마다 머지, 머지마다 릴리즈 PR.

| 사실 | 출처 |
|------|------|
| 5주(2026-10-12~)간 머지된 PR 199건 중 기능 PR 135건 · 릴리즈 PR 64건. 사람이 거부한 PR 은 0건이고, 닫힌 미머지 PR 6건은 모두 묶음 정리였다. | `gh pr list` 실측 |
| 생성에서 머지까지 중앙값: 기능 PR 7.5분, 릴리즈 PR 0.9분. 릴리즈 PR 은 판단 없이 서명만 했다. | 같은 실측 |
| 이슈는 주 19~46건 생기고 열린 이슈가 30건을 넘는다. 이슈마다 진행을 지시하는 자리가 사람의 주의를 쓴다. | 이슈 생성 시각 실측 |
| 같은 기간 대화 안 교정: 답 2,231개 중 156건. 형식 · 분량 54건, 내용 102건, 그중 범위 · 분할 · 추천 같은 방향 교정이 20여 건이다. 거부 0건은 사람이 모든 세션에서 대화로 방향을 잡아 준 결과일 수 있다. | 교정 판정 기록 (`lessons-judge`) |
| 기능 PR 134건 중 규칙 문서 · CLAUDE.md · docs · 훅 · 가드를 건드린 것이 64%다(좁게 ADR · 원칙 · 훅 · 가드만 47%, 넓게 85%). | PR 파일 목록 실측 |
| 최근 이슈 커밋 40개를 하나씩 되돌리면 바로 되는 것 6, 체인지로그 · 버전 파일만 부딪힌 것 23, 이후 변경과 내용이 부딪힌 것 11이다. 최근 15개로 좁히면 내용 충돌은 2다. | 복제본 리허설 |
| ADR-0032 → 0038 → 0039 가 17일 안에 대체됐다. 0032 의 「다시 열 조건」을 인용한 대체는 없었고 0038 에는 그 절이 없었다. | ADR 이력 |
| 외부 근거: 무거운 변경 승인은 변경 실패율을 낮추지 못하고 배포를 늦춘다(DORA). 트렁크 기반 개발은 롤포워드를 기본으로 하고, 롤백 수단은 미리 확보한다(SRE workbook). 외부 피드백 없는 자기 교정은 품질을 올리지 못한다(Huang et al., ICLR 2024). | 각 원전 |

## 결정

**원칙 한 줄: 사람은 설계 리뷰와 의사결정만 하고, 구현 · 릴리즈 · 롤백은 AI 가 빠르게 한다.** 아래 여섯 결정이 이 줄에서 나온다.

```text
갭 발견 ─► 처음: 사례 기록 / 두 번째: 이슈
세션 ─► AI: 이번 세션 묶음 목록 제시 ─► [사람] 의사결정: 착수 승인 (1회)
     ─► AI: 구현 · 결정적 검사 ─► 묶음 PR (「대신 정한 것」 브리핑)
     ─► [사람] 설계 리뷰: 머지 = 채택 / 이슈 단위 반려 = 그 커밋을 제외하고 다시
     ─► 워크플로: 버전 결정 · 릴리즈 (릴리즈 PR 없음)
```

1. **사람의 판단 자리는 세션마다 둘이다.** 의사결정은 묶음 착수 승인에서, 설계 리뷰는 묶음 PR 머지에서 한다. 이슈마다 진행을 지시하지 않는다. 머지는 사람 몫으로 남는다.
2. **갭은 처음엔 사례로 기록하고, 같은 자리가 두 번째 나오면 이슈로 올린다.** 레포 CLAUDE.md 「수정 플로우」의 기존 줄에 기록할 자리를 정한다. 묶음 PR 과 이슈당 커밋(ADR-0039)은 그대로다.
3. **머지 직후 워크플로가 릴리즈한다.** Unreleased 로 버전을 정하고(MAJOR 는 브레이킹 체인지, MINOR 는 기능 추가, PATCH 는 버그 픽스 · 기능 개선. 체인지로그의 `**BREAKING**` 표시 · Added · Deprecated 로 판별) 끊고 태그와 릴리즈 노트를 만든다. 인증은 잡마다 발급되고 잡이 끝나면 만료되는 워크플로 토큰이다.
4. **롤백은 방향을 거부했거나 오작동이 지금도 퍼질 때 먼저 멈추는 수단이다.** 머지된 이슈 커밋 하나를 되돌리고(`scripts/revert-issue.sh`), 체인지로그 · 버전 충돌은 기계적으로 푼다. 이후 변경과 내용이 부딪히면 롤백하지 않고 롤포워드로 고친다. 받아들인 방향 안의 결함은 롤포워드로 고친다. ADR-0038 결정 2(롤포워드, 롤백은 되돌릴 수 없는 피해일 때만)를 이렇게 보정한다.
5. **전문가 깊이는 AI 가 스스로 정하지 않고 결정의 종류로 정한다.** 번복 · 원칙 신설 · 가드 완화는 심화(대안 · 트레이드오프 · 기각 사유 · 그럼에도 고른 이유)다. 기록된 방향의 적용은 단일 결단이다. 기준끼리 충돌하거나 사용자가 이의를 내면 경량으로 올린다.
6. **ADR 을 대체할 때는 대체되는 ADR 의 「다시 열 조건」 중 무엇이 충족됐는지 인용한다.** 새 ADR 은 그 절을 반드시 둔다. 충족된 조건 없이 대체하려면 그 사실과 이유를 적는다.

## 기각한 대안

| 대안 | 포기하는 것 | 얻는 것 | 기각 이유 |
|------|------------|---------|-----------|
| 지금 상태 (이슈마다 진행 지시 · PR 마다 머지 · 릴리즈 PR) | 사람의 주의 | 매 단계 확인 | 거부 0건 · 릴리즈 PR 0.9분이 확인이 아니라 서명이었음을 보인다. 이슈 유입이 사람의 판단 속도를 넘었다. |
| 크리티컬 경로만 사람이 보고 나머지는 AI 가 머지 | 규칙 변경의 직접 확인 | 사람의 주의 감소 | 변경의 64%가 크리티컬 경로라 나눠도 사람이 덜 보지 않는다. 경로 목록을 줄이면 규칙 변경이 확인 없이 퍼진다. |
| 착수 · 머지 모두 AI (전면 자율) | 방향 교정 자리 | 사람의 주의 0 | AI 가 올린 이슈를 AI 가 구현하고 AI 가 머지하는 고리가 생긴다. 외부 피드백 없는 자기 교정은 품질을 올리지 못한다. 거부 0건이 사람이 방향을 잡아 준 결과일 수 있다. |
| 만든 쪽이 권한을 갖고 빠르게 릴리즈 · 롤백 (팀 단위 관행) | 머지 판정 | 속도 | 이 레포는 만든 쪽이 AI 다. 사람이 아닌 작성자에게 권한을 주면 위 고리와 같다. 빠른 릴리즈 · 롤백은 결정 3 · 4 로 받는다. |

## 결과

- README 첫머리에 원칙 한 줄을 두고, 결정자 행을 「세션 묶음 착수 승인 · 묶음 머지(설계 리뷰) · 번복 결정」으로 바꾼다.
- 레포 CLAUDE.md 반영 경로에서 릴리즈 PR 을 제외한다. `post-merge-sync.sh` 는 릴리즈 잡을 기다린 뒤 받는다.
- expert 스킬이 깊이를 결정 종류로 정하고, 노하우 케이스에 양쪽 선택과 재검토 시점(관측값 · 임계)을 둔다(#765 · #766 흡수).
- 자율은 레포 성질이 아니라 판단 자리의 수로 정한다(#731). ADR-0028 의 저장소 유형 병합 분기는 선언한 레포가 0개라 동작하지 않고, 이 결정으로 새로 열지 않는다. 장치 제거는 그 코드를 다음에 고칠 때 한다. 지금 없애면 머지 가드 자체 점검을 다시 짜야 해 이 묶음의 범위를 넘는다.
- 포기하는 것: 퍼지기 직전의 마지막 확인(릴리즈 PR), 이슈마다의 착수 확인, 첫 갭의 즉시 추적.
