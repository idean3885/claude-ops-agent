# ADR-0049: 기본 브랜치 push 의 게이트는 롤백 가능 여부로 정하고, 저장소 유형은 일반 push 를 막지 않는다

- 상태: accepted
- 일시: 2026-11-26
- 관련: #1268, [ADR-0028](0028-merge-owner-follows-impact-scope.md)(레포 유형), [ADR-0018](0018-gate-is-the-only-approval-channel.md)(승인 채널), #1046(대화창 위임), #1133(기본 브랜치 강제 push)

## 배경

| 사실 | 출처 |
|------|------|
| 저장소 유형 레포는 기본 브랜치 직접 반영이 정상 흐름이다. 그래도 일반 push 마다 `git-default-push` 갈래가 막혀 사람이 개방 명령을 실행했다. | 사용자 워크플로 (개인 자산 기록 레포) |
| 대화창 위임(「푸시 권한 위임」, #1046)은 이 왕복을 줄이려고 들어왔다. 위임은 8시간 뒤 닫혀, 긴 세션은 8시간마다 다시 멈췄다. | `docs/action-gate.md` 「대화창 위임」 (이 ADR 로 삭제) |
| 위임은 게이트 판정을 바꾸지 않고 개방 경로만 하나 더 둔 우회였다. 판정 질문이 없어 「무엇을 막는가」가 레포마다 달라질 수 없었다. | 같은 문서 |
| 한시 권한 게이트는 되돌릴 수 없는 행위를 막는 자리다. | README 「되돌릴 수 없는 것은 사람이 판정합니다」 |

## 결정

### 1. 판정 질문은 「롤백한 뒤에도 지울 수 없는 사이드 이펙트가 남는가」다

기준 용어는 style-rules 용어 목록의 「복구 비용 · 롤백 가능」 항목이다. 지울 수 없는 사이드 이펙트는 세 종류다.

| 종류 | 예 |
|------|-----|
| 남이 이미 본 것 | 공개 표면에 올라간 글, 알림이 간 리뷰 |
| 남이 이미 받은 것 | 배포된 릴리즈, 동료가 당겨 간 커밋 |
| 원본이 사라진 것 | 강제 push 로 덮인 이력, 삭제된 원격 브랜치 |

### 2. 저장소 유형 레포의 기본 브랜치 일반 push 는 판정하지 않는다

저장소 유형은 영향이 본인에게만 미친다 (ADR-0028). 일반 push 는 원본을 지우지 않고, 본 사람 · 받은 사람이 없다. 되돌리는 커밋으로 롤백이 끝난다.

### 3. 강제 push 는 계속 막는다

강제 push 는 원본이 사라지는 행위다. `git-force` 갈래가 유형과 무관하게 따로 판정한다 (#1133). 업무 · 사상 유형과 선언 없는 레포의 기본 브랜치 push 도 그대로 막는다. 남이 이미 받은 것이 생기기 때문이다.

### 4. 대화창 위임을 제거한다

판정이 저장소 유형의 일반 push 를 빼면 위임이 열던 자리가 사라진다. 위임 훅 · 기록 · 편집 차단 · 선언 키(`"allow": ["git-default-push"]`)를 지운다. 남은 선언 키 값은 오류 없이 무시된다.

## 기각한 대안

| 대안 | 포기하는 것 | 얻는 것 | 기각 이유 |
|------|------------|---------|-----------|
| 레포 선언의 상시 개방 키 | 판정 자리 하나 | 레포마다 고르는 자유 | 게이트 판정 자리가 유형과 선언 키 둘이 된다. 같은 질문에 두 답이 나올 수 있다. |
| 대화창 위임 유지 | 멈춤 없는 세션 | 변경 없음 | 8시간마다 멈추는 비용이 남고, 판정 질문 없는 우회가 그대로 남는다. |
| 레포별 옵스(게이트) 끄기 | 강제 push 보호 | 가장 단순함 | 전역 동작을 레포 파일이 끈다. 강제 push 까지 함께 풀린다. |

## 결과

- 저장소 유형 레포에서 기본 브랜치 일반 push 는 개방 없이 통과한다. 강제 push 는 계속 막힌다.
- `docs/action-gate.md` 의 갈래 표와 레포 유형 표가 이 판정을 적는다.

### 트레이드오프

개인정보가 담긴 커밋은 이력에 남아 롤백할 수 없다. 그런데 커밋 내용은 게이트가 판정하지 못한다. 이 자리는 레포 지침의 기록 원칙과 대외비 가드가 맡는다.
