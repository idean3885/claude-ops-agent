# ADR-0039: 한 세션의 이슈는 PR 하나로 묶고, 추적성은 이슈마다 커밋 하나로 지킨다

- 상태: accepted
- 일시: 2026-11-16
- 관련: #1013, [ADR-0038](0038-one-purpose-one-pr-roll-forward.md)(결정 1 「나누는 기준은 목적」을 대체, 결정 2 롤포워드 · 결정 3 레포 성격은 유지), [태스크 관리 전략](../task-management.md)

## 배경

| 사실 | 출처 |
|------|------|
| 한 세션에서 나온 문서 변경 4건을 목적별 PR 넷으로 나눴다. 같은 CHANGELOG 줄을 넷이 고쳐 충돌했고, 해소하려면 강제 푸시 권한 요청과 머지 순서 관리가 필요했다. | #1002 · #1004 · #1005 · #1007, 닫은 PR #1008 · #1009 · #1010 |
| 리뷰 봇은 저별점 공개 레포에서 시간당 1건 수준으로 리뷰한다. PR 이 늘면 리뷰를 받는 시간이 그 수만큼 늘어난다. | [PR 가이드](../../skills/flow/guides/pr.md) CodeRabbit 표 |
| 이 레포 main 커밋 중 revert 는 0개다. 원칙이 잘못돼 그 원칙으로 이미 일한 결과는 문서를 되돌려도 복구되지 않는다. | ADR-0038 기각 대안 표 |
| 형상 관리의 중심 목적은 추적성(무엇이 어떤 결정 때문에 바뀌었나)과 재현성이다. 롤백은 그중 한 수단이다. | IEEE 828 · ISO 10007 의 형상 식별 · 변경 통제 · 상태 기록 · 감사 |

## 결정

1. **한 세션에서 잡은 이슈는 몇 개든 PR 하나로 묶는다.** 이슈가 어디서 나왔는지, 목적이 몇 개인지는 나누는 기준이 아니다. 브랜치도 하나다.
2. **이슈마다 커밋 하나를 둔다.** 커밋 제목에 그 이슈 번호를 적는다. 한 이슈의 교정 커밋은 그 이슈의 커밋으로 합친다. 최종 점검(`final-check.sh` 항목 g)이 이를 판정한다. 커밋 하나가 이슈 둘을 함께 닫는 것은 허용한다. 최종 점검은 다른 레포도 쓰므로, 커밋이 하나뿐인 PR 은 제목에 이슈 번호가 없어도 통과한다(트래커 링크를 본문에 두는 레포).
3. **막힌 이슈는 묶음에서 제외하고 열어 둔다.** 한 건이 리뷰 · 설계에서 막혀 전체가 머지되지 못하면, 그 커밋을 묶음에서 제외하고 이슈를 다음 세션 묶음으로 넘긴다.
4. ADR-0038 의 롤포워드(결정 2)와 레포 성격에 따른 분할(결정 3)은 그대로다. 이 결정은 사람 하나가 쓰는 이 레포에 적용한다.

## 기각한 대안

| 대안 | 기각 이유 |
|------|-----------|
| 지금 상태 (목적 하나 = PR 하나, ADR-0038) | 목적이 여럿인 세션은 PR 이 여럿이 되어, 같은 파일 충돌 · 머지 순서 · 리뷰 한도 대기를 사람이 챙긴다. 위 실측이 그 비용이다. |
| 세션 묶음을 커밋 하나로 합친다. | 어느 줄이 어느 결정에서 왔는지 찾을 단서가 커밋 메시지 하나로 줄어 추적성을 잃는다. |
| 묶음 크기에 상한을 둔다. | 리뷰 품질이 떨어진 사례가 아직 없다. 근거 없이 항목을 늘리지 않는다. 리뷰 지적의 질이 떨어지는 것이 보이면 그때 정한다. |

## 결과

- 레포 CLAUDE.md · 태스크 관리 전략 · 이슈 가이드 · PR 가이드가 세션 묶음과 이슈당 커밋 하나를 쓴다.
- 최종 점검 g 는 커밋이 여럿일 때 「제목의 이슈 번호 · 이슈당 커밋 하나」를 본다. 커밋 하나는 예전처럼 통과한다.
- 범용 가이드(이슈 · PR)는 묶음 단위를 레포 규칙에 맡기고, 이 레포의 세션 묶음을 예로 든다.
- 포기하는 것: 이슈마다 따로 머지하는 선택지. 일부만 먼저 반영해야 하면 결정 3 으로 그 이슈를 묶음에서 제외한다.

## 조건이 바뀌면

다른 사람이 이 레포에 기여하거나, 머지가 곧 되돌릴 수 없는 사용자 환경 배포가 되면 목적 단위 분할(ADR-0038 결정 1)로 돌아간다.
