# ADR-0017: 게이트 계획은 대상 행위를 이름으로 댄다

- 상태: superseded by [ADR-0018](0018-gate-is-the-only-approval-channel.md)
- 일시: 2026-10-01
- 관련: 이슈 #577, #141(게이트 개방 프로토콜), ADR-0016(공식 문서가 기본값)

## 배경

#141 은 개방 프로토콜을 「사용자가 창을 열면 어시스턴트가 그 갈래의 행위를 수행한다」로 확정했다. 하네스의 오토 모드 분류기가 막는 것은 개방 명령 하나로 보았다.

사용자가 「릴리즈까지 일괄 승인」으로 자율 진행을 맡긴 작업에서 이 가정이 깨졌다.

| 단계 | 결과 |
|------|------|
| 게이트 창 | `repo-merge` 열림 |
| 어시스턴트의 `gh pr merge` | 분류기가 「리뷰 없는 머지」로 거부 |
| 결과 | 기능 PR · 릴리즈 PR 두 번 모두 사용자가 직접 실행 |

같은 행위를 두 판정자가 보고, 각자 다른 신호를 읽는다.

| 판정자 | 읽는 신호 |
|--------|-----------|
| 액션 게이트 | 마커의 갈래와 만료. 사용자의 문장은 권한을 열지 않는다 |
| 오토 모드 분류기 | 대화 속 사용자의 승인 |

분류기가 승인을 읽는 조건은 공식 문서 [Permission modes](https://code.claude.com/docs/en/permission-modes) 「Approvals you state in conversation」에 있다.

> Name the action and its specifics: your message has to name the action and the specific thing that makes it dangerous, such as the branch of a force push. Naming the verb alone clears nothing

> Expect it to cover one action: an approval covers the destructive action you named, so a later action is blocked again unless you granted the approval as standing.

「일괄 승인」은 행위도 대상도 이름으로 대지 않았다. 분류기 입장에서는 승인이 없었다.

## 결정

### 1. 두 판정자를 각자의 신호로 통과한다

어느 판정자도 비키게 하지 않는다. 게이트는 마커로, 분류기는 사용자의 승인 문장으로 통과한다. 게이트 원칙 「자연어 승인은 게이트를 열지 않는다」는 그대로다. 그 문장은 게이트가 아니라 분류기의 신호다.

### 2. 계획이 승인 문장의 재료를 낸다

GATE 3 1단계 계획은 대상 행위마다 행위 · 대상 · 범위를 이름으로 댄다.

| 항목 | 예 |
|------|----|
| 행위 | PR 머지, 원격 브랜치 삭제 |
| 대상 | `feat/577` PR 과 `release/9.9.1` PR 을 `main` 에 |
| 범위 | 이번 작업 동안 상시 |

대상을 아직 모르면 그것을 만드는 규칙으로 댄다(「이 이슈의 기능 브랜치 PR 과 그 릴리즈 브랜치 PR」). 승인은 사용자가 자기 말로 한다. 어시스턴트는 문장을 대신 말하지 않고 재료만 낸다.

## 기각한 대안

| 대안 | 기각 이유 |
|------|-----------|
| 게이트 대상 명령을 허용 규칙에 넣어 분류기를 거치지 않게 하는 절차를 문서에 둔다 | 안전장치 한 층을 지시로 걷어낸다. 그 지시를 스킬에 넣는 편집을 분류기가 「지시 오염」으로 거부했다. 허용 규칙은 사용자 환경의 선택이고, 이 레포가 권하지 않는다 |
| 게이트 대상 행위를 매번 사용자가 `!` 로 직접 실행 | 자율 위임이 성립하지 않는다. 이번에 쓴 우회이고 사용자가 거부했다 |
| 게이트를 없애고 분류기 승인에 맡긴다 | 갈래 · 만료 같은 범위가 남지 않는다. 오토 모드 밖에서는 판정자가 사라진다 |
| 분류기 차단 목록을 `docs/action-gate.md` 에 정리 | 외부 시스템 규격의 복제다. 하네스가 바뀌는 날부터 거짓이다. 공식 문서를 링크한다 |

## 대가

계획이 한 줄씩 길어진다. 대상을 이름으로 대려면 브랜치 · PR 이 정해지는 시점을 계획에서 미리 정해야 한다.

승인이 분류기를 통과하는지는 분류기가 판정한다. 이 레포가 보장하지 않는다.
