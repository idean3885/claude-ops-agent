# ADR-0011: 게이트 대상 행위는 단독 명령으로만 실행한다

- 상태: accepted
- 일시: 2026-08-27
- 관련: 이슈 #386, PR #384(사고), PR #385(복구), 커밋 `e2d5389`(종료 코드를 0 으로 고친 시점)

## 배경

머지 전 버전 대조(GATE 6)는 8.5.0 에서 도입됐고 문서 스니펫으로 제공됐다. 판정을 「멈춤」 문자열로 출력하고 종료 코드는 0 이었다.

PR #384 머지에서 이 스니펫과 `gh pr merge` 가 한 명령 블록에 들어갔다.

| 단계 | 결과 |
|------|------|
| 버전 대조 실행 | 두 조건 모두 검출 — 버전 동일, CHANGELOG 헤더 중복 |
| 같은 블록의 `gh pr merge` | 실행됨 |
| 기본 브랜치 | `[8.6.1]` 항목이 둘, `VERSION` 이 다른 세션 값과 동일 |

**판정은 정확했다. 막지 못한 것은 실행 순서다.** 출력을 내는 것과 읽는 것은 다른 단계인데, 절차에는 출력을 내는 단계만 있었다.

## 결정

### 1. 검사는 판정을 종료 코드로 돌려준다

스니펫을 `scripts/pre-merge-check.sh` 로 옮기고, 검출 시 종료 코드 1 · 통과 시 0 으로 나눴다. `&&` 로 물리면 검출된 상태에서 다음 명령이 실행되지 않는다.

`e2d5389` 은 같은 스니펫의 종료 코드를 1 에서 0 으로 고쳤다. 사유는 「중복 없음이 실패로 읽힌다」였고, 당시 형태(`[ -n "$dup" ] && echo …`)에서는 맞는 판단이었다. 통과가 1 을 돌려주는 반대 방향이었다. 이번 결정은 그 판단을 되돌리는 것이 아니라 방향을 바로 세우는 것이다.

### 2. 검사하지 못한 상태를 통과와 같은 모양으로 두지 않는다

원격에 브랜치가 없으면 「파일 없음 — 건너뜀」이 아니라 멈춤이다. 사고의 원인이 푸시하지 않은 로컬 리베이스였고, 그 상태에서 원격 조회는 전부 빈 값을 돌려준다. 빈 값을 건너뜀으로 읽으면 검사하지 않은 상태가 통과와 구별되지 않는다.

### 3. 훅이 동거를 거른다

게이트 대상 행위 **앞에** 다른 명령이 같은 블록에 있으면, 갈래가 열려 있어도 차단한다.

| 형태 | 판정 | 근거 |
|------|------|------|
| gated 행위 단독 | 통과 | — |
| `cd`·`export`·`set`·주석이 앞에 | 통과 | 읽어야 할 판정 출력이 없다 |
| gated 행위 뒤의 정리 명령 | 통과 | 이미 실행된 행위에 딸린 것이고, 실패하면 실행되지 않는다 |
| 그 밖의 명령이 앞에 | **차단** | 출력을 읽기 전에 행위가 실행된다 |
| `pre-merge-check.sh` 가 앞에 | 통과 | 판정을 종료 코드로 돌려주므로 읽지 않아도 집행된다 |

**앞 세그먼트만 본다.** 뒤에 오는 명령은 되돌리기 어려운 행위가 이미 끝난 뒤의 결과 처리다.

이 검사는 갈래 허용과 독립이다. `all` 이 열려 있어도 발동한다. 게이트가 열린 동안에만 의미가 있는 검사이기 때문이다. 게이트가 닫혀 있으면 갈래 차단이 먼저 걸린다.

## 기각한 대안

| 대안 | 기각 이유 |
|------|-----------|
| 문서에 「분리해서 실행하라」만 적는다 | 잊었을 때 걸리는 것이 없다. 이 사고가 지시를 어긴 것이 아니라 지시가 없어서 난 것이다 |
| 스니펫을 그대로 두고 종료 코드만 바꾼다 | 스니펫은 복사되는 순간 원본과 갈라진다. 실행 주체가 여러 줄을 손으로 옮기면 한 줄이 빠져도 드러나지 않는다 |
| 모든 체인 세그먼트를 금지한다 | `cd <경로> && gh pr merge` 는 워크트리에서 필요한 형태다. 뒤따르는 정리 명령까지 막으면 정상 절차가 두 배로 늘어난다 |
| 검사 스크립트도 예외 없이 차단한다 | 종료 코드로 집행되는 검사를 체인에 물리는 것이 분리 실행보다 강하다. 사람이 출력을 읽지 않아도 결과가 적용된다 |

## 대가

게이트 대상 행위를 포함한 블록은 조회 명령과 합칠 수 없다. 도구 호출이 한 번 더 늘어난다. 되돌리기 어려운 행위에만 걸리므로 빈도는 낮다.

heredoc 본문이 세그먼트로 잘려 오탐이 날 수 있다. 본문 여러 줄을 담은 명령과 gated 행위가 한 블록에 있는 형태인데, 그 조합 자체가 차단 대상이라 오탐이 곧 정탐이다.

## 다시 열어야 하는 조건

| 조건 | 다시 볼 것 |
|------|-----------|
| 정상 절차가 반복적으로 차단된다 | `COHABIT_BENIGN` 허용 목록 |
| 종료 코드로 판정하는 검사가 늘어난다 | `COHABIT_GATE_CHECK` 를 이름 하나가 아니라 설정으로 둘지 |
