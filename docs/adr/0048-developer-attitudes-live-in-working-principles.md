# ADR-0048: 개발자 태도의 원천은 작업 원칙의 기준 절이고, 사례는 비공개 기록이 갖는다

- 상태: accepted
- 일시: 2026-11-26
- 관련: #1262, [ADR-0040](0040-human-designs-and-decides-ai-ships-fast.md)(태도 7 의 경계), [ADR-0022](0022-lessons-keep-facts-procedures-tastes.md)(사용자가 선언한 원칙은 작업 원칙이 갖는다)

## 배경

| 사실 | 출처 |
|------|------|
| 작업 원칙의 기준은 「함께 일하고 싶은 개발자」이고, 사용자의 비공개 원칙 문서의 기준은 「같이 일하고 싶은 동료」다. 같은 뿌리의 문장이 두 곳에서 따로 고쳐졌다. | 두 문서 대조 (2026-11-26) |
| 비공개 원칙 7개 중 6개가 작업 원칙과 뜻이 겹쳤다. 겹치지 않는 1개는 합의 · 표현이다. | 같은 대조 |
| 어시스턴트가 개발 태도를 묻는 대화에서 작업 원칙만 보고 답해, 이미 있던 비공개 원칙을 놓치고 새 자리를 제안했다. | 세션 기록 (2026-11-26) |
| 겹치는 쌍 중 둘은 작업 원칙 쪽이 부실했다. 딥다이브는 「모르면 묻고 기다린다」로만 읽혔고, 테스트는 시나리오에서 출발한다는 점과 커버리지를 목표로 두지 않는다는 점이 없었다. | 같은 세션의 사용자 판정 |

## 결정

1. **개발자 태도 7개를 작업 원칙의 기준 절 아래 「태도」로 둔다.** 기준과 원칙 사이를 잇는 층이고, 위계 표의 기준 층에 속한다. 기존 원칙은 각 태도 아래 경계로 연결한다.
2. **태도 1 · 2 · 6 · 7 을 잇는 「가치에서 확인까지」 흐름을 같은 절에 둔다.** 검증(만든 대로 동작하는가)과 확인(가치를 냈는가)을 나눠, 확인 결과가 다음 시나리오로 돌아오는 고리를 둔다.
3. **태도 문장의 원천은 이 문서 하나다.** 사용자의 비공개 기록은 태도마다 사례 · 출처만 두고 이 절을 가리킨다. 참조는 비공개에서 공개로 한 방향만 둔다.
4. **원칙 두 개에 태도와 맞추는 문장을 더한다.** 「조사 공수는 방안을 선택하는 데까지 잡는다」에는 조건을 바꿔 본 결과가 방안 선택의 재료라는 줄을, 「이름은 있는 것부터 찾는다」에는 책임 경계 밖은 그 시스템의 이름으로 부른다는 줄을 더한다.

## 기각한 대안

| 대안 | 포기하는 것 | 얻는 것 | 기각 이유 |
|------|------------|---------|-----------|
| 지금 상태 (두 곳에 따로 둠) | 하나의 원천 | 비공개 쪽 문장의 자유 | 한쪽만 찾고 놓치는 일이 이미 생겼고, 같은 뜻의 문장이 갈라지고 있다. |
| 비공개 기록을 원천으로 두고 작업 원칙이 가리킴 | 공개 원칙의 자족성 | 사례와 문장이 한 곳 | 공개 표면은 비공개 기록을 가리킬 수 없다. 작업 원칙만 읽는 어시스턴트는 계속 놓친다. |
| 태도를 새 절(기준 밖)로 둠 | 위계의 단순함 | 기존 기준 절을 건드리지 않음 | 기준과 태도가 다시 두 자리가 된다. 기준의 「함께 일하고 싶은 개발자」를 행동으로 푼 것이 태도라 같은 층이다. |
| 태도를 흐름 단계 4개(1 · 2 · 6 · 7)로 줄임 | 약점 · 협업 질문의 출발점 | 줄 수 | 실제 받은 질문 중 「다른 팀과 부딪힌 경험」 · 「약점」에 출발점이 사라진다. |

## 결과

- 작업 원칙 기준 절에 태도 7개와 흐름 그림이 생기고, 원칙 두 개에 한 줄씩 더해진다.
- 글로벌 지침의 「작업 원칙 (항시)」 요약은 태도 절을 가리키는 한 줄로 맞춘다.
- 포기하는 것: 비공개 쪽에서 문장을 혼자 고치는 자유. 문장을 고치려면 이 문서를 먼저 고친다.

|------|------------|

| 사용자가 받은 질문 중 일곱 태도 어디에서도 출발점을 찾지 못한 것이 1건 이상 | 결정 1: 그 질문으로 태도를 다시 대조한다. |
| 태도 문장이 경계 원칙과 어긋나는 일이 2건 이상 | 결정 1: 태도와 원칙의 위계를 다시 판정한다. |
