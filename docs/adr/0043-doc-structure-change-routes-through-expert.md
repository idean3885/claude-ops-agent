## 결정

1. **개발자의 모든 기술 글은 규모와 무관하게 계획안과 판정을 기술 커뮤니케이션 전문가가, 승인을 사용자가 한다.** 범위의 원천은 [전문가 파일 「범위」 표](../../experts/tech-comm.md#범위) 하나다. 문장 한두 개 · 오탈자 · 링크도 면제하지 않는다. 작은 글도 계획안의 항목(PU1 · PU2 · 분량 · 시각)은 넷이고 값만 작다. 커밋 메시지 · 변경 기록(CHANGELOG) 항목 · 대화 보고 · 일자별 기록은 그 표의 「다루지 않는다」 칸에 있어 들어가지 않는다. 이 칸은 규모가 아니라 장르로 가르므로 「규모 면제 없음」과 충돌하지 않는다. 넣을지를 바꾸려면 표를 고친다. 전문가는 서브에이전트로 부르고, 판정의 반환 첫 줄은 `[tech-comm-verdict: pass|revise|hold]` 중 하나다. 메인 세션은 계획안 · 판정을 사용자에게 전달한다.
2. **공유 표면 쓰기는 기계가 경유를 기록하고, 2주 기록 뒤 차단으로 올릴지 판정한다.** 대상은 이슈 · PR 생성 · 본문 편집 · 댓글, PR 리뷰, `gh api` 로 쓰는 댓글 · 리뷰, 범위 안 md(`*.md` 에서 변경 기록 파일을 뺀 것. 범위 표의 「레포 문서」. 변경 기록 파일의 이름 규칙은 [hooks-config 「전문가 경유 지표」](../hooks-config.md))를 담은 커밋, 오버레이로 더한 문서 도구다. 레포 문서는 초고 쓰기가 판정보다 먼저 오므로 쓰는 순간이 아니라 커밋 때 「판정 뒤 보낸다」를 본다. 커밋도 흔적을 소비해, 그 커밋을 담는 PR 본문은 따로 판정받는다. 본문 줄 수를 함께 남겨 규모별로 나눠 볼 수 있게 한다. 한 호출에 표면이 여럿이면(커밋 뒤 PR 생성 등) 표면마다 한 줄을 남기고, 흔적은 명령 순서대로 앞 표면이 소비한다. 경유에는 판정 값(pass · revise · hold)을 함께 남긴다. 경유로 세는지는 판정 값과 무관하다. 경유는 전문가 파일을 가리킨 에이전트 호출의 결과 첫 줄이 판정 표식일 때뿐이다. 메인 세션이 쓴 표식은 세지 않는다. 메인 세션이 전문가 파일을 직접 읽기만 했으면 「판정 불가(inline)」, 흔적이 없으면 「누락」이다. 이슈 · PR 본문에 출처 표식을 넣지 않는다.
3. **레슨 판정의 원인에 「경로」를 더한다.** 경로는 불렀어야 할 스킬 · 전문가 · 검증 단계를 부르지 않아 생긴 교정이다. 경로 원인에 한해 기준선을 한 번 다시 판정한다. 원인 둘 시절에 판정한 세션 가운데 기록이 남은 것이 대상이고, 기존 판정 행은 덮지 않고 경로 교정 수만 따로 남긴다. 판정 행에 원인 갈래 판을 남겨 판이 다른 행끼리는 경로를 비교하지 않는다. 새 판정은 경로를 먼저 가르므로 원인 셋 판(판 2)의 내용 · 수준 수도 원인 둘 판(판 1)과 뜻이 달라, 내용 · 수준 역시 같은 판끼리만 비교한다. 전체(교정 수)는 원인 갈래와 무관해 판을 넘어 비교한다.
4. **자동 지표도 원인 갈래도 없는 시범은 등록하지 않는다.** 세션 시작 주입에서 빼고 이름만 한 줄로 알린다. 지표는 줄 수 집계와 함께 두 필드 합의 비율을 받는다. 문구 감지 지표에는 세션 식별자를 남겨 그 세션의 정답률과 잇는다.
5. **세션 시작 요약에 경로 누락을 보인다.** 최근 7일의 공유 표면 쓰기 경유 · 누락 · 판정 불가 수, 레슨 원인 「경로」 수, 플로우 진입 누락 수(커밋 · push)를 한 줄로 둔다.

## ADR-0005 결정 2 대체

ADR-0005 결정 2(규모로 게이트 강도를 나눈다)의 면제 구간을 없앤다. 결정 1 · 3 · 4 · 5 는 그대로다.

ADR-0005 의 다시 열 조건 가운데 해당하는 둘(「규모 기준: 면제 구간에서 되돌리기가 관측될 때」, 「전면 강제: 게이트 통과가 습관이 되어 사람이 묻기 전에 답을 적기 시작할 때」)은 충족 여부를 잰 기록이 없다. 면제 구간의 되돌리기를 세는 지표가 없었다. 충족된 조건 없이 대체하는 이유는 사용자 결정이다(ADR-0040 결정 6 · 7). 전문가는 모든 글쓰기를 맡기려고 만들었고, 규모로 경로를 가르면 결과가 일정하지 않다.

ADR-0005 가 전면 강제를 기각한 이유(오탐이 쌓이면 사람이 게이트를 끈다)는 아래 다시 열 조건 첫 행이 받는다. 첫 쓰기 지연 · 오탐이 쌓이면 경로를 가르지 않고 제약을 덜어 낸다.

## ADR-0019 결정 1 유지 · 결정 2 보정

결정 1(결정자는 사용자)은 그대로다. 결정 2 의 「계획 게이트와 최종 확인은 결정자」를 계획안(전문가)과 승인(사용자)으로 나눈다. 어긋난 것은 ADR-0019 가 아니라 글 작성 스킬이 결정자를 「부른 쪽」으로 적은 자리다. 결정을 뒤집지 않고 나누는 보정이라 ADR-0040 결정 6 의 다시 열 조건 인용은 해당하지 않는다. ADR-0019 에는 다시 열 조건 절도 없다.

## ADR-0037 다시 판정할 조건 미충족 · 대체 이유

ADR-0037 의 다시 판정할 조건 셋(표본 일치도 80% 미만, 판정 비용, 기준선 뒤 판단 실수 미감소)은 어느 것도 충족되지 않았다. 표본이 50건에 이르지 않았고, 비용 문제는 보고되지 않았고, 기준선 뒤 비교는 아직 판정 시점 전이다.

그래도 결정 3(원인 둘, 새 용어 없음)과 결정 5(기준선 행이 쌓이면 다시 만들지 않음)를 경로 원인에 한해 대체한다. 결정 2 의 기계 기록이 새 대책이 되는데, 결정 5 는 대책 하나를 원인 하나에 맞추라고 정했다. 「부르지 않음」은 내용 · 수준 어느 쪽으로도 갈리지 않아 맞출 원인이 없다. 원인만 더하고 기준선을 다시 만들지 않으면 경로의 시작 전 구간이 비어 효과 비교가 성립하지 않는다. 내용 · 수준의 기준선 행은 덮지 않는다. 판정 프롬프트는 바뀌어(지적이 경로를 가리키면 경로가 먼저) 판 2 의 내용 · 수준 수는 판 1 과 뜻이 다르다. 그래서 내용 · 수준은 같은 판끼리만 비교하고, 판이 섞인 구간은 비교 불가로 낸다.

ADR-0035 의 다시 열 조건 2(짧은 글 시범에서 교정이 줄지 않으면 집행 자리를 다시 정한다)도 충족되지 않았다. 집행 자리를 훅으로 옮기는 근거는 위임 정확도 시범의 사전 기준(호출 정확도 0.5 미만)이 실측 0.29 로 충족된 것이다.

## 관찰 (ADR-0023)

훅이 대화 기록을 이어 읽는 비용을 기록 사본으로 쟀다 (2026-11-19, macOS, 기본 예산 1500ms). 공유 표면 쓰기에서만 읽는다.

| 경우 | 훅 전체 시간 |
|------|-------------|
| 경유 기록 끔 (기준) | 100 \~ 122ms |
| 75MB 기록 처음 읽기 | 212ms |
| 75MB 기록 이어 읽기 | 98 \~ 107ms |
| 4.8MB 기록(흔적 후보 줄 27개) 처음 읽기 | 112ms |
| md 를 담은 커밋, 기록 끔 (기준) | 71 \~ 75ms |
| md 를 담은 커밋, 75MB 처음 읽기 | 180ms |
| md 를 담은 커밋, 이어 읽기(스테이징 diff 읽기 포함) | 82ms |
| 코드 · 변경 기록만 든 커밋(diff 만 읽고 기록 없음) | 79 \~ 84ms |

실제 기록 형식에서 전문가 호출 · 결과 넘김(SubagentHandback) 흔적을 잡는 것도 확인했다. 그 기록은 표식 규약 전이라 누락으로 나왔다.

## 결과

- 글 작성 스킬 · 글쓰기 실무자 · 기술 커뮤니케이션 전문가가 계획안 · 판정 · 승인 주체를 같은 말로 적는다. 전문가 파일에 반환 형식(계획안 · 판정 모드, 판정 표식)을 둔다.
- 댓글 한 줄도 전문가 호출 두 번(계획안 · 판정)과 사용자 승인 두 번을 거친다. 첫 쓰기가 느려지는 비용은 다시 열 조건 첫 행으로 본다.
- 경유 기록은 `~/.claude/ops-agent/metrics/expert-route-YYYY-MM.jsonl` 에 쌓인다. 본문 · 제목 · 전체 경로는 남기지 않는다. 표면 판별은 `~/.claude/ops-agent/route-surfaces.local.json` 오버레이로 넓힌다.
- 판정 기록에 원인 갈래 판이 생기고, 경로 기준선은 `lessons-judge.py baseline --path` 로 한 번 만든다. 경로 기준선은 `lessons/path-baseline.jsonl` 에 따로 쌓여 기존 판정 행과 하루 상한을 건드리지 않는다.
- 이 결정 전에 시작해 원인 「내용」 · 「수준」을 붙인 시범은 기준선 비교(report --split)의 내용 · 수준 행이 판이 섞여 비교 불가가 된다. 전체 행으로 본다.
- 2주 기록 뒤 차단으로 올릴지는 레포 밖 시범 파일(expert-route)에 적힌 판정일(릴리즈 뒤 14일)에 정한다. 세션 시작 주입의 판정일 줄이 그날을 알린다.
- 지표도 원인도 없는 시범은 릴리즈 즉시 주입에서 빠진다. 시범 파일 정리(종료 판정 · 지표 부여)는 사용자 승인 사항이라 머지 전에 한다.
- 다른 세션에서 받은 판정은 누락으로 잡힌다. 셸 변수로 넘긴 본문 · `gh api` 로 이슈 · PR 본문을 고치는 호출 · `bash -c` 처럼 다른 셸 안에 넣은 명령 · 오버레이에 없는 도구는 판별하지 못한다. 가드가 내부 오류로 검사 없이 통과시킨 쓰기도 기록하지 않는다. 커밋하지 않은 md · 레포 밖 md 는 공유 전이라 세지 않는다. 이 미탐은 2주 표본에서 오탐 종류로 붙여 센다.
- 커밋 범위 해석과 표면 판별의 알려진 미탐 · 오탐은 [hooks-config 「전문가 경유 지표」](../hooks-config.md) 표가 원천이다. 2주 표본에서는 그 종류를 붙여 세고, 커밋 범위 해석기는 대외비 커밋 검사 강화(#1161)에서 함께 고친다.

## 열린 질문

- 서브에이전트 자기 기록의 전문가 파일 직접 읽기(inline)가 상위 기록의 경유를 가린다. 실무자가 기준을 보려고 읽은 경우도 판정 불가가 된다. 자기 기록 흔적 우선을 유지할지 2주 표본으로 본다.
- revise · hold 판정 뒤에 보낸 쓰기도 경유로 센다. revise는 고친 뒤 다시 판정받는다(전문가 파일 「반환 형식」). 이를 어기고 보낸 쓰기를 가를지는 기록의 판정 값(`verdictValue`)으로 2주 뒤 정한다.
