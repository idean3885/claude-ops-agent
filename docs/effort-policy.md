# 작업 강도(effort)·컨텍스트 예산 정책

이 문서는 토큰 소비를 사전에 조절하는 두 수단, effort 와 컨텍스트 예산을 다룬다.

## 왜 이전과 다른가

Claude 5 세대 이전에는 코딩·에이전틱 작업에 높은 단계를 기본으로 두라는 안내였다. 현재 세대는 반대다. 기본값 `high` 에서 시작하고, 품질이 유지되는 구간에서는 `low`·`medium` 을 비용 조절의 주력 수단으로 쓴다.

이전 모델에서 쓰던 effort 기본값을 그대로 물려받지 않는다. 실제 작업으로 다시 재본다.

## 모델 의존과 비용 제약을 나눈다

전에는 아래 다섯 항목을 「특정 모델의 경향을 누르는 값」으로 묶고 모델을 바꾸면 전부 재판정하라고 적었다. 문구를 다시 읽고 나누었다. 재판정 대상은 억제가 목적인 항목뿐이고, 원하는 형태를 적은 규범과 비용을 근거로 둔 제약은 모델이 바뀌어도 그대로다.

| 항목 | 성질 | 모델을 바꾸면 |
|------|------|---------------|
| 전역 지침 「응답」·「진행 서술」·「정정」 | 규범. 원하는 형태를 긍정형으로 적었다 | 그대로 둔다 |
| `CLAUDE.md` 「위임 상한」 | 비용 제약. 정액 사용량 한도가 근거다 | 그대로 둔다. 모드로 선택한다 (아래) |
| 같은 표의 「자기 결과 검증·재확인 → 위임하지 않음」 | 효과 판정. 자기 결과를 자기가 다시 보는 것이 값을 하지 않는다 | 그대로 둔다 |

재판정이 필요한 것은 **억제 문구**다. 「~하지 않는다」로 특정 모델의 기울기를 누르는 자리가 생기면 이 표에 항목으로 올리고, 모델을 바꿀 때 벤더의 모델별 프롬프팅 가이드를 원천으로 다시 본다. 지금 그런 항목은 없다.

모델을 섞어 쓰는 경우도 같다. 위 세 성질은 모델마다 달라지지 않으므로 한 세션에서 두 모델이 돌아도 규칙이 갈리지 않는다.

## 작업 모드

사용량을 아끼는 쪽과 결과를 앞세우는 쪽을 모드로 나눈다. 단일 값으로 두면 마감이 걸린 작업에서 규칙을 어기게 되고, 어긴 규칙은 다음에도 지켜지지 않는다.

| 모드 | 고르는 조건 | 위임 | effort |
|------|-------------|------|--------|
| 절감 | 기본. 순차 의존이 있거나 대화형으로 진행하는 작업 | 직접 처리. 넓은 다중 파일 조사만 위임 | 작업 유형별 권장 그대로 |
| 풀 | 서로 독립인 작업이 여럿이고 파일 경계가 겹치지 않을 때, 또는 마감이 걸렸을 때 | 워크트리로 나눠 병렬. 동시 3개까지 | 판단 단계는 한 단계 위 |

**모드는 사용자가 올린다.** 사용량은 사용자의 자원이므로 어시스턴트가 스스로 풀로 옮기지 않는다. 풀에서 절감으로 내리는 것도 사용자가 말한다.

동시 상한 3 은 Anthropic 「The AI-native SDLC playbook」 의 엔지니어 1명당 2~3 세션 권고를 근거로 둔다. 그 위로 올리면 사람이 오케스트레이션하는 쪽이 병목이 된다.

**자기 결과 검증 위임 금지는 두 모드 공통이다.** 비용이 아니라 효과가 근거라 풀에서도 값을 하지 않는다.

모드 전환은 프롬프트 구성을 바꾸지 않으므로 effort 와 달리 캐시를 무효화하지 않는다. 작업 도중에 올려도 된다.

## 작업 유형별 권장

| 작업 유형 | 권장 | 근거 |
|-----------|------|------|
| 단순 조회, 파일 탐색, 형식 변환 | `low` | 판단 여지가 적다 |
| 일반 구현, 문서 작성, 커밋·PR 본문 | `medium` | 속도와 품질의 균형 지점 |
| 코드 리뷰, 설계 판단, 교차 검증 | `high` (기본) | 판단 정확도가 결과를 좌우한다 |
| 장기 에이전틱 작업, 대규모 리팩토링 | `xhigh` | 도구 호출이 길게 이어지는 구간 |

`max` 는 위 단계에서 품질 여유가 측정으로 확인될 때만 쓴다. 대부분의 작업에서 비용 증가 대비 이득이 작다.

## 두 가지 주의

**effort 는 응답 길이를 줄이지 않는다.** 조절 대상은 생각의 양이다. 응답이 길어서 문제라면 effort 가 아니라 길이 지시로 다룬다. 길이 지침의 원천은 전역 지침의 「어시스턴트 발화 분량」(대화)과 `config/style-rules/base/length.md`(문서)다.

**세션 중간에 바꾸면 프롬프트 캐시가 무효화된다.** effort 값이 프롬프트 구성에 반영되므로, 값을 바꾸면 이전 턴의 캐시된 접두부를 재사용하지 못한다. 긴 세션에서는 시작 시점에 정하고 유지한다. 값을 바꿔야 한다면 작업 단위 사이에서 바꾼다.

## 서브 에이전트

effort 는 **에이전트 정의(`agents/*.md`) frontmatter** 에 기재한다. 호출 도구는 effort 파라미터를 받지 않으므로 호출 시점에 정할 수단이 없다. 생략하면 부모 세션 값을 물려받아, 기계적인 하위 작업에 상위 단계가 그대로 적용된다.

- 수집·탐색·단순 변환을 맡기는 에이전트: `low`
- 판단을 맡기는 에이전트(검증·심사): 부모와 같거나 한 단계 위

단, **조회·검색 도구를 호출해야 하는 에이전트는 낮은 단계로 내리지 않는다.** 낮은 effort 에서는 도구를 호출하지 않고 기억으로 답하는 경향이 보고돼 있다. 조회가 목적인 에이전트에서는 그것이 곧 오답이다.

위임 자체의 판단 기준은 `CLAUDE.md` 「서브 에이전트 위임 상한」 을 따른다.

## 플러그인 활성화 기준

| 판단 | 조건 |
|------|------|
| **활성화** | 매 세션 도구를 실제로 사용하는 플러그인 |
| **비활성화** | 시스템 프롬프트만 차지하고 간헐적으로만 사용하는 플러그인 |
| **재검토** | 3세션 연속 미사용 시 비활성화 검토 |

MCP 도구는 기본적으로 지연 로딩된다. 이름만 상주하고 스키마는 호출 시점에 가져오므로, 안 쓰는 MCP 서버를 끄는 이유는 토큰 절약이 아니라 인증·업데이트 관리 대상을 줄이는 쪽이다. 상주 비용이 실제로 큰 것은 CLAUDE.md 본문, 스킬 목록 항목, 지연 로딩을 끈 MCP 도구 스키마, 매 턴 출력을 내는 훅이다.

## 컨텍스트 예산 의식

- 플러그인이 추가하는 시스템 프롬프트 토큰을 인지할 것
- 매 턴 고정 비용이 큰 플러그인(1만 토큰 이상)은 ROI를 검증할 것
- 같은 텍스트를 여러 턴·여러 도구 호출에 반복해 싣지 않을 것. 정적인 내용은 세션 1회, 변하는 내용만 그때그때
- MEMORY.md는 200행 이내, 핵심 패턴만 유지
- 스킬 목록(이름 + description 합계)은 컨텍스트 창의 약 1% 예산을 넘기면 잘리기 시작한다. 잘리면 스킬 라우팅 정확도가 떨어진다

상주량 실측은 `/context`, 설치·확장 전반 점검은 `/doctor` 를 쓴다.
